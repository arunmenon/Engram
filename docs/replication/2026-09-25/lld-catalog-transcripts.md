## Companion LLD for ADR-0001 — Traceability first context graph

Zero one traceability first context graph. This first companion establishes the invariant before selecting the full runtime stack: an accepted source event enters an immutable ledger with stable event session, agent trace, timestamp, and causal parent identifiers. A projector converts ordered events into semantic nodes and relationships. Retrieval returns an atlas structure in which every derived memory can identify the source evidence that supports it. Keep three boundaries separate: the event envelope records what happened. The graph projection records a rebuildable interpretation. The response contract records what evidence was selected and why. Never make the graph the only copy of source truth, and never return a derived memory with an unresolvable provenance pointer. In the ping code base, open domain models.py for the event and atlas models domain, lineage.py for evidence traversal and querying lineage routes for response construction. Use test lineage.py and the retrieval N2N tests as executable evidence. At this numerical stage, focus on the roles and invariants. Concrete storage and scaling choices are introduced by their own later decisions. The minimum replica test is: ingest a causally linked event sequence, build the projection, query one derived memory, and walk every returned provenance reference back to immutable events. Then discard the projection, replay the same ordered history, and compare the contract-level result. ADR zero zero zero one is replicated only when provenance and deterministic rebuild are properties of the design, not annotations added by a user interface. End of companion LLD zero zero zero one.

## Companion LLD for ADR-0003 — Dual store event and graph architecture

Companion LLD for ADR zero zero zero three dual store event and graph architecture. This decision separates an authoritative event store from a graph projection optimized for traversal. The original document records the evolution of the source store choice, but the durable design principle is stable: source events are authoritative while Neo4j is derived and replaceable. A write is accepted by the source store first. A projector reads ordered events and applies idempotent graph mutations. Query endpoints may use the graph for semantic paths, but recovery never reverse engineers source history from Neo4j. If the graph is lost or corrupted, create an empty projection and replay. In the ping code base, inspect the event store and graph store ports, then adapters, Neo4j store.py and worker projection.py. The exact current source adapter is established when its dedicated storage ADR appears later in the numerical sequence. At this point preserve the authority boundary rather than prematurely coupling the domain to a specific database. Test four conditions: first, source ingestion succeeds while graph projection is temporarily unavailable. Second, a worker retry does not duplicate graph effects. Third, deleting the graph and replaying produces equivalent nodes, edges, and provenance. Fourth, query readiness distinguishes API availability from projection freshness. The local gate is simple: there is one authoritative history and one disposable graph view. A synchronous dual write that requires both stores to commit atomically is not this architecture. End of companion LLD zero zero zero three.

## Companion LLD for ADR-0004 — Immutable ledger and idempotent ingestion

Companion LLD for ADR zero zero zero four. Immutable ledger and idempotent ingestion. The ingestion contract accepts an event exactly once at the logical level, even when clients retry or workers race. Each event has a tenant-aware identifier, occurrence time, event type, actor and session context, causal identifiers, payload, and schema version. Validation completes before any durable partial state is visible. One atomic source store operation checks event ID deduplication, allocates the replay position, stores the immutable envelope, appends work for consumers, and updates required secondary membership. A duplicate returns the previously established identity and position. A malformed or conflicting event creates no partial keys or stream entries. Open domain models.py and domain validation.py for the envelope, then the source adapter's atomic ingest implementation. In the pinned snapshot, the atomic script is adapters redis Lua ingest.lua. The storage selection itself is explained at its numerical ADR. Review test ingest.lua.py, test concurrent ingestion.py, and the ingestion end-to-end suite. Test simultaneous submissions of the same event, same identifier, with different content, invalid schema, unavailable indexes, and process interruption around acknowledgement. Preserve the distinction between the immutable event identifier and any HTTP request retry identifier introduced by later API work. The replication gate is one immutable event and one replay position under arbitrary duplicate delivery. If operators must manually reconcile half-written ledger state, this decision is not complete. End of companion LLD zero zero zero four.

## Companion LLD for ADR-0005 — Graph projection and replay worker

Companion LLD for ADR zero zero zero five. Graph projection and replay worker. The projection worker converts ordered source events into a rebuildable graph. It consumes through a durable consumer group, upcasts and validates each event, applies an idempotent graph mutation, and acknowledges only after the graph effect is durable. The important failure window is between graph commit and stream acknowledgement. If the worker dies there, another consumer receives the event again. Graph mutations therefore merge on stable tenant-aware identities and tolerate redelivery. A worker that cannot process an event after bounded retries moves it to a dead letter stream with safe diagnostic context instead of blocking all later work. Open worker consumer.py for pending entry reclaim, retry, acknowledgement, and dead letter behavior. Open worker projection.py for event to graph application and the graph adapter queries for idempotent merge behavior. Review test consumer.py, test projection worker.py, and resilience end-to-end tests. Replay starts from ordered source history and a clean or explicitly versioned projection. Consumer group trimming must account for pending entries, so retention cannot delete another consumer's unacknowledged work. Kill the worker before graph commit, after graph commit, and before acknowledgement. Require eventual completion with no missing or duplicated logical graph effects. Insert a poison event and prove later valid events continue after dead letter handling. The local gate is crash-safe convergence. Repeated delivery changes latency, not the final graph meaning. End of companion LLD zero zero zero five.

## Companion LLD for ADR-0007 — Memory tier architecture

Companion LLD for ADR zero zero zero seven. Memory tier architecture. This decision divides memory by authority and lifetime. Immutable episodic events record what happened. Semantic memory contains derived facts and relationships. Procedural memory captures reusable behavior. Working memory is a bounded disposable view assembled for the current task. Do not copy the same field into every tier without an ownership rule. A source event remains authoritative for occurrence and provenance. Derived graph properties may record confidence estimates, consolidation, or access metadata, but they cannot rewrite historical facts. Working contexts may be regenerated and evicted without losing durable memory. Open domain models.py for event and graph representations, domain scoring.py for derived retrieval attributes, and the context route for working memory assembly. Inspect model and scoring tests for field validation and bounded output. For each external field, record its authoritative tier derivation source, retention policy, and rebuild path. Test that clearing working memory does not delete durable state, that semantic updates preserve episodic evidence, and that a rebuild projection recreates derived tiers without altering source events. The acceptance gate is an explicit ownership table. If the replica cannot say whether a value is immutable evidence, derived semantic state, reusable procedure, or temporary context later lifecycle and retrieval behavior will drift. End of companion LLD zero zero zero seven.

## Companion LLD for ADR-0008 — Consolidation, decay, and forgetting

Companion LLD for ADR zero zero zero eight. Consolidation, decay, and forgetting. This decision manages long-lived memory without mutating this immutable event ledger. Consolidation groups related evidence into summaries or stronger semantic structures. Decay reduces retrieval priority over time according to configured behavior. Reinforcement updates derived access or importance metadata. Forgetting removes or suppresses eligible derived material under lifecycle policy. Every consolidated memory retains source links. Rerunning consolidation over the same evidence is idempotent. Decay is calculated from stable time and configuration inputs and remains bounded. A retrieval read must not silently rewrite source history. Open domain consolidation.py, domain forgetting.py, and domain scoring.py, followed by worker consolidation.py and the Neo4j maintenance adapter. Review scoring tests, forgetting integration tests, and consolidation end-to-end tests. Use a fixed clock to verify exact decay boundaries. Run consolidation twice and compare graph state. Remove a summary and reconstruct it from evidence. Confirm reinforcement changes only derived metadata. Verify a summary never survives without resolvable supporting events. At this position in the sequence, forgetting concerns memory lifecycle and evidence preservation. Stronger regulatory deletion mechanisms are separate decisions introduced only at their numerical point. The local gate is controlled adaptation. Memory can summarize, fade, reinforce, and retire while source evidence remains immutable and every derived result stays explainable. End of companion LLD zero zero zero eight.
