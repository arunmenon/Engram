One picture

Where does an event go, and what decides what happens to it?

Three facts that shape everything else

  • The ledger is the truth. Events are appended once, with their acceptance record, and never changed. The graph is derived from them and can be rebuilt.
  • Domains are data, not code. A pack file declares types, events, projection rules, retrieval intents and what an LLM may propose. The engine has no PDLC code.
  • One tenant, one database. Isolation comes from the database boundary plus an ownership row that every process checks, not from filtering by a tenant column.

Ingestion: from a source event to graph writes

What has to be true before a byte is stored, and what the workers do after.

What makes this tenant-safe

  • Trust comes from who authenticated, never from a field in the JSON. A webhook's identity is the verified signature; an agent's identity is its token.
  • The acceptance record stamped on each event names the tenant, database, binding, epoch and bundle digest that accepted it. Workers verify that record before they interpret the event.
  • The append is one transaction with the fence check, so a frozen or re-pointed tenant cannot accept a late write.

Retrieval: from a question to an answer with evidence

Why the answer is the one the stored evidence supports, and nothing more.

What keeps an answer honest

  • Bounded walks. Every traversal has a depth, node count and time limit, and the response says when a limit cut it short.
  • Admission before the agent. Superseded, untrusted and rejected links are dropped; proposed links arrive flagged.
  • Provenance on every node. Each returned node points back to the ledger event that produced it.
  • Eval-gated weights. A pack's retrieval weights serve only after its evaluation set passes.

Multi-tenancy: one database per tenant, fenced by an owner row

How one customer's data stays in one database.

Why an epoch and a digest

  • Epoch is a fence against stale processes. Freezing or re-pointing a tenant advances it; anything still holding the old number is refused mid-flight, including a response that was computed but not yet sent.
  • Digest pins the pack bundle. Acceptance records say which bundle admitted an event; a worker running a different bundle will not interpret it.
  • Ownership is adopted by an operator, never created by startup. A database with no owner row refuses service.

The Spanner handshake

What an API or worker process checks before it serves, and what it refuses to repair on its own.

Spanner constraints the design respects

  • Spanner rejects some floats inside JSON columns, so floats are stored tagged and decoded exactly.
  • Graph queries filter on key columns, not on dynamic labels.
  • Writes are split to stay under Spanner's commit limits on mutations and bytes.
  • Every call is a network round trip, so reads and writes are batched per flush.

Ontology packs in play

How a domain is declared once and used at four points of the engine.

What the PDLC pack declares

  • Delivery: pull requests, reviews, test runs, releases, deployments and incidents, with the rules that link them.
  • Planning: versioned specs, requirements and design elements; an approval binds to one revision, and a new revision supersedes the old.
  • Traceability: explicit references from ticket to requirement, PR to ticket and test to requirement.
  • Contracts: a bounded payload contract for every event type.
