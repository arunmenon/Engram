# Independent #29 enrichment ordering preflight

2026-10-13. Read-only implementation review; no new runtime acceptance. Reviewed current issue #29 via GitHub and the current worker/shared graph/Spanner/Neo4j seams.

The proposed existing-worker solution is proportionate. No new service, scheduler, table or enrichment receipt is required for the stated fixed-input keyword/vector pipeline. Resolve the atomicity and retry semantics below before implementation sign-off.

## Concrete design requirements

1. **Atomic importance ownership is essential.** Projection initializes the accepted event's importance hint on creation. Enrichment fills importance with the supplied hint/default 5 only when the stored score is null; it preserves every non-null value, including zero. Later adjustment owns the current score. This avoids an enrichment marker and prevents retry from undoing an adjustment. A separate read followed by writing the observed value is insufficient: an adjustment between them can still be overwritten. Implement the null check and keyword update inside the same backend transaction. Neo4j can use `coalesce(e.importance_score, $importance_score)` with MATCH and a returned existence result. Spanner needs the equivalent transaction-local conditional patch; a small backend override is sufficient.

2. **Annotation existence must be checked at write time.** Current shared `GraphOperations._update_existing` reads then upserts (graph_ops.py:481); callers ignore False. Raising on False repairs the ordinary projection-lag case, but the split read/upsert can recreate a partial Event if deletion occurs between operations. An atomic existing-node update should cover both keywords/importance and embedding. Spanner's `_merge_nodes` is appropriate for projection create-only defaults, but is not an existing-only annotation primitive. Neo4j must consume/check a returned row inside `execute_write`, not merely return an unconsumed AsyncResult.

3. **Field ownership must apply to both single and batch projection.** `graph_ops.py:320–348` and Neo4j `queries.py:104–138` currently overwrite derived defaults. Use event-source fields as updates and keywords, summary, importance, access_count, last_accessed_at as creation defaults. Preserve embedding and private processing metadata. Spanner `_merge_nodes` already performs create/default selection atomically. Replaying stale projection A after derived state B must leave B's owned fields intact.

4. **Retry storage, distinguish provider degradation.** Missing graph Event and missing accepted ledger document must not return success. Re-fetch the document inside the retried operation so a later appearance is observable. Wrap annotation storage with existing `_retry_transient`; do not turn graph write exceptions into embedding-provider degradation. Cache a computed embedding within a delivery while retrying its storage write so a transient write outage does not repeatedly invoke the provider. Optional provider absence/failure may ACK successful keyword/importance enrichment without a new vector, under the existing documented policy; preserve any previously stored vector. Do not describe this as guaranteed eventual vector repair.

5. **Qualify the retry bound.** `consumer.py:84–113` caps exponential backoff, not total wait. A permanently missing ledger/Event can block this consumer until stop; distinguish this from recovered projection lag in diagnostics and evidence. The pre-existing pending-drain delivery-count check (`consumer.py:185–204`) can dead-letter after repeated restarts before `process_message` runs. Therefore “no ACK/DLQ while waiting in place” is accurate; an unconditional “never DLQ missing prerequisites” is not. Do not broaden #29 into #14/#19 scheduler policy without an explicit decision.

## Minimum proof gaps to close

- Projection-first and enrichment-first through actual workers. In enrichment-first, observe its delivery pending while Event is absent, no ACK/DLQ, then start projection and verify exact keywords, importance and vector through stored rows and public reads.
- Both single and batch projection: project A, enrich/adjust/access B, replay A; preserve keywords, summary, vector, adjusted importance and access fields. Include null hint, non-null hint and zero/non-default stored importance. Exercise transaction overlap or an SDK transaction fixture for conditional-importance preservation; sequential replay alone does not prove the race closed.
- Exact duplicate and stop/restart while awaiting projection or document. Check pending identity before restart, eventual single accepted ledger identity, final source fields/evidence and absence of unintended counter changes. Distinguish injected missing-document fixtures from cloud admission behavior.
- Provider absent and provider exception: keywords/importance apply; vector absence is explicitly allowed only for the applicable case. Re-delivery with an existing vector must not erase it. A scripted deterministic provider proves exact vector persistence, not live model quality; label it.
- Inject failure after keyword commit but before vector persistence, then restart or recover transiently: exact keyword/importance/vector convergence and no ACK before successful required storage. A failing storage adapter must not be counted as a harmless provider failure.
- Keep all five real workers and authenticated API/Spanner/public reads for live acceptance; controlled ordering may temporarily hold the relevant worker. Preserve failed evidence, verified export/reset owner fencing and post-process retained fingerprints. Use the already reviewed healthy quiescence procedure without claiming #60 is fixed.

No smarter scoring/extraction, pilot, live Neo4j, concurrent-tenant or general shutdown claim is implied. This review supports implementation once the atomic existing-node/null-importance contract is adopted; it does not clear an implementation or live result that has not yet been reviewed.
