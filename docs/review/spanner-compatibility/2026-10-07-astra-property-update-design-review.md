# Property-update contract review

2026-10-07. Read-only review of the latest #36 proposal and current domain/storage paths. No tests, cloud calls or runtime edits. The registered local diagnostic is supplied evidence; source inspection confirms the corrected public-path behavior.

## Verdict

Approve an **opt-in structured property binding plus explicit removal tuple**. This is smaller and clearer than a general patch language or new mutation service. Preserve shorthand behavior and canonical snapshots initially. Do not claim strict conformance for a rule or pack merely because one field uses the new form.

The proposal correctly retracts the old deletion hypothesis: GraphOperations.upsert_nodes/upsert_edges call stored_values before low-level apply_set, and Neo4j `_props` likewise filters None. Public missing/null therefore preserve today; invalid scalar coercion may silently preserve, and invalid list members may disappear. A/B/A ordering is independently unresolved and stays outside this slice.

## Blocking details

**1. Specify strict evaluation as its own result contract.** Legacy `_walk` returns None for absent keys, explicit null and wrong containers; legacy each converts None to an empty list; concatenation omits null operands. Wrapping that result cannot recover the missing distinctions. Use a small internal tagged result `(VALUE,value) | MISSING | NULL | INVALID(reason)`, including per-cell results for wildcard lists. Never serialize sentinels into payload/graph data.

Define precedence for mixed operands: INVALID first, then MISSING, then NULL, otherwise evaluate values. A missing path segment propagates MISSING; a null intermediate propagates NULL; a present non-container at a required traversal step is INVALID. Wildcards preserve indexes and nesting rather than filtering or flattening missing/null cells. For `select: zip`, require an actually fanned target and list length matching the original `_Keyed.count`; select by original index even when invalid keys elsewhere were skipped. Scalar targets with zip must refuse, not silently broadcast. For `select: value`, a list is one value and never implicitly picked merely because its length matches key fan-out.

Outer missing/null policy applies to the selected value. Missing/null members inside a whole-list VALUE cannot clear the entire property or be dropped: refuse unless a future element-null representation is deliberately supported. Empty list/string, zero and false remain ordinary values. A literal JSON null may be allowed only inside the structured value syntax as the NULL action trigger; it is never persisted as a graph property in this slice.

**2. Strict coercion cannot reuse legacy coerce blindly.** It wraps scalars for list targets, filters invalid list elements, stringifies arbitrary objects, and defaults naive datetime strings to UTC. Build a strict scalar conversion helper with explicit supported inputs and safe failures, then validate every list element. Preserve documented useful conversions such as integer strings, but reject booleans-as-numbers, nonfinite/overflow values, object-to-string accidents and timezone-ambiguous datetime values. Enum conversion must be explicit rather than accepting any object's str(). Decide whether JSON targets accept nested null as data separately from a root null clear; their policy must not bypass finite JSON validation.

**3. Write-time atomicity must include create_only.** Current GraphOperations.upsert_edges gathers create_only keys, checks existing edges outside the final write transaction, then drops each write's flag. Spanner `_upsert_edges` sees only key/updates. This can race concurrent creation, and mixing create_only/ordinary writes for one key is conflated by the set of keys. Carry per-write create_only into the same per-key transaction that applies set/remove, preserving input order. Alternatively, the first slice must explicitly reject strict updates/removals combined with create_only and leave that combination unsupported. Do not claim the current precheck is atomic.

Neo4j already uses ON CREATE SET for create_only; removals must obey that same conditional branch. An unconditional REMOVE after MERGE would mutate an existing create_only edge. Grouping by create_only also must not reorder mixed operations to the same identity. No service runner is needed to review/generated-query-test this, but real backend behavior remains a separate gate.

**4. Protection is about writes, not only clears.** Reject strict set, clear and defaults targeting node identity/key properties, node_type, ontology_version, engine-owned update/provenance metadata, source_trust and lifecycle-managed fields. Otherwise callers can bypass protection by setting a system value rather than removing it. Required edge/link fields cannot be cleared; required domain fields need an explicit registry definition before claiming generic requiredness enforcement. Reuse existing schema owner/subscriber checks, but do not equate permission to reference another pack's node with permission to erase its properties. Until property-level grants exist, restrict strict foreign-pack updates/removals to already explicit write authorization or refuse the unsupported combination. This does not settle broader competing-writer authority.

## Smallest storage representation

Keep properties/defaults unchanged and append `remove_properties: tuple[str,...] = ()` to NodeWrite/EdgeWrite. Validate tuple names, reject duplicates or canonicalize them, reject set/remove overlap, and defensively reject key removal at the public PackGraph boundary. Validate the entire supplied write batch before its first mutation for deterministic shape/protection errors.

Apply defaults only on creation, then set, then remove within the same per-key transaction. Clear-only MERGE may create a keyed node; document that exact choice. An absent-field clear is a no-op on that field, not proof of a changed row. Do not manufacture effect counts from requested removals.

For node writes, the existing low-level `apply_set(..., None)` deletion mechanism can be reused internally: filter ordinary None values first, then add explicit removal entries at the last conversion boundary before transactional merge. This preserves legacy specialized writes without expanding every lower-level signature. Do not pass removals back through stored_values and lose them. Edges still need the create_only correction/explicit exclusion above. In Neo4j, use validated property names or a parameterized null-valued update map that preserves intended removal semantics; `_props` must not filter those explicit removals away. Recompute Spanner JSON/derived columns and commit budgets from the actual merged properties, preserving existing retry/fence behavior.

## Versioning and executable sequence

Extend only node/edge set values with a strict model accepting `value`, `on_missing`, `on_null`, `select`, forbidding unknown keys. Existing RuleValue currently excludes mapping values, so this is an unambiguous syntax extension. Preserve legacy serialization for packs without new bindings; empty port removal defaults do not need to enter pack canonical JSON. Update expression/path validation to inspect structured `value` and not treat policy strings as expressions. Add an engine capability requirement whenever a structured binding is present; unsupported engines fail load/composition.

First executable slice can support literals and direct paths, including wildcard/zip, with explicit set/remove semantics on own-pack properties. Reject unsupported function/concat AST forms at load time until the full propagation table is implemented; do not silently route them through legacy evaluate. Then add function semantics deliberately: regex/map no-match MISSING, regex_all no-match empty VALUE list, match no-match false, regex timeout INVALID, each preserving missing/null and explicitly wrapping present scalars. This keeps the first deliverable usable without claiming the entire proposal implemented.

Structured declarations require an owning pack version/digest change; stricter engine behavior requires a pinned new engine revision for bound cloud runs. A changed old mapping that now clears or refuses is behavioral and may be breaking, even if syntax is additive. Update change classification instead of treating every set-expression change as harmless. Do not reinterpret historical receipts under the new engine; use the established empty-target activation flow for experiments.

## Focused acceptance

Cover direct/nested missing/null/wrong containers; exact false/zero/empty values; whole-list versus zipped selection; original-index gaps; invalid list members; conversion boundaries; omitted fields preserved unchanged; explicit clear present/absent/new node; defaults-before-clear; invalid late subscriber binding discarding the entire fresh plan. Assert common Event may exist but no rejected domain plan is applied.

Storage tests must verify atomic set+remove and fenced retry, protected keys/system fields, invalid batch rejected before writes, existing/missing endpoints, supported create_only behavior or explicit refusal, same-key ordered updates and stable legacy snapshots. Preserve the diagnostic A/B/A result as an unresolved ordering case, not a regression repaired by clear semantics.

An unfamiliar strict fixture should run through plan→apply→memory first, with independent expected properties rather than serialization-only tests, followed by exact real Spanner set/clear/refusal evidence under the new pinned interpretation. PDLC/CRM migrate deliberately afterward. Existing lookup expansion, writer precedence, stale-event ordering and effect attribution remain separate #36 work; this representation leaves room for future conditional/effect metadata without pretending to implement it now.

## Agreed bounded implementation gate

The selected first slice is **strict literals/direct paths only**, with positional wildcard results, explicit zip/value and strict coercion. Full strict functions/concatenation remain proposed extensions. Pack loading must reject any unsupported AST node, including a function or concatenation nested inside another expression; successful schema parsing alone is insufficient. Legacy expression evaluation and shorthand stay unchanged. Structured `value` is required even when its explicit literal value is null; missing the declaration is a load error.

For this slice, reject every `EdgeWrite(create_only=True, remove_properties=nonempty)` before **any** I/O from the supplied call, including when an earlier sibling is otherwise valid or the target edge does not exist. Apply the rule consistently in public memory/shared, Spanner and Neo4j paths. Ordinary legacy create_only behavior remains unchanged and is not advertised as transactionally repaired. Clear-free strict writes may use the existing path with that same explicit limitation. Future atomic create_only support requires the flag-in-transaction work above.

Completion gates: (1) all structured bindings statically satisfy supported-AST, declared-target/path and protected-field rules; (2) malformed runtime values refuse the whole in-memory event plan with safe location/reason; (3) every adapter honors the removal contract or refuses unsupported combinations before I/O; (4) no code path silently downgrades a strict binding to legacy evaluation/coercion; (5) legacy canonical snapshots and plans remain stable; and (6) the fixture/pinned-engine real-Spanner evidence is scoped to these supported operations.

Add explicit tests for top-level and nested unsupported function/concat rejection, missing structured value versus literal null, scalar-target zip refusal, nested wildcard state preservation, mixed valid/invalid write batches with an I/O spy, and create_only removals on existing/absent edges. Test clearing alongside ordinary sets in one key transaction without requiring A/B/A convergence. Mark unsupported function cases as load refusals, never skipped “supported” cases. This gives a small executable contract now and a precise boundary for subsequent extensions.
