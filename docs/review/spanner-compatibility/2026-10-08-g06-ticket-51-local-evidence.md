# G06 #51 local implementation evidence

PDLC 4.0.0 deliberately changes Incident identity to `(repo, service, incident_id)` on a fresh projection. All detected, reported and resolved normalized producer events require those three nonempty strings. No native incident adapter, historical migration or cross-pack identity framework is introduced. Component remains the global service catalog identity.

Detected and reported both record the affected service and enter `detected`; neither reopens a resolved incident. They may identify occurrence on the latest deployment matching **all** repository, service, environment and artifact fields, with deployment `started_at <= occurred_at`. The full Deployment key includes that timestamp, so equal timestamps within this complete scope identify the same node, rather than requiring an arbitrary tie-break between distinct nodes. Missing optional environment/artifact information or no eligible deployment leaves **no OCCURRED_ON relationship**; this is unknown deployment identification, not success. OCCURRED_ON is an occurrence assertion, never causal attribution. Late deployment arrival does not automatically backfill an existing incident; replay is a separate operation.

The bounded `incident` retrieval intent uses OCCURRED_ON, AFFECTS, DEPLOYS and INCLUDES with max depth 3. It excludes DEPLOYED_TO traversal through a shared service. Shared catalog names intentionally denote the same service, so unrelated fixtures use distinct qualified service identities. Same-name cross-repository deployment distractors separately exercise occurrence lookup scope.
