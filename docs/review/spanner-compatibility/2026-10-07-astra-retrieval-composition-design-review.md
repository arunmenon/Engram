# Active-pack retrieval boundary

2026-10-07. Source inspection only; no tests, cloud calls, runtime edits or tenant-routing design. This supplements the composition-boundary review.

## Decision

Use one immutable `RetrievalScope` derived from the active registry, enforced **before backend counts, ordering, limits and path expansion**, then checked defensively before engine ranking/admission. Filtering final answers, or even filtering returned neighbor rows before PPR, is insufficient: inactive rows can consume limited candidate slots and alter active-node seed scores. Keep the two retrieval engines and existing specialized strategies.

The scope needs active node labels, allowed `(source_label, edge_type, target_label)` triples expanded from registry endpoint rules, and allowed event/artifact intents plus supported seed strategies. Expand wildcard endpoints over active labels only. Core Event/Entity/Summary remain active. PackGraph already specifies one label per node: enforce that contract, rather than choosing `labels[0]` when historical Neo4j nodes carry multiple ontology labels. Unknown or ambiguous ontology labels fail closed; infrastructure labels require an explicit convention.

Smallest concrete wiring: inject the scope into `RetrievalEngine` and `ArtifactRetriever`; bind scoped graph-read adapters at composition. For Memory/Spanner, prefer a read-only `GraphOperations` view forwarding `_get_nodes`, `_find_nodes` and `_edges` with active predicates, then construct `GraphOperationReads` over that view. Inspected primitives return complete matching rows without top-N caps, so filtering precedes inherited aggregation and neighbor limits. Validate requested-key membership, reject inherited writes, and narrowly forward access recording for validated Events. Keep original stores for writes/privacy/maintenance. Bypassing native Spanner lineage initially is a reasonable correctness-first tradeoff. Neo4j needs corresponding filtered queries before its scan caps. This avoids changing every port signature; document the scoped contract. A wrapper filtering already-limited rows is insufficient. Production must use scoped instances; legacy construction can retain compatibility.

## Current versus needed

**Event retrieval and strategies.** `engine.py:145–172` accepts external classifier results and explicit intent overrides without validating active intent membership. Intersect inferred results with `RegistryIntents.names`, use its active fallback when empty, and reject unavailable explicit overrides. Guard the empty-intent case in `_expand_cross_session`. Validate strategy availability centrally; a domain naming `user_profile` must not activate it without its provider prerequisites. Do not let backend “unknown strategy → general” conceal an invalid configured strategy.

`graph_ops.py:1380` counts incoming/outgoing edges for causal roots, entity hubs and similar clusters without consistently checking endpoint labels. Its cross-session REFERENCES join can also traverse non-Entity intermediates/non-Event sources. Neo4j types some of these joins more strictly, but causal-root counts and user-profile target patterns remain broad. Apply scope and each strategy's semantic endpoint constraints before counts and LIMIT. Keep Event→Entity→Event cross-session reads core-capable; user-specific intent availability is a separate decision.

**Event neighbors/context/lineage.** `engine.py:655` infers identity from property names, defaults unknown edge weights to 1, and can construct nodes using `neighbor_labels[0]`. Require an active canonical label, matching key field, allowed edge triple, requested seed source and real endpoint before scoring or creating an edge. Unknown edges are excluded, not assigned default relevance. `graph_ops.event_neighbors` and Neo4j's batch query currently limit all outgoing rows before such checks; move predicates ahead of limits. Apply edge scope to `session_edges` too. Neo4j `GET_LINEAGE` labels only its start Event, leaving intermediate/ancestor nodes untyped; require every node in this event-only path to be Event before path LIMIT. Audit corresponding shared and Spanner path implementations against the same contract.

**Seeds and search metadata.** `_fetch_seed_nodes` currently treats every unresolved Event ID as a possible Entity and adds it to seed IDs. Explicit seeds overwrite the seed list before validation. Stop this behavior: explicit raw IDs have documented Event semantics, must resolve to requested Event records, and unresolved IDs are rejected or omitted with a clear result. If supporting explicit Entity seeds, use an explicit typed form and resolve them through a typed read. Reject extra records from `get_event_nodes`.

Keep an internal typed seed key `(label,id)` through fusion to prevent Event/Entity ID collisions. `KeywordIndex` promises Events and `VectorIndex` promises Entities, so callers can assign those fixed types without a universal mixed-index protocol. Add an Entity lookup through existing PackGraph `get_nodes` or a narrow `GraphReads.get_entity_nodes`; never infer existence/type from an unsuccessful Event lookup. Either implement a documented Entity→referencing Events expansion for vector seeds or retain resolved Entity nodes explicitly; the current `event_neighbors` contract cannot traverse Entity IDs. Do not silently relabel vector IDs as Events.

**Concrete Spanner vector gap.** `adapters/spanner/graph.py:610` queries all embedded GraphNodes, without an Entity-label predicate, then returns every node_id as `entity_id`. Generic graph_ops searches Entity only; Neo4j uses the Entity vector index. Fix the Spanner search corpus at the query/index boundary before top_k, with label-aware identity. Merely post-filtering ANN results cannot ensure inactive vectors do not crowd out active Entities; if the deployed ANN index cannot provide that guarantee, use a supported Entity-only index or exact Entity-scoped fallback and state its performance limitation. This is a protocol-conformance defect, not a reason to widen the event search port to all packs.

**Artifact reads.** `_ref` excludes inactive types on many paths, but `_seeds` trusts every returned `get_nodes` entry, and `_neighbors_all` accepts all backend rows. Validate returned refs against the requested set, registry key metadata and properties. Centralize neighbor checks for requested near refs, direction, edge type, both active endpoints and far-node identity. All callers—traversal, `_superseded`, admission, completeness plugins and provenance—must use this boundary. `_superseded` currently allows an inactive source on wildcard SUPERSEDES to hide an active artifact without calling `_ref` on that source. This is a direct answer-changing leak.

Shared `graph_ops.neighbors` slices before fetching far nodes; Neo4j applies `NEIGHBOR_SCAN_CAP` before assembling/sorting results. Apply endpoint/edge predicates before both limits, including backend internal scan caps. Otherwise disabled neighbors change truncation, call budgets and completeness findings. `_neighbors_all` split/retry logic is not pagination past arbitrary inactive rows. Apply existing `exclude_packs` consistently as a further narrowing of scope, including explicit seeds, plugins and admission. Validate explicit artifact intents inside the retriever as well as the HTTP route so direct callers cannot bypass it.

## Focused regression acceptance

1. Differential fixture: identical active graph, then add many inactive nodes/edges ahead of all scan limits. Both engines must retain identical active IDs, scores, ordering, provenance, completeness counts and truncation behavior (excluding timing metadata).
2. Inactive SUPERSEDES source cannot hide an active artifact; inactive corroboration/completeness paths cannot admit or satisfy it. Core wildcard edges cannot bridge through an inactive intermediary.
3. Explicit inactive/unknown seeds, extra backend refs, mismatched keys/labels and Event/Entity ID collisions cannot enter results or teleport PPR mass. Valid explicit Event and documented Entity-vector behavior remain working.
4. Inactive user explicit intents are rejected; inactive classifier outputs fall back safely; no user-profile strategy call occurs without its selected prerequisites. Related core entity retrieval still works.
5. Backend conformance covers pre-limit predicates and aggregate/path membership, including more inactive edges than the neighbor cap, unknown Event→Event edge types, non-Event CAUSED_BY intermediates and cross-session joins through wrong labels.
6. Embedded inactive nodes outranking an Entity cannot occupy its vector slot. Verify Spanner's query/index behavior separately from generic fallback and Neo4j; a recording-port test alone cannot prove ANN semantics.

This boundary hides inactive graph types and edges. Historical ledger Events remain core even when their event namespace refers to an inactive pack; hiding those records is a separate event-admission/visibility policy. It also does not erase prior semantic influence already materialized into active properties or summaries. Privacy operations retain their separate historical-data access. Local implementation acceptance and real Spanner evidence remain distinct.
