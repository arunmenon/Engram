# G06 #53 local implementation evidence

PDLC 4.2.0 adds normalized `pdlc.incident.lesson_recorded`: required nonempty `statement` and complete `incident: {repo, service, incident_id}`, optional complete `change: {repo, number}`, and optional `link_status: proposed|confirmed|rejected` applying to declared LEARNED_FROM support. Numbers and strings use the same typed bounds as #52. No native adapter or authenticated human approval is claimed.

An authored lesson is one immutable admitted assertion. Its existing `content_hash` identity field is `sha256(str(event_id)) + ':authored'`, yielding `Lesson:<digest>:authored`. The suffix separates authored assertions from existing inferred lessons keyed by bare statement digests. Identical retries retain identity; changed content under the same event ID remains an ingress conflict, not a revision mechanism. A new event is a separate assertion even with identical text and incident. Distinct incidents with identical lessons therefore preserve independent nodes, support edges, lifecycle and source evidence. This bounded policy does not introduce logical lesson editing or source merging.

Authored Lesson starts `tentative` and never auto-validates. DERIVED_FROM records the authored event; LEARNED_FROM to the explicit scoped incident and optional Change carries source_event_id, pinned_position and declared-link metadata. Confirmed support means the producer explicitly asserted that relationship; it does not make the lesson validated knowledge. Optional producer-rejected support is retained but excluded by existing retrieval admission.

Spec.approved accepts optional `lesson_refs: [{content_hash: '<digest>:authored'}]`, which deterministically CITES that exact Lesson from the exact `(doc_id, version)` Spec, pinning the citation event's ledger position. The reference contract accepts only 64 lowercase hex characters plus `:authored`. A small generic bounded string-pattern primitive was necessary: the red malformed-reference test showed a same-length nonhex string passed the original length-only contract. Pydantic's non-backtracking Rust regex engine supplies pattern validation; unsupported syntax fails pack loading as a contract validation error. No PDLC dispatch was added to the engine.

Complete references arriving early use existing keyed reference stubs with null artifact provenance and initial lifecycle defaults. A citation alone does not observe the Lesson or validate it. Unknown hashes retain their explicit CITES relationship; later ordinary authored events can populate the corresponding Lesson. Existing generic cited_node_ids remain available with their existing policy; G06 authored-lesson examples use the new typed path. Similar prose or an unciting Spec creates no deterministic CITES. No lesson or citation is synthesized by these rules.

The incident intent now also traverses LEARNED_FROM and CITES at weight 5, retaining max depth 3. Full G06 fixtures include #52's explicit REMEDIATES relationship so Incident→fix remains supported without bypassing the existing sibling-drift guard. Incident and future-Spec explicit seeds and a natural-language unique-Spec question return the declared lesson, incident, correction and citation chain; unrelated matching Spec prose stays out. The shipped lesson evaluation scores F1 1.0.
