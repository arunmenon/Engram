# G06 #52 local implementation evidence

PDLC 4.1.0 adds normalized event `pdlc.incident.remediation_recorded`. Its required references are `change: {repo, number}` and `incident: {repo, service, incident_id}`. Repository, service and incident strings are nonempty; change number is a positive INT64. This is a normalized producer contract, with no native incident adapter promised. Other incident contracts and identities remain unchanged.

The declaration writes only Change→REMEDIATES→Incident with source-declared link defaults, `source_event_id` and `pinned_position` from its envelope. It neither observes the referenced artifacts nor changes their lifecycle. Corrective intent does not imply causal attribution or verified remediation. Merge updates the Change only; a separate incident.resolved event supplies incident resolution. The existing late-detection policy preserves resolution.

Unknown-reference policy: complete keyed endpoints use the existing generic reference stubs. They contain keys and lifecycle defaults, with no source-trust assertion or DERIVED_FROM artifact evidence; retrieval returns null artifact provenance. Thus initial `open`/`detected` values are reference defaults, not evidence that the producer observed either artifact. They are never `merged` or `resolved` solely from remediation declaration. Later ordinary artifact events populate their own observation provenance while preserving the declaration. The REMEDIATES edge is evidence of declared corrective intent, not completed remediation. No link is silently discarded.

Red → green: the explicit-correction test first failed with no REMEDIATES edge; adding the typed declaration and deterministic pack rule made it pass. The forward/reverse retrieval test then omitted the Change; adding only REMEDIATES weight 5 to the bounded incident intent made it pass. Tests also verify independent merge/resolution provenance, late detection, unrelated PR/incident negative controls, early-reference behavior and malformed nested references. The shipped remediation evaluation set scores F1 1.0.

Validation: 168 tests passed across incident remediation, incident scope, pack projection, payload catalog, PDLC retrieval and ontology pack checks. Scoped Ruff checks pass. No core engine or backend changes. Real HTTP append rejection, same-ID identical retry/changed-content conflict, actual workers and Spanner retrieval acceptance remain root-owned and pending. The G05 retained dataset was not accessed or modified.
