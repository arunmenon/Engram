## Severity-ranked findings

1. **P1 — #6: unchecked absence still becomes a factual answer.** Verified by source at `retrieval/artifacts.py:337–357, 840–876`. `_neighbors_all` returns an ordinary list after skipped budget calls or an indivisible full neighbor range; `_missing_links` defaults every candidate absent from `status` to `no_link`. Sequence: seed Acme, consume call budget checking admission, skip BELONGS_TO read, report Acme missing deals. A range containing proposed/rejected edges before an unseen confirmed edge also yields false absence or false `proposed_only`. Global `truncated` does not qualify individual claims. Smallest fix: return per-subject/range completion alongside rows, require complete relevant checks before either negative classification, and count unknown separately. Preserve affirmative evidence already found. Subject-scan truncation and incomplete supersession/admission checks also require scope uncertainty; do not advertise complete population counts. Read exceptions currently propagate from this helper: graceful partial failure behavior is an acceptance requirement, not an independently verified swallowed-error bug.

2. **P1 — #7: rejected relationships enter both answers and question scope.** Verified at `retrieval/artifacts.py:676–714, 808–810, 900–937`. `_traverse` scores/adds a rejected edge and its destination before admission; final admission only checks surviving endpoints. Sequence: D-7 → rejected BELONGS_TO → Acme returns both Acme and rejected evidence. Filtering emitted edges alone leaves unsupported nodes and downstream traversal. Additionally, completeness descendant/join scope loops consume rejected relationships; filtering only `_traverse` misses these routes. Apply one admission predicate before frontier/scope expansion and edge insertion, retaining independently seeded or validly reached nodes. Audit `_superseded` at 769 too: a rejected replacement edge must not remove a node if such statuses are permitted. That schema-dependent case is an untested risk. Preserve explicit proposed/legacy policy and confidence.

3. **P1 — #31: context continuation reverses the initial ordering.** Verified at `adapters/graph_ops.py:190, 1526–1546`; locally reproduced using the actual method with a five-event fixture. Initial page IDs `[4,3]`, continuation `[4]`; 0–2 disappear. First page sorts timestamps descending; continuation chooses greater timestamps and sorts ascending. Ties lack an explicit event-ID sort in both helpers, despite an ID continuation predicate. Use one timestamp/ID tuple order with its matching strict continuation predicate on every page; define old-cursor handling. Keep cursor derived from storage order (`retrieval/engine.py:365`), not relevance-ranked presentation. Repeated IDs also cause repeated access writes.

4. **P1 — #32: timeout is accepted but not enforced through native work.** Verified at `adapters/graph_ops.py:1526–1560`, `adapters/spanner/graph.py:81–112, 166–185`. A local 30 ms `_session_events` delay completed successfully with `timeout_s=0.001`. Spanner query/read helpers call synchronous streaming SDK methods without timeout and consume all rows in `to_thread`; lineage then hydrates edges and nodes separately. Installed SDK `Snapshot.execute_sql` accepts `timeout` and `retry` and constructs a restartable streamed result, so merely wrapping an async await is insufficient. Define per-operation versus request deadline first; propagate remaining time through all constituent reads, SDK retry/stream consumption and acquisition. Check budget before launching follow-on work. Test await cancellation separately from actual worker/remote termination. Native timeout/retry behavior and snapshot-pool waits remain untested here. #26's acquisition cancellation leak remains a prerequisite for lifecycle proof; fixing request latency alone cannot close #32.

5. **P2 — #24: path count is not node capacity; cursor slices the same prefix.** Verified at `retrieval/engine.py:422–466` and `adapters/spanner/graph.py:99–119`. Every page fetches only `clamped_nodes+1` paths, slices by offset, then unions unrestricted path nodes. A seven-event chain can exceed a two-node page and terminate after only the fetched prefix; native GQL LIMIT has no stable path ordering. Enforce unique-node bounds and endpoint-consistent edges, with a deterministic continuation that advances the actual exploration. Increasing fetch size by offset alone neither establishes stable order nor bounds path explosion. Specify seed repetition, cross-page edges and graph-mutation behavior before implementation. #18 supplies durable lineage correctness; #31's ordering contract should precede this pagination design.

6. **P2 — #25: Entity ANN seeds are recorded but never hydrated.** Verified at `retrieval/engine.py:613–626, 669` and `adapters/graph_ops.py:1496–1500`. Vector-only Entity IDs fail Event lookup, remain in seed metadata, then enter an Event-only outgoing-neighbor read. Thus real inbound Event REFERENCES Entity evidence is unreachable. Add narrowly typed Entity hydration and inbound reference reads scoped to the requested session, preserving provenance and node budgets. The helpers currently receive no session argument: unrestricted inbound expansion would introduce leakage. Include identical Event/Entity string IDs to verify typed identity; current ID-only fusion/hydration makes collisions an untested additional risk. #23 is scoped-ready, #29 remains needed for reliable enriched vectors/evidence. #27's legacy codec ambiguity precludes broad existing-data correctness claims.
