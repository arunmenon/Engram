# Durable event interpretation envelopes

2026-10-07. Narrow source-only design review of bound Spanner ingestion, duplicates/import, worker reads and replay. No runtime edits, tests or cloud calls. Public tenant service remains disabled.

## Minimal contract

Keep `domain.models.Event` as the public event model. Store an immutable **acceptance JSON column on Events**, separate from mutable `document`, with this versioned content:

```text
envelope_version: 1
tenant_id, database_resource, binding_id
accepted_epoch, bundle_digest, engine_revision
source_identity: stable server-authenticated principal/source binding
request_digest: algorithm/version + digest of normalized event and full payload
```

The database fields are redundant with physical routing but support archive/import provenance and detect copied/misbound records. Never store credentials or bearer tokens. `accepted_epoch` is when admission occurred; it is not permanent authorization for future processing. Commit timestamp/global position already records admission order, so an extra request-time acceptance timestamp is unnecessary. Future per-pack contract versions can extend a new envelope version; exact bundle identity is sufficient now.

Use one internal `AdmissionContext(binding, source_identity)` supplied by authenticated composition, and a single stamp/fingerprint function shared by normal, batch and webhook ingestion. Per-request principal identity cannot live in a mutable store attribute: pass it through the append call or an immutable request-bound writer. The bound store's tenant fence verifies that supplied binding matches its own authority; no caller-supplied context escapes verification.

**Stable producer identity is an explicit required addition.** Current `Principal` has only credential_id/tenant_id/roles, and rotation changes credential_id. Add a server-configured `source_id` to the authenticated principal/grant contract, scoped by tenant. Rotated credentials intentionally share the same source_id; independent producers do not. Validate its presence for every bound admission grant rather than deriving it from agent_id, credential_id or a tenant-wide default. Several credentials may deliberately represent one producer; that sharing is an operator authorization choice. Roles govern permission and may change without changing source identity. Optional original credential_id can be audit metadata, never dedup identity. Define duplicate equality as `(same stored source_id, same canonical request_digest)`; another producer using the same event ID conflicts even when content matches. A same-producer retry under a rotated authorized credential returns the original acceptance unchanged. A webhook uses its verified source/install binding's source_id; admin import preserves a producer claim only through the explicit trusted-import contract.

Stamp and insert the acceptance record in the same fenced append transaction. Store the original accepted digest and envelope exactly once; deduplication never overwrites them. Add the column through an explicit additive schema migration/handshake, include its bytes/mutation in commit estimates, and preserve unbound compatibility separately. Do not silently enable bound processing of rows whose acceptance is missing.

## Input and normalization boundaries

`Event` is strict about types but does not forbid all unknown fields; `api.ingest.check_events` extracts payload then validates the public model. Reject the reserved acceptance/envelope namespace **on raw top-level input before model validation**, including single event, batch and admin import. Otherwise ignored extra fields conceal attempted spoofing. Payload fields with similar names remain untrusted domain data, never authoritative context; reserve a payload namespace only if the product deliberately defines one. Also reject supplied server position/interpretation fields rather than adopting them.

The request digest covers the complete normalized public Event projection plus the full normalized payload; compare source_id separately as above. Normalize timestamps to UTC (the existing validator already does), UUIDs/enums/defaults through the model, object key order deterministically, and use one explicitly versioned JSON scalar/number policy. Reject unsupported/nonfinite values before append. Include all semantic event fields, including IDs and payload_ref; do not hash search-text truncation, enrichment output or only selected payload fields. Preserve array order and exact meaningful strings. Recommend absent payload and explicit null canonicalize to null while an empty object stays distinct. Reject non-object/non-null payloads: current `check_events` silently converts them to None. Bound capture must not discard an input before fingerprinting and then claim complete request identity.

Exclude only server transport/derived fields such as global_position, search_text, summary enrichment and envelope itself. Epoch/bundle are not part of request content: retries under a newly authorized runtime must still match original content. Credential rotation identity is excluded; stable principal/source authorization identity is included. Avoid a general client-chosen “volatile fields” list.

Canonicalization should start from the accepted model projection plus validated payload, not a generic subtraction list over a mutable stored document. `occurred_at`, ended_at, agent_id, trace_id and payload_ref remain semantic by default. For fingerprint v1 use recursive sorted-key compact UTF-8 JSON with nonfinite numbers rejected, preserving array order and distinguishing booleans/strings/numbers. Define integers and floats as distinct (`1` versus `1.0`) and preserve negative floating zero; freeze encoder fixtures so later serializer changes require a fingerprint version. Reject values that cannot encode losslessly under this contract. Source-specific webhook transport metadata is a separate normalization contract, not an excuse to drop fields from all callers.

**Webhook blocker:** `webhooks.build_events` derives event ID from signed body but uses request-time fallback occurred_at and delivery-header-dependent trace_id/payload_ref. Identical signed-body retries can therefore differ semantically. Establish a source-specific deterministic normalized event contract, or fingerprint the verified source body plus stable translated semantic content while storing transport delivery metadata separately. Do not globally exclude occurred_at or trace_id merely to conceal this discrepancy. HTTP client retries likewise must reuse their original event timestamps/IDs.

## Duplicate, retention and import rules

`log.py:_append_chunk_sync` currently reads only event_id/position/dedup_active and returns the original position without comparing content. Read stored acceptance with the row and compare request digest for both database duplicates and repeated IDs within the same transaction/chunk. Equal content returns duplicate/original position and original envelope; different content returns a typed conflict, without mutation. Map conflicts explicitly in single/batch/import outcomes; already-committed earlier chunks remain committed. Never conflate conflict with RuntimeFencedError or a retryable storage outage.

For a retry after epoch advancement, the **current runtime must first pass current admission fencing**, then may return the old original envelope when content matches. It must not enqueue a new event or relabel the old one as newly accepted. A stale caller cannot bypass its failed fence by claiming a duplicate.

`expire` nulls documents, and `housekeep/_purge` eventually clears dedup flags/deletes rows. Acceptance must survive document expiry while ID deduplication is promised. Choose explicitly between bounded dedup retention and permanent identity tombstones. Minimal safe bound behavior: never overwrite a still-existing row's acceptance even if dedup_active is false; once identity is physically purged, long-term retry identity cannot be guaranteed without a tombstone. Report an expired/unverifiable duplicate rather than claiming equality from ID alone. Retention policy is a blocking contract decision, not an implementation detail.

`append_imported` currently copies arbitrary documents and adds legacy_position; `append_entry` creates a bare documentless entry. Reject both in bound mode until they carry a deliberate trusted-import contract; do not accept an imported JSON envelope as server authority. Same-tenant restore must validate source binding and preserve original acceptance, with separately recorded import provenance. Cross-tenant copying is a new admission under target authority, not preserving an authenticated source claim. Legacy adoption needs an explicit audited mapping to an original known contract or a distinct legacy/unknown marker that is not processable by default. Never stamp unknown historical rows as if today's engine originally accepted them.

## Worker validation and upgrades

Add a small envelope parser/validator returning a validated Event/document/acceptance tuple. Bound processing must use it **before constructing projection plans, prompts or derived writes**. Delivery fields currently supply only event_id; fetch authoritative acceptance from the ledger, never trust a subscription payload copy. Compare fetched Event ID and ledger key. Cover projection batch documents and predecessor lookups, enrichment, extraction trigger and all session documents, pack extraction, and `ontology.versioning.replay`/read_after. Consolidation's control triggers are not normal Events: preserve their current control fence, and validate the provenance of any ledger documents used for derived summaries. Protect `set_document_fields` from changing original event/payload fields or authoritative metadata; allow only declared enrichment fields.

Current write/read fences authorize the worker's **current** epoch. Separately, processing policy validates the accepted contract. Same tenant/binding and identical digest/engine revision can be processed after an epoch-only advance; requiring accepted_epoch==current_epoch would strand valid pending/history records. Different digests require an explicit immutable compatibility grant or replay plan naming old and target contracts; pack semver alone is insufficient. Preserve original acceptance while recording target interpretation on replay outputs/checkpoints.

For this slice permit exact-contract processing only and keep changed-contract activation/replay unavailable until that policy exists. Merely draining queues is insufficient: later extraction loads whole sessions, predecessor lookup reads historical events, and replay intentionally reads old records. Mixed-contract sessions need an explicit compatible-history rule or partitioned extraction, never silently skipping incompatible documents. An incompatible/missing envelope is a control refusal that stops without ACK/DLQ; it must not be swallowed by extraction's parse-error catch. Retired consumers also need an explicit obligation disposition rather than indefinite incompatible pending work.

## Focused acceptance and scope

Test atomic stamp plus control check; spoofed envelope/position at every ingress; full nested payload changes, canonical-equivalent inputs and null/absent policy; equal/different ID reuse across chunks and concurrent writers; retry after epoch-only advance retaining original acceptance; stale-runtime duplicate rejection; webhook redelivery stability; document expiry and dedup expiry; malformed/missing acceptance; forbidden imported/bare bound append; enrichment immutability; mixed-contract session/predecessor reads; compatible epoch-only recovery; and changed-contract replay refusal. Assert original position/envelope and zero writes on conflicts/control refusals, with no accidental ACK/DLQ.

Also test rotated credential IDs sharing source_id, same content under different producer IDs, role changes, non-object payload rejection, and every currently exposed admission path. For a minimal bound-capture slice, unsupported migration/import/bare-entry paths must fail explicitly before any write, not remain unstamped side doors. Envelope schema upgrade must precede bound startup and update both normal insert and duplicate reads, import guards, commit-budget estimates, archive export, document expiry and purge rules. A nullable column for legacy rows is acceptable only with bound startup/processing checks that refuse unknown acceptance; nullable storage is not automatic legacy adoption.

Decide retention horizon and webhook normalization now. Exact-contract-only processing plus blocked changed-contract activation is a safe explicit first limit. Real two-database evidence, legacy adoption, trusted restore and compatibility-granted upgrades remain separate acceptance work; the envelope column alone does not complete #43.
