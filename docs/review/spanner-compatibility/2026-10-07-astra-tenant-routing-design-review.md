# Tenant routing design review

2026-10-07. Read-only review of the design request, current factories, routes/auth, worker entry points, ontology state and Spanner transaction boundaries. No tests, cloud calls, runtime edits or GitHub changes. Scope: #43 architecture and acceptance, not a claim of tenant isolation today.

## Verdict and concrete contract

**Choose an authenticated ASGI dispatcher with one explicit-settings child application/runtime per tenant.** Current routes already access `request.app.state` directly; changing only FastAPI resource dependencies would leave artifacts, evaluation, webhooks, events and other routes on process-selected state. Reuse that boundary rather than rewriting every route or mutating global state per request.

Define immutable server-side values:

- `TenantBinding(tenant_id, database_resource, binding_id, epoch, bundle_digest, archive_namespace, settings_snapshot)`; use full project/instance/database identity, not database basename. Include exact manifest content and interpretation-affecting policy/provider versions in the bundle digest, not only pack names/versions. Keep authentication rotation revision distinct from interpretation epoch.
- `Principal(credential_id, tenant_id, roles, source_binding?)`, minted only by the dispatcher/authenticator. HTTP body/headers/agent_id never construct it. Normal credentials map unambiguously to one tenant; API/admin roles remain distinct. Rotation may temporarily map multiple credentials to the same identity, never to different tenants.
- `TenantRuntime(binding, stores, bundle, child_app)` with explicit `create_app(settings, binding)`/lifespan composition. Workers receive this same binding contract and an explicit tenant target. No production fallback to ambient `Settings()` or a default tenant/database.

Validate the entire catalog before opening stores: unique live database resources and binding IDs, mandatory core, compatible capability providers, unambiguous credentials/source bindings and isolated archive namespaces. For this slice require all durable runtime ports to use the selected Spanner database; fail mixed storage configuration rather than implying database separation covers Redis subscriptions or another graph. Do not add an adapter framework.

## Prioritized gaps

**P0 — Authentication must precede runtime selection and every storage access.** `api/dependencies.py:118,136` currently bypasses auth when keys are unset; that development behavior is unacceptable in tenant mode. Dispatcher verification creates a trusted principal in ASGI scope; child guards validate its tenant and required role. Do not validate the same token again against only one child key, which would break rotation. Strip/reject client-supplied internal identity fields. Unknown credentials, tenant hints that disagree with the principal, unknown tenants and unavailable children fail without fallback. Ensure no route can directly mount/reach an unguarded child.

Webhook paths may select a candidate binding, but authorization requires that candidate's verified source signature and server-side source/install/repository binding. `routes/webhooks.py:145` already rejects missing secrets and verifies HMAC; retain it and bind authentication to the exact raw body before append. Shared secrets alone cannot distinguish tenants: reject ambiguous catalog assignments or require an independently verified installation identity. Source identity must also govern trust; do not turn arbitrary tenant-supplied `agent_id=webhook:github` into verified webhook authority.

**P0 — Persist database ownership and atomic interpretation fences.** `OntologyState:active` stores pack snapshots through ordinary graph upserts (`ontology/versioning.py:47,117`); it is not a protected owner record or compare-and-swap barrier. Add a small dedicated binding/control row with immutable tenant/database/binding identity, active epoch/digest and serving state. Keeping ownership outside user graph data avoids generic rebuild/cleanup accidentally changing it. Only explicit bootstrap/admin activation creates or changes it; normal startup rejects absent/mismatched binding. Bootstrap of an existing populated database requires an explicit adoption decision, never “first caller wins.”

Each append transaction must read and validate this row atomically with ledger insertion (`spanner/log.py:_append_chunk_sync`). Stamp a server-owned envelope containing binding ID, interpretation epoch/digest and authenticated source; never place authoritative routing fields inside pack payload. Duplicate event IDs retain and validate their original envelope, not the caller's current revision. Batch/import/webhook paths use the same rule.

Every graph mutation transaction, subscription checkpoint/ack/dead-letter operation, evaluation-state update, privacy deletion and maintenance transaction validates the expected binding/epoch before effects. Existing graph/subscription `_transact` functions provide integration points, but audit direct transaction paths too. A separate preflight GET followed by mutation is a race. An epoch mismatch is a control-plane stop/retry outcome, not an event failure to dead-letter. Do not acknowledge work after its graph write was fenced out. Multi-transaction processing must remain replay-idempotent after partial success.

**P0 — Smallest activation policy is drain and restart, not hot reinterpretation.** Initially freeze a binding for a runtime lifetime. Activation first changes control state to reject new admissions, drains old-epoch obligations, quiesces workers/maintenance, reconciles/evaluates, then atomically advances epoch/digest and starts replacement runtimes. Hard epoch checks reject forgotten old processes. Drain permits the old epoch's outstanding work; a later frozen state fences all ordinary writes. Do not advance with unfinished old work unless an explicit replay/migration plan exists. An LLM call started before activation must recheck the fence when persisting results. Record original event contracts for future replay; do not silently run old accepted events against a new pack merely because that pack is now active.

Reads also require an active binding: reject stale runtimes and establish a request read epoch. With multiple graph calls, either use a stable snapshot or recheck epoch/state before returning and discard/retry on change. Current child-local caches cannot alone prevent a stale answer during activation. No read-through fallback to another tenant or old runtime.

**P1 — Explicitly close existing bypasses.** `app.py` and `worker/__main__.py` construct `Settings()`; middleware does too when not passed settings. `ontology/__main__.py:95` temporarily mutates process environment for rebuild targets. Pass immutable resolved settings everywhere, including middleware, and replace arbitrary CLI database overrides with catalog-authorized source/target bindings. Enumerate events/batches/import, both retrieval engines, context/lineage/entities, feedback/simulation, ontology/evaluation, ordinary users, privacy/admin, webhook, health and metrics routes. `get_retrieval`'s raw-graph fallback must not apply in tenant mode. Privacy operations bypass inactive-pack visibility only, never tenant authorization.

Cursors currently encode positions without a tenant binding (`domain/pagination.py`): include/authenticate binding ID, epoch and query scope, rejecting foreign cursors before reads. EvalPending, rate-limit buckets, caches, pending tasks and replay cursors belong to one runtime/binding. Content-addressed immutable bundle data may be shared; clients, subscriptions and mutable evaluation state may not. `/metrics` currently mounts process-global collectors; expose aggregate operational metrics only through a separately protected root endpoint, not a tenant endpoint that reveals other tenants. Public health must not reveal tenant/database inventory.

Archive isolation is outside database tables: `registry.py:_open_archive` takes a filesystem base path or GCS prefix. Require distinct validated namespaces for archive/restore/retention, including replay/export temporary artifacts. An authorized rebuild target must be an explicitly reserved same-tenant binding; never allow another live tenant database. Moving a graph projection must not silently switch its source ledger. Defer live database cutover until that distinction has an explicit contract.

**P1 — Own resource lifetimes and failure isolation.** Root startup/shutdown explicitly enters/exits every child lifespan; do not assume mounting starts children. Use bounded tenant count/pools and immutable catalog snapshots initially, avoiding an eviction manager. Reuse stateless embedding/model providers where safe, but retain tenant runtime ownership of stateful stores. Clean up partially opened children on initialization failure. Catalog ambiguity fails deployment; a tenant's transient storage outage may make that tenant unavailable without rerouting or taking down healthy children. Drain in-flight requests/tasks before closing a retired runtime. Rotation revocation is enforced at authentication; document the handling of already-authorized in-flight requests.

## Implementation slices and exact acceptance

1. **Concrete first slice:** add frozen `TenantBinding`/`Principal` and a validated immutable catalog; make `create_app(settings=...)` pass that same snapshot to lifespan and `register_middleware`; make worker construction take resolved settings/binding instead of reading environment. Existing `get_settings` already reads `request.app.state` and needs no replacement abstraction. Add a small ASGI dispatcher that authenticates, resolves exactly one binding, attaches the trusted principal, invokes the corresponding child and rejects tenant-hint mismatch. Keep tenant role checks centralized in existing guard functions. Root owns child lifespan entry/exit and cleanup. Avoid a new service, general runtime manager or context-variable store locator. Test default single-deployment compatibility, two children with colliding IDs, missing/ambiguous credentials, role and hint mismatch, explicit settings unaffected by environment, middleware isolation, partial-startup cleanup and bounded resource closure. Rejected requests make zero store calls.
2. Protected binding bootstrap, durable event envelopes and transactional admission/write/subscription fences. Add frozen-epoch pinned workers/admin commands. Then explicit drain/activation with recovery; do not market step 1 alone as complete isolation/version correctness.
3. Bind cursors/evaluation/replay, close maintenance/privacy/export/webhook bypasses, and run conformance plus two-database cloud acceptance.

**First-slice release boundary:** the catalog/factory/dispatcher substrate may be merged and exercised with local recording ports, but must not enable production tenant service startup until durable binding verification/fence support is wired. In particular, append/import/webhook, worker mutations/acks, privacy/admin writes, evaluation/replay and maintenance cannot safely serve tenant traffic with startup-only checks. Reads can demonstrate database routing locally, but cannot claim current-bundle isolation under activation without durable read-epoch handling and cursor binding. Fail tenant-mode startup explicitly while these prerequisites are absent; preserve existing single-deployment behavior separately. This is a concrete incremental deliverable, not closure of #43.

Real acceptance uses A=core+PDLC and B=core+user, both in one instance/service, with identical event/session/agent/user/entity/artifact IDs and credentials carrying different roles. Assert exact database effects and forbidden effects for single/batch/import/webhook ingestion; both query engines; context/lineage; user reads/export/erasure; evaluation state; replay/rebuild; subscriptions/acks/deadletters; archive restore and retention. Cross-use credentials, tenant hints, webhook signatures, IDs, cursors, target overrides and duplicated catalog bindings. Only the authorized database may change; the other database's before/after rows and archive namespace remain unchanged.

Race activation against append, delayed LLM output, graph writes, ack, privacy deletion and retention. Prove stale operations cannot commit, duplicates keep original envelopes, unfinished work is recoverable, and no activation silently reinterprets it. Kill/restart a worker and child startup; rotate/revoke credentials; deny one database while the other remains usable. Capture durable binding/epoch/envelope rows and transaction outcomes, not merely HTTP statuses. Exercise with database-scoped IAM credentials wherever possible; broad shared service credentials make application isolation—not IAM—the defense against routing bugs.

Decisions needed now: adoption authorization for existing data, credential/source binding ownership, and acceptance of the drain/restart activation limit. Hot per-request version multiplexing, live database relocation and shared external archive namespaces can remain explicitly unsupported. No new orchestration service is required.
