## Severity-ranked findings

1. **P1, #29 — verified silent enrichment loss, including after successful enrichment.** `src/context_graph/adapters/graph_ops.py:458–476` returns False for absent Event, but public enrichment/embedding methods discard it. `src/context_graph/worker/enrichment.py:84–97` returns successfully, allowing normal ACK. Sequence: enrich E → project E leaves no enrichment. Additionally, project E → enrich E → duplicate/replayed projection E clears keywords and resets importance through `_event_props` and unconditional node upsert (`graph_ops.py:296–322`). Thus merely deferring until Event exists does not meet the acceptance requirement. Smallest coherent fix: make missing projection visible to the worker and retain pending work; preserve worker-owned derived fields on projection replay. Coordinate partial keyword/vector success and retry, rather than rerunning an already-ACKed provider result blindly.

2. **P1, #10 — verified pack evidence and candidate loss before projection.** `src/context_graph/worker/pack_extraction.py:161–167` derives the event's own references but offers only already-present nodes to the model. Before projection, relevant own items are absent, so waiting only at edge-write time cannot recover links the model never proposed. Proposed nodes' provenance is planned in `src/context_graph/domain/pack_extraction.py:495`, then absent endpoints are silently filtered by `src/context_graph/adapters/graph_ops.py:639–656`. `_extract` treats the returned edge count as success (`pack_extraction.py:141`). Sequence: extraction creates proposal before source Event/own artifact → provenance/link omitted → ACK → projection never repairs it. Defer before candidate construction, or durably preserve sufficient input/result and reconcile both candidate completeness and edge application. A mere nonzero-write/count check is insufficient.

3. **P1, #18 — verified wrong replica predecessor and independent missing-endpoint loss.** `src/context_graph/worker/projection.py:256–258` trusts any cached session event. Ledger A,B,C; replica R1 projects A, R2 projects B, R1 projects C: C follows A instead of B. Session-end processed by R2 similarly leaves stale R1 state. Even always reading the ledger does not suffice: B may project before A, and Spanner drops B→A because A is absent (`src/context_graph/adapters/spanner/graph.py:538–554`). The worker ACKs after successful batch return (`projection.py:181–184`). Use authoritative ingestion-order predecessor selection, then durable endpoint repair. Preserve session boundaries; occurrence-time sorting is not a substitute. Cache mutation before writes (`projection.py:138–150`) also requires failure/retry coverage to prevent self/backward edges.

4. **P1, #30 — verified causal edge loss.** `src/context_graph/domain/projection.py:119` computes causal intent from parent_event_id, but the same Spanner endpoint filter silently removes it. Child C projects and ACKs before accepted parent P; projecting P later does not revisit C. Preserve dependency intent until both endpoints exist and distinguish accepted-but-late parents from permanently absent parents. Share narrowly scoped missing-endpoint handling with #18; do not add a second lineage ordering scheme.

5. **P1, #8 — verified incomplete lookup and wrong prefix-latest selection.** `src/context_graph/adapters/graph_ops.py:688–701` sorts by key and truncates per equality condition; `src/context_graph/worker/pack_projection.py:95–97` applies prefix/time/latest selection afterward. With limit N and the sole eligible/newest prefix match at key N+1, the expected edge is absent or an older match wins. Prefetch populates the cache, so the warning at lines 88–94 is normally bypassed too. Non-prefix latest already searches all equal matches: preserve that behavior. Move prefix/cutoff selection before latest, and provide complete paginated bounded lookup or explicit incomplete outcomes for fan-out. Raising the cap is not a fix; shared adapter currently scans the full label before slicing, so result caps are not read budgets.

6. **P2, #20 — verified deterministic session-extraction failure.** `src/context_graph/worker/extraction.py:408–416` passes entity_id to `write_derived_from_edge`; `src/context_graph/adapters/graph_ops.py:136–141,1298` excludes it and raises ValueError after INTERESTED_IN was written. Every nonempty interest with source events fails that path. Add Entity to the existing typed provenance mapping. Retry can rerun earlier session writes, so verify no multiplied observation/assessment counts or regenerated duplicate preference IDs on partial failure; this is a follow-up risk, not a claim of an executed full-session reproduction.

7. **P2, #9 — verified lifecycle evidence omission.** `src/context_graph/domain/pack_projection.py:386–387` adds provenance only inside upserts; transition planning at lines 408–411 emits only StateChange. Existing artifact X transitioned by an event that does not upsert X changes status without X→causing Event evidence. Include transition provenance, with an explicit contract for rejected/stale/only_from-no-op transitions. Blindly recording every attempted transition as proof of an actual change would overstate evidence; transition outcome and provenance should remain consistent under retries and interruption.
