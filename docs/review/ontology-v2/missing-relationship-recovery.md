## Product behavior and observed failure

A contact can arrive before its account. With one event per flush, the exact-ID/lookup relationship used to disappear even after both records existed. Rebuilding again created it. The original18-case/54-run baseline proves order/batch dependence without missing documents or dead letters. Keyed endpoint stubs already worked.

Recovery must recreate only the skipped relationship. Repeating its original node upserts or state changes could overwrite newer data. A required missing link prevents a replacement graph being called complete; an unflagged exact missing reference is counted but retains the previous non-blocking meaning.

## Implemented contract and components

- `EdgeRuleDef.required` defaults false, omitted from canonical pack JSON so existing digests stay stable. Required lookups must supply the target/source type's complete immutable key by equality. They become exact references without creating target stubs. Required non-key, prefix and latest searches are rejected explicitly as `required_relationship_needs_exact_identity`. Missing required identity operands refuse the event plan. Original optional search semantics stay in place.
- Ordinary keyed endpoints retain stub behavior. Optional searches are evaluated once at original processing; when the exact known endpoint was missing, selected candidate references and the selector digest are pinned. Recovery never re-selects a mutable or latest target. A truncated original lookup is explicitly blocking. Required broad/latest searches are unsupported; no batch-invariance claim is made for existing optional broad/latest selection.
- Pending effects reuse existing tenant graph storage through internal reserved `ProjectionRecovery` rows. A row is keyed by the edge identity; its generation pins original event, whole bundle digest and exact effect/selector digest. It contains references, source authority and log metadata, not copies of event payload/property values. Among deferred writes to one edge, an atomic register retains the last original-log contribution to each property, using the original event and effect ordinal. The adapter supplies a comparable native-log token; this is existing log write order, not S3's business-recency policy.
- The first contract suggested one row per event/effect. Implementation instead uses one atomic compacted register per edge, retaining source references only for property contributions not overwritten by later effects. A whole-event winner lost earlier disjoint fields (red-partial-link-properties); per-property references fix that without retaining payload values or an unbounded history. Older/equal redelivery cannot regress a terminal row. Point reads fence duplicate delivery of a deferred event from clobbering an existing reviewed edge. A genuinely later normal event keeps its existing write semantics; protecting arbitrary old ordinary node/state writes belongs to S3.
- `PackGraph` gains bounded native keyset/point reads and atomic register/settlement. Memory methods execute without awaits inside their mutation; Spanner uses fenced read-write transactions over GraphNodes/GraphEdges; Neo4j uses a unique internal key, row lock and MERGE/ON CREATE in a transaction. Endpoint existence, create-if-absent and terminal status are one atomic unit. Existing relationship properties are never changed by recovery. Explicit removals are vacuous on an insert.
- Before creating a recovered edge, fetch the original source through EventLog or typed AcceptedRecordReader and re-run source policy. Exact tenant/database/binding/engine/configuration and effect must still match. The original producer and complete request fingerprint are pinned, including source fields that do not affect projection. Missing/changed source, changed bundle/effect/relationship-plan order, or changed authority remains explicit blocking. An equivalent re-derived effect under a compatible unbound bundle can recover; unknown historical authenticated contracts still require their existing interpretation grant. Epoch-only advances are compatible, while current storage fences and typed receipts still enforce epoch. Exceptions/fences do not mutate the affected intent.
- A persistent rotating cursor makes bounded live idle/startup pages fair across new consumer instances. A full bounded final pass after the ledger blocks rebuild/replay completion if required rows or unexamined rows remain. Waiting/blocking counts and scan status appear in reports and recorded readiness. Settings bound page size, full-pass work and elapsed time. Intents do not create records during recovery, so one complete post-ledger pass is the fixed point on a controlled target.
- Internal labels are reserved, uniquely constrained in Neo4j and excluded from domain graph counts. No new service, queue, database table or automatic cutover is introduced. Optional recovery state is still bounded by explicit configured scan limits; budget exhaustion is incomplete, not success.
