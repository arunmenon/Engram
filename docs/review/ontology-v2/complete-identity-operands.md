## First-review corrections and explicit limits

Fable round1 requested a narrow revision: preserve pattern search-text lists with empty cells; reject literal-led expression-looking identity constants at validation; and prevent partial composite equality/prefix lookups. Each has a failing-before public-seam witness in red-review-findings.txt. The fixes retain ordinary pattern search text, add identity/reference-only validation for unrecognized strings containing payload/event path markers, and make malformed lookup operands find nothing with a named rejection reason. Existing fixture/oracle files are unchanged. Diagnostic errors name the declared node/key or node_id, never source values.

An explicit pattern defines its own capture. A permissive `regex(merchant + ':' + missing_id, '(.+)')` can still capture merchant-only text because pattern input is search text, not an inferred identity schema. The test documents this boundary. The engine does not infer domain-required fields or make a permissive pattern business-correct. Whitespace/object operands and preexisting text truncation are separate limits. Literal identity values containing `$.`/`$event` now require a recognized expression form rather than being silently treated as a constant; this is a deliberate compatibility tightening.

A malformed composite refuses the complete event plan; the existing worker dead-letters that event and replay/rebuild reports failures. Existing bad graph identities are not repaired automatically. Direct absent keys/optional matches remain no-record outcomes. Hashing an empty dynamic statement now produces no Decision instead of a hash-of-empty record. This behavior is distinct from reinterpreting old data or certifying a rebuild.
