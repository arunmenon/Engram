01 / The purpose

Records need meaning before they become useful context.

Engram turns events into connected knowledge. A pack tells the engine how to understand a particular world.

Input

Events

Reports of what happened, received from source systems.

Meaning

Ontology → pack

The things, identities and relationships that matter—expressed as executable definitions and rules.

Result

Connected context

A graph of things and their relationships, with evidence for retrieval.

One reusable engine. Explicit, versioned understanding for each domain.

A defined model can still be wrong. Examples, review and evaluation test its interpretation.

02 / Composition

Shared foundation. Optional additions. Domain meaning.

A tenant selects a compatible set of packs for its tenant context.

Domain packsBusiness vocabulary, identities, event mappings and retrieval configuration.
Optional add-onsMemory: beliefs, goals, episodes   ·   User: profiles, preferences
Core · requiredCommon concepts and shared interfaces that domain models can use.
The engine checks dependencies and conflicting names across the selected packs.

Pack composition defines the model. Authentication and database boundaries are separate tenant-isolation controls.

03 / Inside a domain pack

Make the interpretation explicit.

Illustrative incident example: an incident affects a checkout service.

Things, keys and states

Incident and Service. Incident identity includes its account. Lifecycle rules govern state changes.

Event contracts

Which event fields must exist and what shapes are accepted.

Mapping rules

Create or update the incident. Connect it to the correct service.

Retrieval configuration

Guide which entities and relationships matter for a supported question.

Alongside the pack: reviewed questions and expected answers test whether that interpretation is useful.

Packs configure supported engine capabilities; they do not supply arbitrary new runtime code.

06 / Proof and handoff

Approval, activation and answer readiness are distinct.

A journey bundles an ordered story of events, checkpoints and questions.

1. Reviewed version

Approve a specific configuration and its supporting test evidence.

2. Runtime activation

Bind the runtime to the approved configuration through the supported operational procedure.

3. Answer readiness

An intent is a named retrieval task. Run and record its evaluation on the target graph. An empty new tenant may remain pending.
