claim: On our agent tasks, serving 2 memory entries per step instead of our current top-k cuts injected memory tokens by at least 25% with a pass-rate loss of no more than 2 points.
proposed experiment: Frozen agent harness, model and memory store. Arms: (A) current top-k; (B) top-2; (C) sufficiency stop rule where available (links H8 and B9, so the three budgets are compared once). Attribution: render each step's prompt with and without memory and count the difference (the paper's two-pass method), splitting cached and uncached input. Dataset: at least 60 tasks from our engineering-agent task set, 3 seeds per arm. Metrics: injected memory tokens and dollars per task, pass rate with bootstrap intervals by task. Predeclared margin: B adopted if injected tokens fall at least 25% and the pass-rate interval lower bound is above minus 2 points. Kill: pass rate falls more than 2 points. Note from the source: its "almost no accuracy cost" was 0.600 to 0.570 on one seed with keyword grading, so the margin here is stricter.
why it matters for us: R3 asks for sufficient evidence within a bounded budget; the paper puts memory injection at 13.6% of variable workflow cost and growing with depth, so the default budget is a real cost lever. Exact per-step attribution is also cheap telemetry we lack today (R6).
