claim: On generic tasks the best open-weight System One models now tie Jev 1.13 on accuracy (Arize: Clef 27B 85.2% vs Jev 85.5% hallucination, 91.5% vs 91.1% evaluators) but lose on calibration (0.062 vs 0.023) and some collapse when the question is negated (Kev 9B ROC AUC 0.85 to 0.54, Liquid 0.92 to 0.17). Laya zero-shot trails Jev by 0.22 on an independent sealed set.

proposed experiment: Four arms on the same sealed set of about 300 labelled PDLC link decisions (PR implements requirement, test verifies requirement, ticket blocks ticket) drawn from one real project history: Jev 1.13 hosted; Clef-flash self-hosted; Kev 9B self-hosted; Laya. Each question asked in both polarities. Thresholds fit on half (split by time), scored on the other half. Metrics: accuracy with paired bootstrap CIs, ECE, polarity agreement rate, p50/p95 latency on our hardware, cost per 1,000. Reuse the sysone-bench sealed-manifest harness pattern. This extends H5 (which tests Jev as an extraction gate against self-reported confidence) with the open-weight arms and the link stage; H5's arms do not include open models.

why it matters for us: Priority 2 wants memory text kept in-house. If Clef-flash or Kev matches Jev on our link decisions and passes the polarity check, the first PDLC slice can ship without sending project text to a third party.
