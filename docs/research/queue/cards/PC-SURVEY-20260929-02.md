claim: On 3,103 issues and 7,688 commits across six large projects, a LightGBM LambdaMART ranker over text similarity plus six metadata features (time proximity, diff size, file overlap and others) reached average F1 73.17 on issue-to-commit links against 48.39 for a GPT-OSS-120B agent and 35.88 for SBERT plus GPT-4o rerank, in 19.6 vs 421 minutes of test time (arXiv 2607.23610). Metadata was the largest single contributor (PyTorch: all features 76.38, SBERT only 44.69). A small supervised RoBERTa+GraphCodeBERT model also beat plain Gemini 2.5 Pro on requirement-to-code links (0.7155 vs 0.5874, arXiv 2509.05585). Gold links in both come from developer references, which the authors call inconsistent.

proposed experiment: Refines PC-SURVEY-20260928-06 (Jev vs open-weight vs fine-tuned vs LLM checker on IMPLEMENTS links) by adding the arm it lacks, a no-model metadata ranker, and a cascade that spends model calls only on its top candidates; H7 then consumes the links. Data: the same 300 adjudicated (requirement or ticket, PR) pairs from 6 to 10 SpecMine Kiro repositories plus one internal repository, each requirement with its full candidate pool of PRs within +-180 days; train the ranker on a disjoint set of repositories. Arms: (A) LambdaMART over BM25, embedding cosine, time proximity, file overlap with paths named in the requirement or design, diff size; (B) Jev Noul "does this PR implement this requirement?" on every candidate; (C) A, then Jev on A's top 5; (D) A, then an LLM checker on A's top 5; (E) A, then a self-hosted open-weight decision model on A's top 5. Metrics: F1 and precision at recall 0.8 against the adjudicated labels; model calls and cost per 1,000 requirements; p95 latency. Kill for the ranker-first design: C and E both more than 3 F1 points below B, or A's top 5 missing the gold PR for more than 10% of requirements.

why it matters for us: Linking each piece of code to the requirement it delivers is the core of the product-development memory, and asking a model about every possible pair is the expensive part. A published study found that simple clues we already record, such as when things happened and which files they touched, found the right links better than large models and far faster. If that holds for us, the graph can check only a handful of candidates per requirement, which makes keeping it current on every change affordable.
