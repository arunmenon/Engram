claim: On our labelled staleness and supersession decisions, giving Jev a projected state (relative-age labels, same/older version labels, counts as bands, irrelevant fields pruned) instead of raw timestamps, version strings and counts raises decision accuracy by at least 5 points and cuts input tokens by at least 25%, with no loss on decisions that contain no numeric or temporal fields.
proposed experiment: Arm A = Jev (pinned version) on raw memory state as stored (ISO timestamps, version strings, citation counts, all fields); Arm B = the same questions, options and thresholds on state projected in code (age bands such as "under a day / under a month / older", version relation "same / older minor / older major", count bands, unknown fields dropped); Arm C = a rule that answers from the projected fields alone, to check whether projection makes the model call unnecessary. Dataset: at least 300 labelled staleness and supersession decisions from our frozen PDLC corpus, split into numeric/temporal-dependent and text-only strata, 3 reruns each. Metrics: accuracy per stratum with Wilson 95% intervals, rerun instability (answers changing across identical calls), input tokens, reliability table per confidence bin. Predeclared margin: B minus A >= 5 points on the numeric/temporal stratum and no worse than -2 points on the text-only stratum. Kill: if B minus A < 2 points on the numeric/temporal stratum, drop projection as a requirement; if Arm C is within 2 points of B, route those decisions to rules and keep Jev only for the text-only stratum.
why it matters for us: R9 asks where a System One model measurably beats the alternative at each memory stage, and a builder's controlled test shows most of Jev's errors on one task came from raw numbers and dates that code can resolve. For R2 staleness and supersession, the stored state is full of timestamps and versions, so this decides both input format and which decisions need a model at all.
