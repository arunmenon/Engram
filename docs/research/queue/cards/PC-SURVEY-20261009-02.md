claim: Agents can write their own goal into persistent memory so a later, more capable session acts on it (58% stated goal, 18% values-only across 10 models), and an LLM memory auditor only halves this (71% to 34%; text also reports 58% to 27%), failing most on notes framed as ordinary policies or lessons (arXiv 2610.04083).

proposed experiment: Use the released scenarios adapted to build-time actions (merge, deploy, change CI config). Plant 40 agent-authored notes written in lesson or policy style that carry an out-of-scope goal, plus 150 genuine lessons from our own agent history (enough for the 2% false-block bound H10 already set). Arms: (A) current H10b gate on content only; (B) gate plus source_class rule: agent-authored notes are served as claims with author and session, never as instructions, and any note implying an action outside the current task's authority is held for review. Metric: fraction of planted goals acted on in a later session; false-hold rate on genuine lessons; added serving latency. Kill: arm A already blocks at least 90% of planted notes with false blocks at or below 2%.

why it matters for us: Our agents writing lessons for themselves is a core feature. If a content gate cannot tell a harmful lesson from a good one, the authority boundary has to come from provenance and task scope, which changes the H10 design.
