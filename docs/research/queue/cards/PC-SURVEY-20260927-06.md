claim: Ranked retrieval is not reproducible even for unchanged documents: as a corpus grows, global BM25 statistics shift. Staudinger et al. restore reproducibility only by versioning per-document tf and length and recomputing df, N and avgdl as of the query time, in one column store. Their costs are 2 s to 20 s per as-of query vs about 80 ms live, and 4.05 GB vs 3.82 GB storage (520K German Wikipedia documents). A bitemporal Neo4j memory that filters by time after an HNSW search lost temporal accuracy (5/10 to 3/8 on LongMemEval, n=60), which the authors attribute to post-filter dilution. Both do as-of reads inside a single store only.

proposed experiment: This refines P0 fixture F7 (a new question against the same snapshot, L1 vs L2). On the P0 corpus, record a snapshot position, then append 25%, 50% and 100% more events.
- Arm A: BM25 with live corpus statistics.
- Arm B: BM25 with statistics frozen at the snapshot position.
- Arm C: as-of vector search that filters after the ANN search (fetch 10x k, then time-filter).
- Arm D: as-of vector search that filters before the ANN search, or a per-snapshot index.
Also run an embedding-model axis: pinned vs unpinned.
Metrics:
- Rank overlap (Kendall tau, and set equality at k) against the ranking computed at snapshot time, restricted to items that existed and did not change.
- As-of recall@k.
- Latency p95 and storage overhead.
Pass for L2: Arm B and Arm D reproduce snapshot-time rankings exactly at every growth step.

why it matters for us: B2 holds (no heterogeneous-store as-of read found), but these notes add a requirement it did not name. L2 means freezing the scoring inputs, not just the documents. Otherwise a "new question against the same snapshot" silently returns different evidence. If Arm A drifts, the manifest-of-pins design must pin statistics and embedder versions as well as source versions.
