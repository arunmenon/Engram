claim: On our own write-gate candidates, restating the review as a batched list of separate typed questions with the existing model recovers at least 80% of the quality and cost gain that swapping in Jev (TypeSafe) on the same question list delivers.
proposed experiment: arm A the current single-prompt review with the existing model vs arm B the same model answering a batched question list, answers only vs arm C Jev answering the identical question list · dataset: the labelled write-gate candidates on the frozen harness (keep or skip, overinterpretation, already saved), at least 200 candidates so that a zero-error cell bounds the rate near 1.5% · metric: F1 on keep or skip and on overinterpretation, wrong-reject rate reported separately, cost and p50 latency per candidate · predeclared margin: arm C must beat arm B by at least 3 F1 points or 30% cost at equal F1 to justify the model swap · kill: if arm B is within 3 F1 points and 30% cost of arm C, restructure the prompt and do not add the decision model at this stage. Design warnings from the source: the source's gain was measured on 40 examples in one run; criteria were clarified while converting, so freeze the criteria text across arms; a wrong reject is unrecoverable, so report it on its own and keep any rejecting arm in shadow.
why it matters for us: R9 says a fast typed decision model belongs at a memory stage only where it measurably beats the alternative on our data; this isolates the model from the question format at the write gate. It also tells R2 whether the write gate's cost problem is a prompt-structure problem we can fix without a new dependency.
