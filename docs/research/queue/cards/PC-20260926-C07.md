claim: On H10's seeded history, the "still true given the snapshot?" audit reaches at least 0.10 higher stale-flag precision at recall >= 0.7 when items are stored as decision records with a date and a reason than when the same items are stored as bare facts, and a "not updated in more than two weeks" age flag scores below both.

proposed experiment: Arm A = age flag: mark anything not updated in more than two weeks (rvaniaaaa's daily compilation recipe). Arm B = bare facts: each item stored as a one-line fact with a timestamp, audited with jevmem's noul ("Is memory X still true for this repository, given the snapshot?"; true = consistent or no evidence against, false = the file, dependency or approach it names is gone or replaced), flag below 0.4. Arm C = decision records: the same items stored as decision, date and reason (JeffWitters: "A decision arrives with a date and a reason attached, so when it stops being true there is something to check it against"), audited with the same noul given the reason. Arm D = source-change invalidation (H10a's required first control): flag an item when a file or dependency it cites changes. Dataset: H10's ~50 Decisions whose underlying file or dependency later changes and ~50 that stay valid, each authored once and rendered in both B and C forms; snapshot per jevmem (tree to depth 3, package.json fields, first 3,000 chars of README) plus the diff of cited files. Metrics: stale-flag precision and recall, threshold fit on half and tested on the other half; audit tokens per item. Predeclared margin: C - B >= 0.10 precision at recall >= 0.7, A below B. Kill: C - B below 0.05 (the reason field is not worth making mandatory), or D matches C (source-change invalidation suffices and the model audit is not needed, which H10a already names as a kill).

Evidence: all four practitioner posts behind this rule are opinions with 0 to 1 likes and 7 to 25 views; the questions "Does storing reasons with decisions measurably reduce stale-entry retrieval? Not tested." and how jevmem's file behaves over weeks ("false `[stale?]` flags ... Not measured") are open in the notes. jevmem lines carry a timestamp and confidence but no free-text reason field, and its snapshot is shallow, so memories about code internals get "no evidence against it" and pass.

why it matters for us: R2's hardest write problem is memory that goes stale silently, and the catalogue offers a concrete representation rule (decisions with reasons) that nobody has measured. The result decides whether P5 makes `reason` mandatory and gives H10a a representation arm; it could seed a new register belief, since no current belief covers record representation.
