claim: Outcome-linked reinforcement that credits every served memory with the task reward (MemRL rule) still reinforces wrong memories. With 10 % planted noisy entries over ten rounds, noisy entries got 3.7 positive updates on average (7.2 with UCB exploration) vs 2.4 under a lower-credit scheme. Separately, storing every self-generated execution (add-all) scored below not learning at all on four agents (e.g. CIC-IoT 71.50 to 59.90).

proposed experiment: Refines H4. H4 compares outcome-linked vs access-count reinforcement. It does not split the outcome-linked arm or define the loop metric operationally. Run H4's replayed stream with four arms: (1) access-count boost; (2) outcome-linked, joint credit to every served memory (MemRL rule); (3) outcome-linked, interventional credit (leave-one-out rerun of the served set on a sample, on batch-invariant inference so replay noise does not decide credit); (4) no reinforcement (add-all baseline). Plant 10 % known-wrong memories (stale Decisions from H10's seed set). Metrics: task success; positive updates per planted entry; planted share at end; feedback-loop rate as B17 defines it. Kill for arm 3: loop rate not below arm 2 by a predeclared margin, or credit cost over budget.

why it matters for us: H4's pass would ship arm 2 by default, and that arm has a published loop failure. The planted-noise protocol gives B17 a number rather than "unmeasured everywhere". It reuses H4 and H10 fixtures, so the added cost is arm 3's rerun budget.
