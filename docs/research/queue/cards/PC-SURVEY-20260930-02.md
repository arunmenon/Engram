claim: On a Spec-to-review workflow with several agents, a shared store filtered by an explicit scope (consumer, verified status, not superseded) keeps at least 80 % of the task-progress gain that unfiltered shared retrieval has over declared handoffs only, while keeping isolation within 5 points of declared handoffs only. Source result (N-SURVEY-20260930-03), repository code domain, fixed executor: declared handoffs only 0.0 % workflow success with 89.4 % isolation; full context 16.0 % and 71.9 %; shared flat retrieval 18.0 % and 73.9 %; Mem0 2.0 % and 89.1 %. The paper did not run a scope-filtered arm.

proposed experiment: Build 40 to 60 workflow cases from our PDLC seed set as matched pairs: a clean case and the same case with one planted artifact (a sibling branch's result, a wrong-entity record, an unverified result, a superseded requirement). Arms, with the executor model fixed: (1) declared handoffs only; (2) unfiltered shared retrieval; (3) shared retrieval filtered by scope fields; (4) full context. Metric: workflow success by executable check, verified handoff success, isolation (polluted-case success among pairs whose clean case succeeds), tokens served per agent. Kill: arm 3 no better than arm 1 on success, or more than 5 points below arm 1 on isolation.

why it matters for us: The published trade-off says that giving agents more shared context buys progress and costs isolation, and that current memory products do not fix this. Our contract asks for one scoped interface; this test says whether scope fields on served items are enough to get both, which decides the read surface for multi-agent use. The matched clean and polluted pair design is also a candidate scoring scheme for the changed-requirement and stale-memory items of our own memory test.
