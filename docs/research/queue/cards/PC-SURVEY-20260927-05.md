claim: Storing the served context is not enough to re-execute a decision. At temperature 0, one 1000-sample run of Qwen3-235B produced 80 distinct completions; only batch-invariant kernels (1.6 to 2.1x wall time) or CoRun-style fixed-shape scheduling (32.6 ms vs 19.4 ms per step) made output deterministic on a self-hosted engine with an identical stack. No source claims hosted APIs are deterministic. agrepl reaches replay fidelity 1.0 only because it returns recorded model responses and never calls the model.

proposed experiment: This refines P0, step 3 (replay at PR review). Use the P0 Spec-to-PR-review fixtures, with at least 30 decisions spread over at least 5 specs.
- Arm A: strict lookup replay. Return the recorded served bundle and the recorded model output. A missing item is an explicit error.
- Arm B: re-run the identical served bundle against the same hosted model snapshot, 5 times per decision.
- Arm C (optional): re-run on self-hosted vLLM with batch-invariant mode.
Metrics:
- Decision flip rate: the share of re-runs where the review verdict or the chosen action differs from the recorded one, not text difference.
- Byte-identical output rate.
- Cost per replay.
Pass for Arm A: zero flips by construction, plus zero silent substitutions. The number that matters is Arm B's flip rate: if it is above 0 with a clustered interval, P0 must define "reproduce" as re-inspection of recorded output only.

why it matters for us: B1 currently treats reproducing a decision as a property of the evidence alone. If Arm B's re-runs flip the verdict, the replay guarantee has to include the recorded output and a serving-stack record: model snapshot, engine version, dtype, parallelism, seed. That shapes the ledger schema before P0 freezes the contract.
