claim: A practitioner framework (Talisman, Ontology Pipeline, 2026) holds that an ontology cannot be built reliably until a controlled vocabulary and thesaurus exist beneath it. For us that means a governed PDLC word list, where each tool's issue types, statuses and link names are alternative labels of one concept, should sit between the tools and our shared types. It gives no measurements.

proposed experiment:
- **Setup.** Collect every issue type, status, label and link name from one Jira project, one GitHub repository and one Linear team, which is probably 200 to 400 strings. Build a small SKOS thesaurus from them: preferred label, alternative labels and a one-line scope note per concept. Budget: two people for two days. Reuse the 300 labelled items from PC-SURVEY-20260928-09 and the matched pairs from PC-SURVEY-20260928-08 if those run.
- **Arms.**
  - A: Jev Choice with the raw target type names as the menu.
  - B: the same Choice with thesaurus-expanded options (preferred label, alternative labels, scope note).
  - C: exact label lookup in the thesaurus first, then B only for strings not found.
- **Metrics.**
  - Type accuracy (G7) and same-item F1 (G13).
  - Share of items resolved by lookup alone.
  - Cost and p95 latency per 1K items.
  - Hours of upkeep per month when one tool adds a new status.
- **Kill criterion.**
  - B beats A by under 3 points on both tasks, and C resolves under 40% of items by lookup: the thesaurus is not worth its upkeep, so map raw names directly.
  - Upkeep exceeds 4 hours a month: fold it into the ontology gate instead of keeping a separate layer.

why it matters for us: Tonight's recommendations add shared kinds and per-tool bindings to our ontology. This tests the cheap layer that the book says must come first, before we commit to the heavier design.
