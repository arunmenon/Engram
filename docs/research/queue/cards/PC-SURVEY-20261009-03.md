claim: A planted memory phrased as a persistent update or authoritative correction is accepted at .23 to .26 (lexical) and .12 to .14 (dense), versus .02 and .00 for the same content without update framing; recency alone changes nothing (arXiv 2608.07622, 100 paired items per condition). Supersession that suppresses old values is worth about 33 points on knowledge-update questions (arXiv 2609.10263), so a hijacked supersede edge would also hide the true value.

proposed experiment: On H7's ~300 typed records, add 40 planted items in three framings (plain mention, "this replaces decision X", authoritative correction) arriving from low-trust sources (pasted ticket comment, tool output), plus 40 legitimate requirement changes from trusted sources. Arms: (A) supersede edge created when the extractor judges the new item updates an old one; (B) same, but the edge is created only if the new item's source_class is at least as trusted as the old item's, otherwise both are kept and flagged as contradicting. Metric: planted items that supersede a true decision; legitimate changes correctly superseded; knowledge-update accuracy on H7's supersession class. Kill: arm A hijack rate below 5%, or arm B loses more than 5 points on legitimate changes.

why it matters for us: Supersession is the PDLC layer's core write and B3 is still a lead. If the update decision can be steered by wording, the same feature that hides stale requirements will hide true ones.
