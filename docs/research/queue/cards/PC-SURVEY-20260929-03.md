claim: In one automotive project, about 10% of human-maintained requirement links were invalid (219 of 2,132). Zero-shot Claude 3.5 Sonnet detected invalid links poorly (invalid-class F1 29.45%); giving it the 3 most similar valid and 3 most similar invalid labelled links raised invalid-F1 to 94.06% (TVR, arXiv 2504.15427), and its errors did not overlap with a plain retrieval classifier's. Across 6.7 million distinct links in commit messages, 70% no longer resolve (arXiv 2305.16591). Jev had the highest contradiction recall of ten models on a three-way entail / contradict / not-mentioned task at about one sixth to one four-hundredth of the others' cost (arXiv 2609.27678).

proposed experiment: Refines H10(a), which audits whether stored Decisions are still true against a snapshot, by applying it to trace links, a case H10 does not cover; its first test ("no gain over source-change invalidation") is arm A here. Data: 200 IMPLEMENTS and REFINES links from SpecMine repositories where the requirement or design file, or the linked code, changed after the link was made, plus 100 links whose ends did not change; two labellers mark each link still valid / no longer valid after the change, kappa reported; rejected links from a disjoint repository set form the labelled-neighbour pool. Arms: (A) source-change invalidation: flag every link whose end changed; (B) Jev Noul "does this PR still implement this requirement as now written?" zero-shot, threshold fit with one temperature on a held-out half (N-SURVEY-20260929-02); (C) B with the 3 most similar valid and 3 most similar invalid labelled links placed in the state; (D) an LLM with the same 3+3 neighbours (TVR recipe); (E) C then D below a confidence threshold. Metrics: invalid-link precision at recall 0.7, invalid-class F1, false-flag rate on unchanged links, cost per 1,000 checks. Kill for model-based revalidation: no arm beats A by 0.10 precision at recall 0.7.

why it matters for us: The links in our product-development memory will be imported from tools and made by models, and published studies show about one in ten such links is wrong, and many more go bad as documents and code change. An agent that trusts a wrong link will act on the wrong requirement. This test tells us whether a cheap check can catch broken links when something changes, or whether simply flagging every changed link for review is just as good.
