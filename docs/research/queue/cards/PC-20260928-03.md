claim: On engineering-memory questions, answering from write-time extracted fact records loses at least 3 points of answer accuracy against answering from the retained source evidence at the same retriever, reader and judge, even though retrieval recall on the source id is unchanged.
proposed experiment: Arm A = index retained source artifacts (design sections, tickets, PR descriptions, decision records) and retrieve top-k; arm B = index one extracted fact sheet per source artifact (same extractor for all, source id inherited) and retrieve top-k; also arm A' = source artifacts at the k whose reader tokens match arm B's. Dataset: the PDLC memory benchmark v1 question set (decision-behind-design, changed requirement, PR-implements) on the frozen harness, 300 or more questions. Metrics: answer accuracy by the fixed judge, reader-level evidence sufficiency (does the served text contain the answer span), recall@k on source id, reader tokens. Predeclared margin: B is worse than A by at least 3.0 points with a 95% paired bootstrap interval clustered by repository excluding 0. Kill: if B is within 1.0 point of A' at matched tokens, extraction is not the loss and the card is withdrawn.
why it matters for us: This is R2's core write-path question (does a durable extraction step destroy evidence) measured where R3 retrieval metrics cannot see it. If the loss replicates on our artifacts, source evidence stays canonical and extraction becomes an optional derived view with its own sufficiency metric in the benchmark.
