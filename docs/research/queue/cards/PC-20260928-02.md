claim: With the model and memory arm held fixed, the host harness changes cost per resolved engineering task by at least 1.5x while changing resolve rate by less than 3 points, so memory-arm cost effects measured in one harness do not transfer to another.
proposed experiment: Arms: A = our current host harness with the memory tool enabled; B = a minimal four-tool harness (read, write, edit, bash; e.g. Pi) with the same memory tool exposed through the same MCP interface. Model fixed; memory store and retrieval config frozen; memory on and memory off in each harness (2 x 2). Dataset: 30 tasks from our P0 engineering set (or SWE-bench Lite's HarnessTax 30-task sample if P0 is not ready), 3 attempts each, 100-turn cap. Metrics: resolve rate and cost per attempt at a fixed price list, bootstrap 95% CIs over tasks; primary quantity is the memory-on minus memory-off cost delta in each harness. Predeclared margin: the harnesses agree if the memory cost delta differs by less than 20% between A and B. Kill: if the deltas agree within 20% and resolve rates within 3 points, keep the current host and stop reporting per-harness costs.
why it matters for us: This is R6 evaluation integrity: a memory arm that saves tokens may save them only against one harness's overhead, and HarnessTax shows harness overhead alone can be 1.5x to 2x. The answer decides whether our memory-cost claims need a second harness before we believe them.
