## Contradictions and tensions (read first)

No belief on R6 or R7 (B19 to B23) is contradicted by anything read. Four findings are in tension with positions the company holds elsewhere:

1. **A pattern the landscape marks for adoption did not replicate.** The September landscape lists ReasoningBank's item schema as a drop-in fit for BehavioralPattern nodes. An independent re-evaluation (N-SURVEY-20260930-05, Salesforce) finds ReasoningBank's gain over no memory is +1.5 points with p=0.23 in the default task order and 4.1 to 5.0 points below no memory when the task order is shuffled. Agent Workflow Memory is below no memory in every setting. This does not contradict B16 (it supports "induced procedures are a hypothesis"); it contradicts the landscape's fit label and adds a control H4 and H6 lack (task order).
2. **An earlier survey note is qualified.** N-SURVEY-20260928-08 reported that a normalised convex combination beat RRF on every dataset. N-SURVEY-20260930-08 finds that for graph plus vector fusion a calibrated combination has no paired advantage over RRF at k=60 on held-out queries (7 wins and 11 losses, p=.48; 3 wins and 0 losses, p=.25). B23 stands. Card PC-SURVEY-20260928-03 should expect a null when the graph leg is included.
3. **Verbatim retention does not answer current-state questions.** On StateMemBench (N-SURVEY-20260930-06) the full transcript in context scores 0.149 and answers with the superseded value in about 65 % of in-pool answers. H1's "verbatim first" arm should be expected to fail this question class. Not a belief contradiction; it bounds what H1 can show.
4. **Memory products trail plain baselines on interdependent tasks.** On MemoryArena (read for N-SURVEY-20260930-02) memory agents average 0.12 task success against 0.17 for long context and 0.20 for plain retrieval. This matches the DreamBench-SWE and CL-Bench pattern already on the bus rather than contradicting it, and it is a second independent benchmark saying so.

### What I looked for

### What I found
- **Judge and reader floor on LongMemEval-S (N-SURVEY-20260930-04).** Two passes of one frozen system score 479 and 475 of 500; the official judge flips 3 verdicts on byte-identical answers; a second judge agrees on 493 of 500 and scores 472; the reader model moves the score 14 points among strong readers; 8 of 500 gold answers are disputable; a tool-enabled reader leaked the expected answer from the web. The top of this leaderboard is inside its own noise. Supports B20 and the frozen-judge rule with numbers.
- **Run variance and task order (N-SURVEY-20260930-05).** Adding a memory loop raised run-to-run variance in 17 of 24 cases; published gains vanish under shuffled order. Card PC-SURVEY-20260930-03 adds order and repeated runs to H4 and H6.
- **A staleness benchmark with computed gold (N-SURVEY-20260930-06).** StateMemBench: 234 scenarios, closed-pool grading that names the stale answer, anti-trap cases. Supersession marking measured in isolation (0.174 to 0.298, one backbone), which is relevant to B3 without being enough to move its grade.
- **Recall versus task success (plan question 4).** Partly answered. MemoryArena's authors claim systems near saturation on LoCoMo do poorly on interdependent tasks; they print no LoCoMo numbers beside their own, so the claim is qualitative. StateMemBench shows Mem0 at 0.566 to 0.594 on LongMemEval and 0.149 to 0.177 on state tracking with the same backbones, which is a quantitative instance.
- **Statistics (plan question 2).** Partly answered by example: Welch p=0.23 on three runs for a 1.5-point gain; Wilson intervals overlapping across all arms at n=20 to 40. No source on clustered standard errors was read this run; see pending.

### What this should change in our PDLC memory benchmark
1. Compute gold by replaying typed operations (StateMemBench), so there is no answer key to dispute. LongMemEval has 1.6 % disputable gold and LoCoMo 6.4 %.
2. Grade staleness with a closed pool that names the stale answer; report current-state accuracy and drift rate separately; include anti-trap cases.
3. Build "changed requirement" and "stale memory" items as clean and polluted pairs with an executable check (CoMemBench), and score isolation only where the clean case passes.
4. Score interdependent multi-session tasks, not only recall (MemoryArena), and always run plain long-context and plain retrieval arms.
5. Two full passes per configuration, judge controls in every scoring run, one re-judge of identical answers, a pinned reader, tools off, a held-out split (the Auditable paper did the first four and admits lacking the last).
6. Publish per-arm denominators; a failed sample scores zero.
7. Vary ingestion order and task order at least once (RoutePrism, Fragility).

## R7 Interoperability and coordination contracts

Serves no CTO priority directly, except that note 03 (CoMemBench) is also a memory benchmark (**priority 4**) and note 02 documents a benchmark harness (**priority 4**). The rest serves the design-partner contract behind B22.

### What I looked for
Swap tests of memory stores under a fixed harness; fusion across different evidence units (B23); a testable memory interface standard with conformance tests; measured handoff or shared-memory failures with a contract arm; point-in-time reads across several stores.

### What I found
- **A controlled swap study of the store itself (N-SURVEY-20260930-01).** Writer-model swap: notes +9.91 and −13.28 points by direction, fixed-schema graph ±0.1. Mixed embedding index recovers 4.96 of 11.90 points. Store-only repair 0 of 48. Supports B22 (a swap test finds real damage), B1 (raw source enables repair) and B5. Card PC-SURVEY-20260930-01.
- **What breaks when backends are swapped behind one harness (N-SURVEY-20260930-02).** A 100,000-token write limit turned into skipped tasks, a backend-named patch was needed, failed samples vanished from the denominator, embedders were unmatched. Vendor-authored, with the conflict stated. Useful as a list of contract checks, not as a ranking.
- **Shared memory between agents (N-SURVEY-20260930-03).** More shared context raises progress and lowers isolation; memory products do not fix it; results change with workflow shape. Card PC-SURVEY-20260930-02 adds the scope-filtered arm the paper did not run.
- **A source-to-memory invalidation contract (N-SURVEY-20260930-07).** Item-level invalidation precision 1.00 against 0.25 for the coarse unit; the same bytes get 100 % or 11 % compliance depending on the planner model. Card PC-SURVEY-20260930-04 refines H10's source-change baseline and P5's granularity.
- **Fusion (N-SURVEY-20260930-08).** RRF at k=60 holds against a calibrated alternative for graph plus vector lists. The heterogeneous-unit clause of B23 is still untested by any source found.
- **Interface standards (plan question 3).** Not answered. AIM (Microsoft) uses the word interoperable for a shared registry with a record schema and tests no second backend or agent. MELD defines a merge protocol between agent memories with a single wire object and a status CRDT (30 of 30 partition-heal reconvergence against 11 of 30 for last-writer-wins, merge classifier AUC 0.968, false-merge rate 0.013) and tests only homogeneous agents. The Model Context Protocol conformance repository exists (github.com/modelcontextprotocol/conformance) and covers protocol behaviour, not memory semantics; not fetched.
- **Point-in-time reads across stores (plan question 5).** Nothing found. B2 is unchanged.
