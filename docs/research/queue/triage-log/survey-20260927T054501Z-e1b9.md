# Survey summary, run survey-20260927T054501Z-e1b9 (R1, R5), 2026-09-27

## Contradictions and belief changes (read first)

1. **B17 (working) is partly contradicted.** "Practice Makes Unsafe" (arXiv 2608.12851, note N-SURVEY-20260927-10) reports an Unsafe Retrieval Rate (URR): the share of clean-session probe tasks that retrieve a skill judged unsafe (content-unsafety score of 3 or more). The unmitigated worst cell reaches 52.00%. This is a per-task reuse rate of bad memories, not the per-memory "fraction of wrong memories whose stability increased" that H4 defines. **Suggested rewording of B17:** "No system in our survey reports the per-memory reinforcement rate of wrong memories; per-task unsafe-reuse rates now exist (URR, 2608.12851)." H4 can adopt URR as a secondary metric.
2. **B1 (working) is refined, and contradicted for re-execution.**
   - Sources: the CoRun and batch-invariance cluster (N-SURVEY-20260927-13) and agrepl (N-SURVEY-20260927-14).
   - Re-execution on hosted APIs: the same served context does not reproduce the same output. At temperature 0, one 1000-sample run of Qwen3-235B gave 80 distinct completions. No source claims any hosted API is deterministic.
   - Re-execution self-hosted: works only with batch-invariant or CoRun-style inference on an identical stack, at 1.6 to 2.1x wall time or about 1.7x per-step latency.
   - Re-inspection: B1's sufficiency claim holds only if the recorded model output and a serving-stack record are retained alongside the served artifacts.
   - Suggested wording: "sufficient for re-inspection when output and serving stack are recorded; not sufficient for re-execution on hosted models."
3. **B18 (lead) gains its first measured support, including a benign coding case.** No contradiction. Details under R5 below.

## R1 Evidence and reproducibility

**Looked for:** model-side reproducibility of a served decision (B1); record and replay for tool-using agents; point-in-time reads over heterogeneous stores (B2); a provenance-correctness benchmark.

**Found:**
- **N-SURVEY-20260927-13, CoRun (2608.14376) plus the Thinking Machines "Defeating Nondeterminism" blog, strength paper-ablated.**
  - Nondeterminism at temperature 0 comes from batch-dependent kernels.
  - Batch-invariant kernels: 26 s default vs 55 s deterministic vs 42 s improved.
  - CoRun: deterministic with 15 to 324% more throughput than batch-invariant kernels (19.4 / 88.4 / 32.6 ms per step for default / batch-invariant / CoRun).
  - CoRun's determinism test is small (32 prompts, at most 8 output tokens). It makes no claim across hardware, kernel versions or tensor-parallel degrees.
- **N-SURVEY-20260927-14, agrepl (2607.16200), strength builder-report.**
  - Transport-layer record and replay. Its fidelity of 1.0 is tautological because it replays recorded LLM responses.
  - Inconsistencies inside the paper: n is stated as 250 but the setup gives 25; the median latency reduction is stated as 98.3% but the per-workload rows show 99.4 to 99.8%.
  - Useful as a design reference for "exact lookup, never substitute".
- **N-SURVEY-20260927-15, Reproducible Hybrid Time-Travel Retrieval (2411.04051).**
  - Ranked BM25 retrieval is not reproducible even for unchanged documents, because global statistics drift as the corpus grows.
  - The fix is a versioned column store that recomputes df, N and avgdl as of the query time. It costs 2 to 20 s per as-of query vs about 80 ms live, and 4.05 GB vs 3.82 GB storage.
  - It is a single store, so it supports B2.
- **N-SURVEY-20260927-16, Graph-native bitemporal memory store (2607.26520).**
  - As-of reads filter by time after an HNSW search, and temporal accuracy dropped (5/10 to 3/8, n=60). No code released.
  - Single store, so it supports B2. It is weak evidence and kept only for the post-filter failure mode.
- **B2 verdict:** held. Every as-of read found runs inside one store. New requirement: L2 snapshots must also freeze the scoring inputs, meaning BM25 statistics and the embedder version.

**Skipped as known:** DFAH (2601.15322), Re-feeding Is Not Replaying (2606.15621), Chronicle (2609.20625), Revoked but Still Authoritative (2609.08258), and the provenance architectures in landscape section 1.

**Considered, not noted:**

- GitOfThoughts (2606.14470): single git store; its numbers are accuracy, not replay.
- Quantifying non deterministic drift (2601.19934): abstract only. Directional support for the CoRun note, with no numbers extracted.

## R5 Learning from experience

**Looked for:** B18 measurement; B16 raw vs distilled head-to-head; B15 lineage vs single-trajectory; B17 feedback-loop rate.

**Found:**
- **N-SURVEY-20260927-09, Your Agent May Misevolve (2509.26354, ICLR 2026), plus MemEvoBench (2604.15774) folded in.**
  - Benign memory build-up in a coding agent: SE-Agent (Qwen3-Coder-480B) worked through 3 rounds of SWE-Bench-verified. On RedCode-Gen, its refusal rate then fell from 99.4% to 54.4% and ASR rose from 0.6% to 20.6%. There was no attacker.
  - The "references, not rules" framing partly recovered this: ASR 13.1%, refusal 66.9%.
  - Planted-memory reward hacking: more than 60% of 40 cases. In one cell the judge is the same model as the agent (Gemini-2.5-Pro); a human judge was also used.
  - MemEvoBench with biased feedback: ASR 71.6 / 84.9 / 87.8% over three rounds.
  - Supports B18. One model and one benchmark, and n is not stated for RedCode-Gen.
- **N-SURVEY-20260927-10, Practice Makes Unsafe (2608.12851), strength paper-ablated.**
  - 25 configurations, each covering 525 tasks over 25 episodes. All 21 evolved configurations authored unsafe skills, and 15 caused harm in fresh sessions.
  - Exposure sweep: 16.0% carryover ASR rises to 35.3% after 3 malicious tasks.
  - SafeEvolve: unsafe retrieval 35.33% to 8.67%, harm 21.33% to 4.00%. Benign success on clean-session probes fell from 53.33 to 40.67, which the headline "0.4 point" utility claim hides.
  - Judges are separate models. This is the B17 partial contradiction above.
- **N-SURVEY-20260927-11, SkillEvolBench (2605.24117), strength paper-ablated.**
  - 180 tasks, 6 environments (one of them code debugging), 10 models, 3 CLI harnesses.
  - Skill arms vs no-skill under frozen deployment: -2.56 and -2.44 pp.
  - Raw-trajectory reuse: 37.6% vs a no-skill mean of 34.7% (computed from Table 1), the best of any arm.
  - Replay success overstates transfer by up to about 18 pp.
  - Supports B16. Candidate for promotion from lead to working once the harness can reproduce it on the E1 code environment.
- **N-SURVEY-20260927-12, Huxley-Goedel Machine (2510.21614).**
  - Lineage-pooled selection correlates with descendants' performance at 0.778, vs 0.285 (DGM) and 0.444 (SICA), on SWE-Verified-60.
  - Accuracy 56.7% vs 53.3% vs 50.0%, a gap of 2 of 60 tasks. Single runs, no ablation isolating the lineage signal.
  - Weak, partial support for B15: it supports lineage-pooled parent selection, not comparative refinement. B15 stays lead.
