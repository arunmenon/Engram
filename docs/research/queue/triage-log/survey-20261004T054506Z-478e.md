## R10: context graph and ontology

**Looked for:** how well current methods decide an IMPLEMENTS link and how candidate-set size matters; prescribed ontology vs learned schema for downstream QA; deduplication during ontology-guided extraction; schema evolution (DIAL-KG already read).

**Found and wrote:**
- N-SURVEY-20261004-02 `paper-issue-commit-linking-classic-rerankers-vs-llm-2605-00447.md`, with LinkAnchor 2508.12232 as a companion. A random-forest reranker matches GPT-5.1 on issue-to-commit linking over 41,203 test issues, and a time window keeps 97% of true links. Neither paper models "no link" or confidence. Priority 3.

**Read and not noted (below threshold):**
- arXiv 2511.05991 (Granter.ai): ontology learning vs KG construction for RAG. It uses one document and 20 questions, and 18/20 vs 18/20 cannot be told apart. Its one usable signal: schema-only graphs scored 3/20 and 4/20 until source chunks were attached to nodes, which raised both to 18/20. This supports anchoring claims to exact content, but the evidence is too weak for a note.
- arXiv 2607.28662 (Konectu): ontology-guided, deduplication-aware extraction on confidential naval documents. It is an engineering report. It claims search recall went "from roughly 70 to 95 percent with no false merges" with no stated evaluation set, and ontology context fell from about 11,200 to about 700 tokens by retrieving only the relevant slice. No code, and the evaluation section was not retrievable in full.

**No new evidence found on:** confidence-scored trace links with calibration, or schema evolution beyond DIAL-KG and the Palantir and Fabric docs already on the bus.
