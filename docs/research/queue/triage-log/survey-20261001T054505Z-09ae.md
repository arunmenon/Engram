## Contradictions and narrowings (read first)

1. **Our PDLC design misreads its source on link confidence (R10, priority 3).** `pdlc-memory-layer.md` section 2 and `memory-research-landscape.md` row 6.5 cite Trust-Aware Multi-Agent Traceability (arXiv 2606.17203) for "a calibrated confidence per trace link ... so low-confidence upstream decisions do not orphan requirements downstream". On a primary read the paper reports **no calibration measurement** (ECE and Brier are named as metrics, but no values appear in any table). The confidence is the unnamed LLM's own five-band score. And **filtering by that confidence lowered conflict-aware path completeness from 100.00% to 33.64%** (Table VI). The useful finding is the threshold sweep: 0.7 gives the best F1. Note N-SURVEY-20261001-01; card PC-SURVEY-20261001-01. This is a claim in a design document, not a register belief, so no belief id is affected. The design doc's sentence should be corrected.
2. **B14 ("vendor calibration is claimed, not shown") no longer holds for Jev Choice.** An independent study with all raw responses released (arXiv 2609.37647) measured pooled Choice ECE 0.028 over 279,925 answers. B14's second half still holds, more strongly than before: binary and multi-label probabilities need local thresholds (multi-label mean P(yes) 0.209 vs observed 0.041; UNFAIR-ToS F1 0.499 to 0.748 after tuning). Suggest a revision event that narrows B14 to binary and multi-label questions. Note N-SURVEY-20261001-04. Bongard's report (vendor) puts Jev's ECE at 0.128 on DecisionBench, so calibration depends on the task.
3. **B11 narrowed: a "none" option is not enough for admission.** With the correct answer absent, Jev chose "none" 7% of the time on two-step arithmetic (99% when present). Per-candidate Boolean verification rejected correctly 99% of the time (arXiv 2609.39496). This supports B11's split between ranking and admission, and adds that admission must be per-candidate or thresholded when dates, versions or counts decide. Note N-SURVEY-20261001-05; card PC-SURVEY-20261001-02.

## R10: the context graph and its ontology

**Looked for:** (1) confidence-scored trace links; (2) agent-maintained traceability graphs with numbers; (3) schema evolution for LLM-built graphs; (4) ontology-guided extraction from software artifacts; (5) traceability benchmarks for our PDLC benchmark.

**Found:**
- Confidence-scored links: Trust-Aware (N-01); see contradiction 1.
- Traceability graph: TraceDev (N-02). Removing the graph-walking validator dropped task success from 47.19% to 28.37% (ETOUR, DeepSeek-V3.2). The graph's own link accuracy is not reported, and there are no test nodes.
- Schema evolution: DIAL-KG (N-03). Types are admitted by frequency, coherence and an LLM check, then merged across batches. A separate informational vs evolutionary intent decision drives soft deprecation: deprecation precision 0.986 on Kubernetes release logs; without the intent step, delta-precision fell from 0.976 to 0.848. GRAFT gives a logic-only vocabulary of 11 schema edits compiled to Cypher, with no learned component.
- Ontology-guided extraction from software artifacts: nothing new beyond 2025 work (arXiv 2509.00140, triple extraction from SE standards, not read). Question left open.
- For the PDLC benchmark (priority 4): TraceDev uses ETOUR (58 use cases) and SMOS (67), the classic traceability sets with gold links. DIAL-KG's SoftRel-Delta (1,515 Kubernetes release-log entries, three change windows) is a template for "notice a changed requirement" items. But it is the authors' own data and no release was found. Both suggest scoring completeness and deprecation with recall, not precision alone.

**Skipped as known:** LinkRank, PAIChecker, TraceLLM, TVR, SpecMine, EDC and AutoSchemaKG, EvoWiki, Graphiti and Cognee docs, OSLC, Palantir, Fabric IQ, OpenBKN, MegaMemory, graph-DB cost paper, MOOSEDev, ProjectMem. EA-Graph (landscape row 6.2) was not re-read; no new number sought this run.
