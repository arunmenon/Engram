claim: On our own write-gate decisions, the answer of a typed decision model follows the option name rather than the rubric bound to it. Specifically, on H5's 90 labelled extracted items, swapping which natural option name (yes/no for Noul `quote_supports_item`; the four `source_type` names for Choice) is bound to which rubric, with question, state and rubric text unchanged, changes Jev's decision on more than max(2 x test-retest floor, 5 of 90 items); and neutral option names (A/B, or random strings) with meaning carried only in the rubric keep F1 against labels within H5's noise floor of the aligned natural-name template. Source: arXiv 2609.26758 (N-SURVEY-20260928-10), 76.92% flips with yes/no names versus 6.00 to 6.50% with neutral names on generic workflow decisions; hosted Jev AUC .8146 to .5806 under the swap. Transfer to memory decisions with long domain-specific rubrics is untested; that is the question.

arms:
- A (aligned natural names, current H5 design): Noul options named yes/no with rubrics matching their everyday meaning; Choice `source_type` options named `user-stated`, `tool-result`, `inferred`, `imported` with matching rubrics.
- B (neutral names): the same rubrics, option names replaced by `A`/`B` (Noul) and `A`/`B`/`C`/`D` (Choice); a second neutral variant B' uses random 6-character strings, fixed once and recorded.
- C (swapped binding, sensitivity probe only): the same names and rubrics as A, with the name-to-rubric binding permuted (Noul: yes bound to the "does not support" rubric; Choice: a fixed derangement of the four names). Expected answers are re-mapped through the rubric, so a model that reads the rubric scores identically to A.
- Every arm is run twice with identical requests (A1, A2 and so on) to measure the test-retest floor.
- Models: hosted Jev (version pinned at freeze) and one self-hosted open-weight model, Laya-0.4B (Apache 2.0 per its model card), as a comparison of read-out sensitivity (priority 2). decider-0.8b is a substitute only if its licence is confirmed before freeze.
- Score `strength` is out of scope: override: the card includes it, but a Score decision has no option names to swap; its scale anchors are a different question and are not tested here.

metric:
- Primary: flip rate of C relative to A, where a flip is a decision in C whose rubric-mapped answer differs from the same item's decision in A1, per model and per template.
- Floor: flip rate of A2 relative to A1 (test-retest), per model and per template.
- Secondary: F1 against the H5 labels for A, B and B'; ECE per arm (reported, not used for the decision; 90 items is too few to estimate ECE tightly).
- Report the top-two option probability gap per decision; flips concentrated in small-gap items are noted separately.

predeclared margin: Naming is a risk for us if C's flip rate exceeds max(2 x floor, 5/90 = 5.6%) on either template for Jev. Neutral names are adoptable if B's F1 is no more than H5's noise floor below A's F1 (H5's noise floor from its own repeated runs; if H5 has not measured it yet, use 0.05 F1 as the provisional floor and say so in the verdict).

sample size and power note: 90 items x 2 templates x 4 conditions (A, B, B', C) x 2 runs x 2 models = 2,880 calls. The source effect is about 70 pp; at that size 90 paired items detect it with power near 1. The threshold of 5 of 90 items is set by resolution: with zero flips in 90 independent items the one-sided 95% upper bound is about 3.3% (B21), so smaller effects are not claimable at this size. Items that come from the same source document or session are correlated; intervals are clustered by source document, which lowers the effective n; the number of clusters is reported next to every interval. The F1 comparison of B vs A is underpowered for small differences (paired, 90 items): it can show a large loss, not equivalence; the verdict says so.

kill criterion: If C flips no more than max(2 x floor, 5/90) on both templates for Jev, naming is not a risk on our templates: stop, keep A, and H5 proceeds unchanged. If B's F1 is more than the noise floor below A's, do not adopt B even if C flips heavily; keep aligned natural names and forbid rubrics that refine or invert a name's meaning.

what a pass unlocks: The template wording standard for every Jev and open-weight decision at the write gate (H5), the staleness audit (H10a) and the IMPLEMENTS link decision (E-20260928-08), fixed before those larger runs spend budget; a standing swap audit for new templates; a first read-out sensitivity comparison of Jev against a self-hosted model on our own decisions.

cost (runs, tokens, people-days): 2,880 decisions; Jev billed per call (the source paper's comparable robustness run cost well under USD 1 for 11,368 requests, so expected spend is a few US dollars, estimate); Laya-0.4B on one CPU or T4-class GPU; about 1.5 people-days to build the arm variants and scorer on H5's items. ## Execution packet

- harness: harness not yet built: it must (1) load the frozen H5 item set; (2) render each item into four template variants (A, B, B', C) from one template source file per decision type, differing only in the option-name map, and assert byte equality of question, state and rubric text across variants; (3) call hosted Jev and a local Laya-0.4B with identical payloads, twice per variant, logging request bytes, response, option probabilities and billed tokens; (4) map every answer back through its variant's name-to-rubric map to a rubric id before scoring; (5) write the output manifest below. No arm may see labels.
- dataset: H5-labelled-90, the 90 labelled extracted items of H5 (30 obvious, 30 ambiguous, 30 no-fit) from the discovery plan. Frozen as a JSONL file plus a manifest listing each item id, source document id and sha256 of the item record; the manifest sha256 is written into the run bundle before the first call. If H5's labels are not frozen by the start date, the run waits; it does not relabel.
- baseline arm: A, the current H5 template wording with natural names aligned to natural polarity, run twice (A1 is the reference, A2 gives the floor).
- metric definition and statistic: flip(i) = 1 if rubric_id(C, i) != rubric_id(A1, i); flip rate = mean over items. Floor = mean of 1[rubric_id(A2, i) != rubric_id(A1, i)]. Excess = C rate minus floor with a 95% cluster-bootstrap interval (10,000 resamples, clustering unit: source document). F1 per arm against H5 labels with the same cluster bootstrap for B minus A.
- budget: policy unset (policy.md status: unset; nothing executes until the CTO sets it; sized at S above).
- kill rule (machine-checkable): `naming_risk = any(flip_rate_C[jev][t] > max(2*floor[jev][t], 5/90) for t in ["noul_quote_supports_item", "choice_source_type"])`; `adopt_neutral = naming_risk and (F1_A[jev] - F1_B[jev]) <= noise_floor_F1`; if `not naming_risk`: verdict = "negative".
- expected output manifest: `run_manifest.json` (dataset manifest sha256, model versions, template file sha256s, start and end times); `calls.jsonl` (one row per call: item id, model, arm, run, request sha256, answer, rubric id, option probabilities, billed tokens, latency ms); `flips.csv` (per model, template, arm: flip rate, floor, excess, interval, clusters); `f1_ece.csv`; `verdict.json` (naming_risk, adopt_neutral, verdict, per-template numbers); `receipts.sha256` (sha256 of every file above).
