claim: For typing items from connected engineering trackers onto the ontology's shared types, a governed PDLC thesaurus (one preferred label per concept, each tool's type-bearing strings as namespaced alternative labels, a one-line scope note) raises type accuracy over a menu of the same shared type names with the same scope notes but no alternative labels; and exact, namespaced lookup in the thesaurus types a large share of items with no model call, without losing accuracy against the model call. Only type accuracy, the lookup share and upkeep are tested; token cost and latency are reported, not claimed, and same-item matching (G13) is not tested here. Source: N-SURVEY-20260928-27 (Talisman, Ontology Pipeline, 2026): a practitioner framework that says a controlled vocabulary and thesaurus must precede the ontology; no measurements, no baseline, no case study, and the author sells the framework. N-SURVEY-20260928-26 (synthesis) proposes shared kinds with per-tool bindings; N-SURVEY-20260928-20 notes Cognee's canonical renaming on match, also unmeasured. The evidence is opinion grade: this spec tests a design idea. It is the exploration slot of its run: cheap, and a surprising result either way changes the binding design before E-20260928-15-r2's heavier work.

arms (same items, same pinned typed Choice model (Jev), same scorer; arms differ only in the menu and the lookup step):
- A (names): typed Choice over the shared target types, each given by its type name only.
- A2 (names plus definitions, control): each option rendered as the type name plus the same one-line scope note the thesaurus uses; no alternative labels.
- B (thesaurus menu): each option rendered as preferred label, the alternative labels for the item's tool and the scope note.
- C (lookup first): the deterministic lookup below; items it types take that type with no model call; all others go to B.

deterministic lookup (C): thesaurus concepts are namespaced by tool and field, for example `jira:issuetype:Bug`, `github:label:type/bug`, `gitlab:label:type::bug`. Only type-bearing fields are used: the Jira issue type; for GitHub and GitLab, labels in the thesaurus's declared type-bearing label set for that tool; statuses, priorities and other labels never type an item. Normalise each type-bearing string (Unicode NFKC, casefold, trim, collapse whitespace, treat `-`, `_`, `/` and `::` as one separator); look up (tool, field, normalised string) in the alternative-label index. The item is typed by lookup only if every type-bearing string on it resolves to exactly one concept and all of those concepts map to the same shared type. Zero matches, an empty field, a string matching more than one concept (a collision, listed at freeze in `collisions.json`), or type-bearing strings mapping to different shared types all fall back to B. No heuristic tie-breaking.

metric: type accuracy against the gold shared type (primary); share of held-out items typed by lookup in C; C's accuracy on lookup-typed items; upkeep hours per month from the drill below; tokens, cost and p95 latency per 1,000 items per arm (reported).

predeclared margin: governed-alias benefit: B minus A2 at least 3.0 points with the 95% clustered interval excluding zero; definitions benefit: A2 minus A, same rule, reported and used for `definitions_suffice`; lookup: share at least 40% and the one-sided 95% lower bound of (C minus B) above minus 2.0 points; upkeep at most 4.0 hours a month. Bounded negative on each gain: the one-sided 95% upper bound below 3.0 points.

sample size and power note: 450 held-out items, 150 per tool. Clustering unit: (tool, the item's normalised type-bearing strings), because the lookup outcome and much of the Choice outcome depend only on those; the number of clusters is reported, and if it is under 30 the interval switches to a cluster-level t interval. B minus A2: discordance about 0.08, design effect about 2: SE = sqrt(0.08 / 450) x sqrt(2), about 1.9 points; P(pass) at a true 8-point gain about 0.99, at a true 3-point gain about 0.35. C versus B: they differ only on lookup-typed items; at a 40% lookup share with about 5% of those items disagreeing with B, discordance is about 0.02: SE = sqrt(0.02 / 450) x sqrt(2), about 0.94 points; at a true difference of 0, non-inferiority at minus 2 is shown with probability Phi(2 / 0.94 minus 1.645), about 0.69. The lookup share has a clustered SE of about 3.3 points at a true 40%.

kill criterion: the thesaurus layer is killed on the bounded negative (upper bounds of B minus A2 and A2 minus A below 3 points, lookup share under 40%), and folded into the ontology gate if upkeep exceeds 4 hours a month. Invalid (rerun under a new spec revision, not a verdict): the scored thesaurus containing any post-cutoff string; gold labellers overlapping with thesaurus builders; gold inter-annotator agreement (Cohen's kappa) below 0.7 before adjudication; the scored thesaurus sha256 changing at any point, including during the upkeep drill.

what a pass unlocks: the binding design for gateway component 15 (per-tool bindings through a governed thesaurus) and a deterministic lookup that removes model calls for typing; menus for the G7 Choice; input to E-20260928-15-r2 and E-20260928-16-r2, where new labels would land as alternative labels. The register holds no belief on controlled vocabularies, so a pass proposes a new belief rather than moving a grade.

cost (runs, tokens, people-days): thesaurus build, 2 people x 2 days; gold labelling of 450 items by 2 other engineers, 2.5 days each; harness 2 engineer-days; upkeep drill 1 hour. Model tokens: A, A2 and B at about 1.5k tokens per item, 450 items each, about 2.0M; C's fallbacks about 0.4M; total about 2.4M Jev tokens, 2 runs, under 1 USD at 0.042 USD per million. Cost S.
