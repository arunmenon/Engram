claim: On H10's seeded history, the "still true given the snapshot?" audit reaches at least 0.10 higher stale-flag precision at recall >= 0.7 when items are stored as decision records with a date and a reason than when the same items are stored as bare facts, and a "not updated in more than two weeks" age flag scores below both. This is the exploration slot: a cheap test of an opinion-grade rule that no current belief covers.

arms:
- Arm A (age flag): flag any item not updated in more than 14 days (rvaniaaaa's daily compilation recipe).
- Arm B (bare facts): each item as a one-line fact with a timestamp, audited with jevmem's noul ("Is memory X still true for this repository, given the snapshot?"; true = consistent or no evidence against it; false = the file, dependency or approach it names is gone or replaced).
- Arm C (decision records): the same items as decision, date and reason, audited with the same noul with the reason included in the state.
- Arm D (source-change invalidation, H10a's required first control): flag an item when a file or dependency it cites changes.
- Snapshot for B and C: jevmem's recipe (tree to depth 3, selected package.json fields, first 3,000 characters of README) plus the diff of files cited by the item. Same audit model, prompt and batch size for B and C.

metric: stale-flag precision at recall >= 0.7 (threshold fit on the fitting half, applied to the test half) per arm; recall at the fitted threshold; audit tokens per item.

predeclared margin: directional pass requires C minus B precision >= 0.10 at recall >= 0.7 on the test half AND A below B. Because this is exploratory, a pass is directional only and cannot by itself make P5's reason field mandatory.

sample size and power note: target 100 stale and 100 still-valid decisions (at least H10's 50 and 50), across at least 6 repositories; the fit and test halves are split by repository so no repository's items straddle them. With about 50 stale items in the test half, precision at recall 0.7 rests on about 35 true flags, so the standard error of a precision difference is roughly 0.07 even with pairing (the same items appear in B and C); a 0.10 difference is not reliably detectable. The verdict therefore reports the paired difference with a repository-clustered interval and labels any result as directional. Leakage control: reasons are harvested from artifacts dated before the change that made the item stale (ADRs, PR descriptions, commit messages, design notes), never written by the audit designer or anyone who knows which items later go stale; items with no pre-change reason are excluded from both forms.

kill criterion: reason_not_worth_it: C minus B precision below 0.05 at recall >= 0.7. source_change_suffices: D's precision at recall >= 0.7 is at least C's (the model audit is not needed, which H10a already names as its kill). Stop before running (not a result) if fewer than 50 stale items with pre-change reasons exist.

what a pass unlocks: a confirmatory run and a candidate register belief on record representation; informs whether P5 makes `reason` mandatory on Decisions and Beliefs; gives H10a a representation arm.

cost (runs, tokens, people-days): S. Assumptions: audit batches of 20 items; each call about 3,000 snapshot tokens plus 20 x (60 item tokens + 500 diff tokens) = about 14,000 tokens.
