claim: When the requirement or design text, or the code of the linked pull request, changes after a trace link was written, Jev asked "does this PR still implement this requirement as now written?" with the 3 most similar valid and the 3 most similar invalid labelled links from other repositories placed in its state reaches invalid-link precision at recall 0.7 at least 0.10 higher than flagging every link whose end changed (source-change invalidation); zero-shot Jev and an LLM given the same neighbours are reported. This applies H10(a)'s first test (does a model audit beat plain source-change invalidation?) to trace links, a case H10 does not cover. Sources: N-SURVEY-20260929-07 (paper-single-benchmark): in one automotive project 219 of 2,132 human-maintained requirement links were invalid (about 10%, kappa about 0.962); zero-shot Claude 3.5 Sonnet detected them poorly (invalid-class F1 29.45%), while retrieving 3 valid and 3 invalid labelled links into the prompt (TVR, arXiv 2504.15427) raised invalid-F1 to 94.06%, and its errors did not overlap with a plain retrieval classifier's; of 6.7 million distinct links in commit messages 70% no longer resolved (arXiv 2305.16591), but only 8% of github.com links, and reachability is not validity. N-SURVEY-20260929-04: Jev had the highest contradiction recall of ten models on a three-way entail, contradict or not-mentioned task (77.27%), at one sixth to one four-hundredth of the others' cost. N-SURVEY-20260929-02: one fitted temperature transfers, isotonic does not, and a threshold's error on a split it was not fitted on is worse than on the fit split. Limits that make our test necessary: TVR is one industrial project, leave-one-out, not public, binary outputs, no cost or calibration; ContractNLI is legal text; nothing measures link validity after a change on engineering repositories. The register holds no belief on link maintenance, so this decides a design rather than a grade.

arms (same 300 links, same rendered state of the link after the change: the requirement or design text as now written, the PR title and description, and the changed files' diff stat at the check time; thresholds and one temperature fit on the fit fold only):
- A (baseline, no model): source-change invalidation: flag every link whose requirement, design section or PR code changed after the link was written; never flags an unchanged link.
- B (reported): Jev noul zero-shot, the question and criteria fixed in `prompts/still_implements.json`; flag if P(still valid) < t_B.
- C (decision arm): B plus the 3 most similar valid and 3 most similar invalid labelled links from the neighbour pool (embedding similarity of the rendered pair, pinned embedder), placed in the state as labelled examples; flag if P(still valid) < t_C.
- D (reported): an LLM (the checker pinned in E-20260928-08-r2) with the same 3 plus 3 neighbours, TVR's prompt shape; verdict plus a verbalised confidence.
- E (reported): C, then D only where C's P(still valid) lies within 0.2 of t_C (cascade); cost per 1,000 checks reported.
- override: the card's kill says "no arm beats A"; this spec names C as the single decision arm to avoid a multiplicity correction across four model arms, because C is the arm the source evidence supports (TVR's gain came from the labelled neighbours) and Jev is the cheap decider. B, D and E are reported with intervals.

metric: invalid-link precision at recall 0.7 (primary): for each model arm, the threshold on the fit fold is the highest flag threshold whose invalid recall is at least 0.7, applied to the test fold; A's precision is the share of changed links that are truly invalid, at A's own recall (reported; A's recall on links that became invalid through a change is 1 by construction, and links invalid from the start among unchanged links count against it); invalid-class F1; false-flag rate on the 100 unchanged links; cost and p95 latency per 1,000 checks.

predeclared margin: positive needs precision(C) minus precision(A), each at its operating point on the test fold, at least 0.10 with the two-sided 95% interval excluding zero, and C's test-fold invalid recall at least 0.6 (a threshold fitted to 0.7 that collapses on test does not count).

sample size and power note: 300 links, 200 changed and 100 unchanged, 2-fold cross-fitting grouped by repository so each link is tested once with thresholds fitted on other repositories. If about 35% of changed links are truly invalid (TVR's 10% base rate is for unchanged links; a change raises it; the actual share is recorded at label freeze), about 70 invalid links in total. Precision at a fixed recall on a flagged set of about 80 to 100 links has SE about 0.05 per arm; the paired difference against A, which flags all 200 changed links, has SE about 0.05 to 0.06; a true 0.20 gain passes with probability about 0.95, a true 0.10 gain about 0.4. The harness runs `lv power` (repository-cluster resampling of the frozen labels, 1,000 draws, seed 20261123) before any model call and records it in `power.json`; the decision rule does not change with it.

kill criterion: negative if the upper 95% bound of precision(C) minus precision(A) is below 0.10 and no reported model arm (B, D) has a point estimate at least 0.10 above A. Invalid (rerun under a new spec revision, not a verdict): labeller kappa on still valid or no longer valid below 0.6; a neighbour drawn from a test-fold repository or from the evaluated link's own repository; thresholds or temperature fit on test-fold links; the rendered state differing between model arms; the Jev version or prompt differing from the pin; fewer than 40 invalid links in the frozen set.

what a pass unlocks: the link maintenance rule for the PDLC ontology (priority 3): whether a trace link is re-checked by a cheap model when either end changes, or simply flagged for review; the rule that rejected links are kept as labelled negatives because a check needs them; a measured invalid share among changed links in spec-driven repositories, which the pdlc-memory-layer draft does not have; the neighbour-retrieval design reused by E-20260928-07-r2's typed-field question.

cost (runs, tokens, people-days): labelling 300 links plus a neighbour pool of at least 150 links (at least 40 invalid) from disjoint repositories, two labellers, adjudicated, about 25 labeller-hours; link extraction from SpecMine histories (requirement, design and task references with their commit times) and change detection, 3 engineer-days; harness 2 engineer-days. Model tokens: embeddings for 450 pairs, about 0.3M; B: 300 x about 1.2k = 0.36M; C: 300 x about 4k = 1.2M; D: 300 x about 4.5k = 1.35M; E: at most 0.5M re-used from D's answers (E reads D's cached verdicts, no new calls); temperature and threshold fitting reuse cached answers; total about 3.2M in 3 shards, aggregate hard cap 4.5M. USD: LLM about 6 USD, Jev under 0.1 USD; aggregate cap 15 USD. Cost M.
