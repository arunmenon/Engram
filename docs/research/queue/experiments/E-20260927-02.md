claim: On our Spec-to-PR-review decisions, re-running the pinned hosted model at temperature 0 on the retained served briefing does not reproduce the recorded decision reliably: fewer than 95% of cases reach a unanimous final decision across 5 replays, while returning the recorded output from the receipt reproduces 100% of cases byte-identical. Retaining served artifacts is therefore sufficient to show what was served and what was decided, not to re-derive the decision.

arms:
- Arm A (hosted re-run): for each case, re-run the pinned hosted model on the pinned served briefing and the same tool surface at temperature 0, seed set where the provider supports one, 5 replays per case. Tool calls are answered from the recorded tool results in the receipt (not live), so only model nondeterminism is measured.
- Arm B (self-hosted, batch-invariant, secondary): the same 5 replays on a pinned open-weights model served self-hosted with batch-invariant kernels enabled. Run only if such an endpoint is available in the quarter; if not, recorded as not run, and the verdict rests on A and C. Arm B answers a different question (can re-derivation be offered at all on controlled serving) and never substitutes for A.
- Arm C (recorded output): return the recorded output from the receipt; check byte identity of briefing and output against the stored sha256 values and that the receipt carries output, model id and version, provider and sampling parameters.
- Held equal across A and B: case set, served briefing bytes, prompt template sha256, tool results, decision schema. The model that recorded the original decision is the arm A pin (same id, version and provider).

metric: primary: decision unanimity per case (DFAH DecDet with N = 5: 1 if all 5 replays give the same final decision as each other and as the recorded decision, else 0), averaged over cases, for arm A. Secondary: tool-signature unanimity (identical tool names and arguments across replays); agreement of the replay majority with the recorded decision; arm B unanimity; arm C fidelity (share of cases returned byte-identical with all required receipt fields). Final decision = the PR review verdict enum {approve, request_changes, comment_only} extracted by schema, not by a model.

predeclared margin: artifact_only if unanimity_A < 0.95 (3 or more non-unanimous cases of 50). rederive_supported if non-unanimous_A == 0 of 50 (one-sided 95% upper bound on the non-unanimity rate about 5.8%, B21) and fidelity_C == 1.0. Otherwise (1 or 2 non-unanimous cases) inconclusive. Arm C must reach fidelity 1.0 for any verdict; a C failure is a receipt defect reported to P0, not a result on B1.

sample size and power note: 50 cases, clustered by Spec (at least 15 Specs, no Spec contributing more than 5 cases). Unanimity over 5 replays is still an optimistic bound on true per-case agreement (the note flags 3 replays as small; this spec uses 5). Prior from N-SURVEY-20260927-01: frontier decision unanimity 64.0 to 94.0% on the two valid DFAH benchmarks (Tables 4 and 6; Table 5 is void). If our true non-unanimity rate is 6% or more, the chance of seeing 0 of 50 is at most about 5%, so a rederive_supported verdict is hard to reach by luck; if it is 10%, P(3 or more of 50) is about 88%, so artifact_only is well powered at that rate. The interval on unanimity_A is reported with a cluster bootstrap by Spec. This is a contract fixture, not a population estimate for all models.

kill criterion: the hypothesis (re-derivation is unreliable) is killed by rederive_supported. Stop before running (not a result) if fewer than 50 cases or 15 Specs exist, any case lacks a recorded output or tool results, any pin is missing, or the P0 harness cannot answer tool calls from the receipt.

## Execution packet

- **Harness:** harness not yet built: it must extend the P0 harness with `engram-p0 replay-decisions --manifest <path>/manifest.json --arms A,B,C --replays 5 --out <run_dir>` that (1) loads each case's served briefing and receipt, verifies sha256 values, and refuses to run on any mismatch; (2) for A and B, re-runs the pinned model with the pinned prompt template at temperature 0 (seed where supported), answering every tool call from the recorded tool results by matching tool name and arguments, and records an unmatched call as `tool_miss` (counts as a different signature, and the replay continues with an empty result); (3) extracts the final decision with the pinned schema parser; (4) for C, returns the recorded output and checks required receipt fields; (5) logs per replay: decision, tool signature hash, tokens, latency, provider response id; (6) aborts at the token cap.
