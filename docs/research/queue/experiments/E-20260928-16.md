claim: On engineering artifacts, a prescribed PDLC core type set that admits new types only through canonicalise-first then a task-score gate answers questions about team-specific artifacts (runbooks, feature flags, incidents) substantially better than keeping unmatched items as flagged generic entities (annotate mode), without hurting the core supersession, completeness and negation questions; ungated learned types multiply the type count without an accuracy gain. Sources: N-SURVEY-20260928-20 (Graphiti and Cognee both expose prescribed, annotate or strict, and learned types; neither publishes a number on the choice; vendor docs); N-SURVEY-20260928-25 (EDC canonicalisation keeps 200 relation types at 0.956 precision where CESI keeps 280 at 0.724 on WebNLG, human evaluation; removing the schema retriever lowers WebNLG F1 from 0.794 to 0.752; open-domain relations, no admission gate ablated); N-20260928-07 (EvoOntology: removing the paired-evaluation acceptance gate costs 11.2 trajectory-wise points on DDR-Bench, data agents, no seeds reported); N-SURVEY-20260928-26 (synthesis). The card grades this paper-ablated; the ablations are on adjacent tasks (open-domain relation canonicalisation, data-agent ontology edits), none on engineering artifacts and none ablating type admission itself, so the evidence supports a testable question, not an expected effect size. The claim that no paper tests type admission on engineering artifacts is a novelty claim, hence review.

arms (same raw artifacts, same extractor model and base prompt, same H7 graph traversal and reader, same questions; arms differ only in the type-set policy at ingestion):
- A (strict): PDLC core types only (Requirement, Decision, Constraint, Ticket, PR and H7's edge types); items the extractor cannot place on a core type are dropped.
- B (annotate): core types; unmatched items kept as generic `Entity` with `ontology_valid = false` and their extracted text.
- C (learned, ungated): the extractor may create a new type for any unmatched item; every new type is kept.
- D (learned, gated): each proposed new type is first defined in one sentence, the 5 nearest existing types are retrieved by embedding similarity, and a typed Choice (Jev, pinned) decides `same_as(k)` or `new`; a `new` type is admitted only if H7 exact-answer accuracy on the validation split rises by at least 2.0 points with it versus without it (EvoOntology-style paired gate, same budget, same reader); at most 20 candidate types are evaluated, in order of frequency; rejected candidates are logged and not re-proposed.

metric: H7 exact-answer accuracy on the held-out split, per class (supersession, completeness, negation) and for the team-specific family (primary); number of node types after ingestion; share of items dropped (A) or left generic (B); extraction and gate cost in tokens; number of candidate types proposed, merged and admitted in D.

predeclared margin: (1) team-specific family, D minus B at least 10.0 points with the 95% repository-clustered interval excluding 0. (2) Core classes pooled, non-inferiority of B and of D against A: one-sided 95% lower bound of (arm minus A) above -5.0 points. (3) Strict preferred if A minus B on the core classes exceeds 3.0 points with the 95% interval excluding 0. (4) Ungated rejected if C ends with more than twice D's number of types and C minus D is below 2.0 points on both the core pool and the team-specific family.

sample size and power note: 360 questions from at least 6 repositories: 225 core (75 per class) and 135 team-specific; split by repository into validation (one third, used only by D's gate) and held-out (two thirds: about 150 core, 90 team-specific), so the gate never sees held-out questions. Team-specific, D vs B: A drops these items and B keeps them untyped, so the discordant rate may be large, about 0.25; SE = sqrt(0.25 / 90) x sqrt(1.5), about 6.5 points. P(pass) at a true 20-point gain = Phi(20 / 6.5 - 1.96) = Phi(1.12), about 87%; at a true 10-point gain, about 34%. This design detects large effects only; the card's "within 2 points on every class" equivalence rule cannot be resolved at this size and is replaced by margins (1) and (2) (override: a 2-point equivalence per class would need several thousand questions). Core pooled, about 150 held-out questions, discordance about 0.08: SE about 2.8 points; at a true difference of 0, non-inferiority at -5 points is shown about 56% of the time, and failure to show it reads as inconclusive, not as harm. The gate's 2-point rule on a validation split of about 120 questions is noisy (SE about 2.5 points); that noise is part of what arm D measures and is reported as the admitted-versus-rejected ratio.

kill criterion: gated admission is killed if margin (1) fails (D does not beat B by 10 points with the interval excluding 0). Ungated learning is killed if condition (4) holds. Annotate mode is killed in favour of strict if condition (3) holds. Invalid (rerun, not a verdict): fewer than 40 team-specific artifacts ingested, gold answer not derivable from the raw artifacts for more than 5% of questions, D's gate evaluated on held-out questions, or the token cap hit.

what a pass unlocks: the ADR-0011 amendment choosing closed, annotate or gated-open for the PDLC ontology (priority 3); the type-admission path the synthesis (N-SURVEY-20260928-26) left open; a proposed new belief on gated type admission for engineering artifacts (the register holds none, so this creates a grade rather than moving one); input to E-20260928-15 (bind-time typing) and PC-SURVEY-20260928-11 (thesaurus), which decide where types come from, not whether the set may grow.

cost (runs, tokens, people-days): estimate, pending pins. Four ingestion runs over about 360 raw artifacts at about 2k tokens: about 2.9M tokens; canonicalisation Choices about 0.3M; gate evaluations up to 20 candidates x about 120 validation questions x about 4k tokens, about 9.6M; final evaluation 4 arms x 360 x about 4k, about 5.8M; exact-answer scoring is deterministic. Depends on H7's seeded history and harness (Track B, weeks 3 to 4); starts after H7's harness is frozen.
