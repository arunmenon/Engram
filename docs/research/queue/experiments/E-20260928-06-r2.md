claim: On our own write-gate decisions, hosted Jev's answer follows the option name more than the rubric bound to it, and neutral option names remove that excess sensitivity without losing quality. Specifically, on H5's 90 labelled extracted items, for each of two templates (Noul `quote_supports_item`, Choice `source_type`): (1) reassigning which natural option name is bound to which rubric, with question, state and rubric text byte-identical, raises Jev's rubric-mapped flip rate above its test-retest floor by more than 10 pp (excess sensitivity, confidence-bound rule below); (2) under the identical reassignments, random-string names (primary neutral set) show excess sensitivity below 10 pp and at least 10 pp less than natural names; (3) random-string names keep per-template F1 against gold labels non-inferior to aligned natural names within H5's noise floor. Source: arXiv 2609.26758 (N-SURVEY-20260928-10): on Laya, yes/no names flipped 76.92% of answers versus 6.50% (0/1) and 6.00% (A/B); for hosted Jev the swap flip rate was 32.50% with a 30.4 pp excess (section 4.5) and AUC fell from .8146 to .5806; random-string names returned all models to the neutral regime; on Laya with 3 to 16 options even neutral letters changed 52.4% of decisions. Transfer to memory decisions with long domain-specific rubrics is untested; that is the question.

arms:
- Factorial design per template: name set x binding x option position x run.
- Name sets (same rubrics in all): N (natural: yes/no for Noul; `user-stated`, `tool-result`, `inferred`, `imported` for Choice); R (random 6-character strings, generated once, recorded in the template file, primary neutral set); L (letters A/B and A/B/C/D, secondary neutral set, reported, not decisive).
- Bindings: aligned (name j bound to rubric j; for N this is the current H5 design) and reassigned. Noul: one reassignment (the name in slot 1 bound to the "does not support" rubric). Choice: the three cyclic shifts s = 1, 2, 3 (name j bound to rubric (j + s) mod 4), which with the aligned binding form a Latin square, so every name is bound to every rubric exactly once. The same permutations are applied to N, R and L.
- Option position: each variant is rendered in two presentation orders of the rubrics (canonical and reversed), so name, binding and slot position are counterbalanced.
- Runs: every aligned cell is run twice (run 1 is the reference, run 2 gives the test-retest floor); reassigned cells run once. Expected answers are re-mapped through the rubric, so a model that reads only the rubric scores identically in every cell.
- Baseline arm: N-aligned, run 1 (current H5 wording), both orders.
- Models: hosted Jev (version pinned at freeze), decisive. Laya-0.4B, self-hosted, secondary read-out comparison (priority 2), included only if its licence is confirmed from a model-card file frozen with its sha256 (the Apache 2.0 claim is not verified in the staged sources); decider-0.8b substitutes only under the same licence check; if neither passes, the run is Jev only.
- Score `strength` is out of scope: override: the card includes it, but a Score decision has no option names to swap; its scale anchors are a different question and are not tested here.

metric:
- flip(i, cell) = share of item i's decisions in a cell whose rubric id differs from the same item, order and name set in aligned run 1 (for Choice, averaged over the three shifts and two orders; for Noul, over two orders).
- floor(i, name set) = share of item i's aligned run 2 decisions whose rubric id differs from aligned run 1 (averaged over orders).
- Excess sensitivity E[set, t] = mean over items of flip(i, reassigned) minus floor(i), per model, template t and name set.
- Mitigation M[t] = E[N, t] minus E[R, t], paired by item under identical permutations.
- Quality, defined separately per template against separate gold columns frozen with the labels: Noul: binary F1 with positive class "supports" against `gold_quote_supports_item` (supports / does_not_support). Choice: macro-F1 over the four `source_type` classes against `gold_source_type`, computed over items that carry a Choice gold label (items whose gold is null, for example no-fit items, are excluded from Choice F1 but kept in flip rates; the count is reported); a class with zero gold support is excluded from the macro average and listed.
- Calibration (reported, not decisive): Noul: ECE of P(supports) in 10 equal-width bins; Choice: top-label ECE, 10 bins. 90 items is too few to estimate ECE tightly.
- Top-two option probability gap per decision; flips concentrated in small-gap items are reported separately.
- All intervals: cluster bootstrap over source documents (10,000 resamples, percentile), cluster count G reported next to every interval.

predeclared margin: Risk margin m_r = 0.10 (10 pp of excess sensitivity), fixed before the run. Rationale: about one third of the Jev source excess (30.4 pp), and large enough that a confidence-bound exclusion is attainable at n = 90 under clustering; the original 5/90 was a resolution floor, not a materiality margin. Neutral-name quality margin nf = H5's measured F1 noise floor; if H5 has not measured it at freeze, nf = 0.05 provisional, stated in the verdict. Decision rules use confidence bounds, not point estimates:
- risk_confirmed[t]: one-sided 97.5% lower bound of E[N, t] > m_r (Bonferroni across the two templates).
- risk_excluded[t]: one-sided 95% upper bound of E[N, t] < m_r (both templates required, an intersection-union test, so no adjustment).
- mitigates[t]: one-sided 97.5% lower bound of M[t] > m_r and one-sided 95% upper bound of E[R, t] < m_r (tested only after risk_confirmed[t], fixed sequence, so alpha is not spent twice).
- noninferior[t]: one-sided 95% lower bound of F1[R-aligned, t] minus F1[N-aligned run 1, t] > -nf.
- confirmatory: G >= 30 source documents in the frozen set; otherwise every verdict is downgraded to inconclusive and labelled exploratory.

sample size and power note: Calls: per item per model, Noul 3 name sets x (2 aligned runs + 1 reassigned) x 2 orders = 18; Choice 3 x (2 + 3 shifts) x 2 = 30; total 48. 48 x 90 = 4,320 calls per model; 8,640 with Laya. Power is computed with the Jev-specific source effect (30.4 pp excess at a 32.50% flip rate, so a planning floor of 32.50 minus 30.4 = 2.1 pp, rounded to 2%), not Laya's 76.92%. Per-item variance of the flip-minus-floor difference, treating the two indicators as independent: 0.325 x 0.675 + 0.02 x 0.98 = 0.239, SD 0.489; SE at n = 90 is 0.489 / sqrt(90) = 0.489 / 9.487 = 0.0515. Clustering by source document inflates SE by sqrt(DEFF), DEFF = 1 + (m - 1) x ICC, m the mean items per document. The observed clustering is not yet known (cluster count unavailable until the labels are frozen): G and m are computed from the frozen manifest before the first call and written into run_manifest.json; the realised DEFF is estimated from the bootstrap and reported. Planning assumption ICC = 0.5 (an assumption, not a source number), so G >= 30 (m <= 3) gives DEFF <= 2.
- risk_confirmed power for a true excess of 0.304 (alpha 0.025 one-sided), P = Phi((0.304 - 0.10) / SE - 1.96): DEFF 1: SE 0.0515, Phi(3.96 - 1.96) = Phi(2.00) = 0.98; DEFF 2: SE 0.0729, Phi(0.84) = 0.80; DEFF 3: SE 0.0893, Phi(0.33) = 0.63; DEFF 4: SE 0.103, Phi(0.02) = 0.51. So at DEFF 2 (the confirmatory limit) power is 0.80 for Noul. The source gives no Jev number for four-option Choice, so Choice power is not anchored and is not claimed.
- risk_excluded power if the true excess is 0 with a planning flip rate of 3% in both cells (assumption): per-item SD sqrt(2 x 0.03 x 0.97) = 0.241, SE 0.0254 at DEFF 1; P per template = Phi(0.10 / SE - 1.645): DEFF 1: Phi(2.29) = 0.99; DEFF 2 (SE 0.0360): Phi(1.14) = 0.87; DEFF 3 (SE 0.0440): Phi(0.63) = 0.73. Both templates must pass: about 0.76 at DEFF 2 if independent. Normal approximations are rough at small rates; the bootstrap governs.
- mitigates power for a true M of 0.304 and E[R] near 0: per-item variance about 0.239 + 0.058 = 0.297, SD 0.545, SE 0.0575 at DEFF 1: Phi(0.204 / 0.0575 - 1.96) = Phi(1.59) = 0.94; DEFF 2 (SE 0.0813): Phi(0.55) = 0.71.
- noninferior power at a true F1 difference of 0 with nf = 0.05, approximating the paired F1 difference by the discordance d between arms, SE about sqrt(d / 90): d = 0.05: SE 0.0236, Phi(2.12 - 1.645) = Phi(0.48) = 0.68; d = 0.10: SE 0.0333, Phi(1.50 - 1.645) = Phi(-0.15) = 0.44. Non-inferiority is attainable only when the neutral and aligned arms disagree on few items; otherwise the verdict falls to inconclusive and the inconclusive action applies. This is stated in the verdict, not hidden.
- Resolution: zero excess flips in 90 independent items bounds the rate at about 3/90 = 3.3% one-sided 95% (B21); smaller effects are not claimable at this size.

kill criterion: If risk_excluded holds on both templates for Jev (upper bounds below 10 pp), naming is not a risk on our templates: stop, keep aligned natural names, H5 proceeds unchanged (negative). If risk is confirmed but neutral names fail mitigates or noninferior on any template, do not adopt neutral names: keep aligned natural names and forbid rubrics that refine or invert a name's meaning (inconclusive action). Any validity failure (byte inequality, payload-delivery mismatch, missing gold, budget cap reached) voids the run; no verdict.

what a pass unlocks: The template wording standard for every Jev and open-weight decision at the write gate (H5), the staleness audit (H10a) and the IMPLEMENTS link decision (E-20260928-08), fixed before those larger runs spend budget; a standing swap audit (Latin-square bindings, both orders) for new templates; a first read-out sensitivity comparison of Jev against a self-hosted model on our own decisions; evidence on B14 about whether Jev's typed-decision probabilities reflect rubric content.

cost (runs, tokens, people-days): 4,320 Jev calls plus 4,320 local Laya calls (8,640), with a hard call cap of 9,072 (5% for retries). Jev billed per call; the source paper's comparable robustness run cost well under USD 1 for 11,368 requests, so expected spend is a few US dollars (estimate).   ```
  T = ["noul_quote_supports_item", "choice_source_type"]

  if not valid_run: verdict = "void"            # byte check, payload check, gold, cap

    if any(risk_confirmed.values()):
        if all(noninferior[t] and ub95(E["R"][t]) < m_r for t in T) and \
