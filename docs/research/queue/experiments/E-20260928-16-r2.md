claim: On engineering artifacts from public repositories, a prescribed PDLC core type set that admits new types only through canonicalise-first then a task-score gate, with the admitted set learned on validation repositories and frozen before held-out ingestion, answers questions about team-specific artifacts (runbooks, feature flags, incidents) substantially better than annotate mode, in which unmatched items are kept as they are, with their extracted type label, flagged as outside the ontology; and it does so without hurting the core supersession, completeness and negation questions. Separately, the spec isolates what the acceptance gate adds over canonicalisation alone, and what canonicalisation adds over ungated learning. Sources: N-SURVEY-20260928-20 (Graphiti and Cognee expose prescribed, annotate or strict, and learned types; neither publishes a number on the choice; vendor docs); N-SURVEY-20260928-25 (EDC canonicalisation keeps 200 relation types at 0.956 precision where CESI keeps 280 at 0.724 on WebNLG, a human evaluation of extracted triplet reasonableness, not of admitted node types; removing the schema retriever lowers WebNLG F1 from 0.794 to 0.752); N-20260928-07 (EvoOntology: removing the paired-evaluation acceptance gate costs 11.2 trajectory-wise points on DDR-Bench, data agents, no seeds reported); N-SURVEY-20260928-26 (synthesis). No source tests type admission on engineering artifacts, which is a novelty claim, hence review.

arms (the same raw artifacts and one shared extraction pass by the pinned extractor, which proposes a type for every item; the same H7 graph traversal, reader and questions; arms differ only in the type-set policy applied to the extractor's output):
- A (strict): PDLC core types only (Requirement, Decision, Constraint, Ticket, PR and H7's edge types); items not placed on a core type are dropped.
- B (annotate, Cognee-faithful): core types; unmatched items kept as they are, with the extractor's proposed type label preserved and `ontology_valid = false` (Cognee's documented behaviour, "kept as-is, never rejected"; the E-20260928-16 variant that erased the label to a generic Entity is dropped).
- C (learned, ungated): on validation repositories, every proposed new type is admitted as proposed; the admitted set is then frozen.
- C2 (canonicalised, ungated): on validation repositories, each proposed new type is defined in one sentence, its 5 nearest existing types are retrieved by embedding similarity, and a typed Choice (Jev, pinned) decides `same_as(k)` or `new`; every `new` is admitted without a score test; the set is then frozen.
- D (canonicalised, gated): as C2, but a `new` type is admitted only if H7 exact-answer accuracy on the validation questions rises by at least 2.0 points with it versus the cached baseline without it; at most 10 candidates are evaluated, in order of frequency on validation repositories; rejected candidates are logged and not re-proposed; the set is then frozen.
- Held-out ingestion for C, C2 and D uses only its frozen set: a held-out item whose proposed type matches a frozen learned type (exactly for C; by the same `same_as(k)` Choice against the frozen set for C2 and D) takes that type; otherwise it is kept as in B. No type is learned from held-out repositories.

metric: H7 exact-answer accuracy on held-out questions, per core class (supersession, completeness, negation) and for the team-specific family (primary); number of node types after ingestion; share of items dropped (A) or kept unmatched (B and fallbacks); extraction, canonicalisation and gate tokens; candidates proposed, merged and admitted per learned arm.

predeclared margin: (1) team-specific, D minus B at least 10.0 points with the 95% interval excluding zero; (2) core pooled, non-inferiority of B and of D against A: one-sided 95% lower bound of (arm minus A) above minus 5.0 points; (3) strict preferred if A minus B on the core classes exceeds 3.0 points with the 95% interval excluding zero; (4) bounded negative for gated admission if the upper end of the 95% interval of (D minus B) on team-specific questions is below 10.0 points; (5) gate contribution: D minus C2 on team-specific questions, and canonicalisation contribution: C2 minus C, reported with intervals; ungated learning rejected if C ends with more than twice D's number of types and C minus D is below 2.0 points on both the core pool and the team-specific family.

sample size and power note: 15 public repositories, split by repository before any question is written: 5 validation (135 questions: 75 core, 60 team-specific; used only by D's gate) and 10 held-out (330 questions: 150 core, 180 team-specific). Inference uses the repository as the cluster: a cluster-level paired t interval with 9 degrees of freedom (t = 2.262 two-sided, 1.833 one-sided), which is more conservative than a bootstrap at 10 clusters. Team-specific, D versus B: discordance about 0.25, design effect about 1.5, SE = sqrt(0.25 / 180) x sqrt(1.5), about 4.6 points. P(pass) at a true 20-point gain = Phi(20 / 4.6 minus 2.262), about 0.98; at a true 10-point gain, about 0.47. At a true difference of 0, the bounded negative (upper bound below 10) is reached with probability about 0.47. Core pooled, 150 questions, discordance about 0.08, design effect about 1.3: SE about 2.6 points; at a true difference of 0, non-inferiority at minus 5 is shown about 54% of the time, and failure to show it reads as inconclusive, not as harm. The gate's 2-point rule on 135 validation questions is noisy (SE about 2.4 points); that noise is part of what D measures and is reported as the admitted-versus-rejected ratio.

kill criterion: gated admission is killed only on the bounded negative (4); a failed superiority test (1) without the bounded negative is inconclusive, not a kill. Ungated learning is killed if the rule in (5) holds. Annotate mode is killed in favour of strict if (3) holds. Invalid (rerun under a new spec revision, not a verdict): fewer than 8 team-specific artifacts in any held-out repository; gold answer not derivable from the raw artifacts for more than 5% of questions; any learned type or gate decision drawing on a held-out repository; any learned arm's frozen type set changing after held-out ingestion begins.

what a pass unlocks: the ADR-0011 amendment choosing closed, annotate or gated-open for the PDLC ontology (priority 3); the type-admission path the synthesis left open; a proposed new belief on gated type admission for engineering artifacts (the register holds none); input to E-20260928-15-r2 (bind-time typing) and E-20260928-17-r2 (thesaurus).
