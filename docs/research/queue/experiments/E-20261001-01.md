claim: On our own write-gate candidates, with the criteria text frozen and identical in every arm, restating the review as a batched list of separate typed questions answered by the existing write-gate model (B) recovers most of the quality and cost gain that Jev answering the identical question list (C) delivers over the current single-prompt review (A); the decision is whether C beats B by at least 3 F1 points on keep or skip, or matches it at no more than 70% of B's cost. Source: N-20260930-12 (Nowledge Mem, "Giving a Memory System Reflexes", builder-report, priority 1): with the same chat model (Kimi k3) on 40 candidates in one run, a question list with answers only raised overinterpretation F1 from 0.27 to 1.00 and long-term retention F1 from 0.83 to 1.00 at relative cost 1.00 against 1.10; the modelled monthly cost for a heavy user fell from 100 to about 37 with workflow changes and batching on the same model and to about 26 with Jev, "about 85% of the savings come from changes to the workflow"; measured savings per thread were roughly 10% to 19%; Jev's own accuracy is withheld at the vendor's request; candidate review through the decision model stayed in shadow and "Cost did not fall either". Limits that make our test necessary: n = 40, one run, criteria clarified while converting (so question shape and criteria are confounded in the source), vendor's own unreleased examples, personal and work notes rather than engineering artifacts, no Jev quality figure at all. The card's design warnings are adopted: criteria text frozen across arms, wrong rejects reported on their own, every rejecting arm offline only.

arms (same 240 candidates, same source material per candidate, same three questions and the same frozen criteria text `prompts/criteria.md`; for the already-saved question every arm sees the same 5 nearest committed memories, retrieved once and frozen):
- A0 (reported): the production write-gate review prompt exactly as deployed (pinned sha256), production model, unchanged criteria; measures how much the criteria rewrite alone moves quality.
- A (control): the production prompt shape (one holistic review returning keep or skip, an overinterpretation flag and a duplicate flag, with a reason, as the production format requires) with the frozen criteria text substituted for the production criteria; production model, temperature 0.
- B (question list, same model): the production model answers the three questions Q1 "worth keeping long term", Q2 "the source supports the item as written (not an overinterpretation)", Q3 "already saved among the 5 committed memories shown" in one call, answers only (true or false per question), no reasons; keep = Q1 true and Q2 true and Q3 false.
- C (decision arm): hosted Jev (pinned version), one noul per question with the identical question and criteria text, the three calls issued concurrently per candidate; keep = P(Q1) >= t1 and P(Q2) >= t2 and P(Q3) < t3, thresholds fitted on the fit fold (below); C at the fixed thresholds 0.5 is reported beside it.
- override: the card asks for "at least 200 candidates so that a zero-error cell bounds the rate near 1.5%". 240 candidates are used; a zero-error cell over 240 bounds the rate at about 1.25% (rule of three, B21), but wrong rejects are counted on true keeps only (about 120), whose zero-error bound is about 2.5%; this is stated rather than claimed as 1.5%.

metric: primary, keep-or-skip F1 (positive class = keep, gold from the adjudicated Q1, Q2, Q3 labels combined by the same keep rule); secondary, overinterpretation F1 (Q2 false as positive class) and duplicate F1 (Q3); wrong-reject rate = true keeps that the arm skipped / true keeps (reported on its own, per the card); cost per candidate in USD from the frozen price table (input and output tokens per arm, Jev billed per call); p50 and p95 latency per candidate with caching off; Jev repeat flip rate (every C call sent twice; share of candidates whose keep decision differs); the descriptive recovery ratio (F1_B minus F1_A) / (F1_C minus F1_A), reported only when the denominator's 95% interval excludes zero.

predeclared margin: model justified needs either (i) F1_C minus F1_B at least 0.03 with the two-sided 95% interval excluding zero, or (ii) cost_C at most 0.70 x cost_B with the one-sided 95% lower bound of F1_C minus F1_B above minus 0.02, and in both cases wrong-reject_C minus wrong-reject_B at most 0.02 (point estimate). Restructure only needs the upper 95% bound of F1_C minus F1_B below 0.03 and cost_C above 0.70 x cost_B.

sample size and power note: 240 candidates in about 60 to 80 source clusters (the source session or document a candidate was extracted from; clustering unit). Keep base rate expected 0.4 to 0.6. Paired keep-or-skip decisions between B and C are expected to disagree on 10% to 15% of candidates; with a design effect of about 1.3 the SE of the paired F1 difference is about 2.5 to 3 points, so a true 8-point gain passes rule (i) with probability about 0.8, a true 3-point gain about 0.15; rule (ii)'s non-inferiority at minus 2 points holds at a true difference of 0 with probability about 0.3. This is a pilot that can detect a large model effect and cannot certify equivalence; `wg power` (cluster-resampling simulation under these discordance assumptions, 1,000 draws, seed 20261026) runs before any model call and is recorded in `power.json`; the decision rule does not change with it.

kill criterion: restructure only (negative for the model) if the upper 95% bound of F1_C minus F1_B is below 0.03 and cost_C is above 0.70 x cost_B. Invalid (rerun under a new spec revision, not a verdict): the criteria text differing between A, B and C (sha256 mismatch); the committed-memory neighbours differing between arms for any candidate; labeller kappa on the keep rule below 0.6; a threshold fitted on a test-fold cluster; labels edited after any arm ran; any candidate missing from a decisive arm (A, B or C) without an explicit failed record.

what a pass unlocks: the priority 1 question at the write gate, answered on our data: whether the gate pays for a System One model or only for a better question shape on the model it already has; a measured wrong-reject rate per arm for B11 (working: admission is a separate decision that must be allowed to stay empty, and a wrong reject costs more than a wrong accept); a local reliability table for Jev's three gate questions for B14 (working: calibration claimed, not shown); a frozen question list that E-20260929-02-r2's fitted thresholds and E-20260926-03-r2's recalibration can reuse.

cost (runs, tokens, people-days): labelling 150 new candidates on three questions by two labellers blind to arm outputs, adjudicated, about 12 labeller-hours (H5's 90 items gain the Q3 label, about 3 hours); criteria text rewrite and freeze, 0.5 day; harness 2 engineer-days (reuses the write-path extraction and the committed-memory retriever). Model tokens: A0 and A, 240 x about 2.6k each = 1.25M; B, 240 x about 2.1k = 0.5M; C, 240 x 3 x about 800 x 2 calls = 1.15M; total about 2.9M in 3 shards, aggregate hard cap 4M. USD: production chat model about 6 USD at the frozen price table, Jev under 0.1 USD; aggregate cap 15 USD. Cost S.
