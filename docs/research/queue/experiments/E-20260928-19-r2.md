claim: Narrowed from the card to the reranking stage, and to selection from a frozen common pool. On investigation questions about a public engineering codebase, with every arm choosing from the same frozen pool of candidate passage windows under the same 12,000-token pack budget, genigrep's Jev file and passage scoring (engine at commit da10c5e, thresholds as recorded from its config at that commit, lexical guard on) puts more gold evidence spans into the pack than the same selection with keyword-only scores, and more than the lexical floor, while a self-hosted cross-encoder over the same pool is tested for non-inferiority to it. The keywords are written blind to the gold locations, so the result applies to non-oracle keyword retrieval; it says nothing about genigrep's own lead following, which is outside the frozen pool. Source: N-20260928-21 (genigrep at da10c5e and the OpenGeni evaluation doc): on 26 questions on one TypeScript monorepo, the agent with the tool was 6.6% cheaper [-11.5, -1.9] and 9.1% faster [-13.4, -4.6] in run 1, while run 2 intervals included zero; pass rate +1.9 points [-4.8, +8.7]; no effect on 24 bug-fix tasks; keyword-only ranking of the same pipeline "lost 7.7 points of answer quality"; question set, rubric and graders unpublished. override: the card's agent-level arms (40 questions x 2 runs plus 20 bug-fix tasks) need roughly 60M to 200M tokens, far beyond POLICY-v1.1's 12 runs a week for all research; this spec tests the precondition for any agent-level saving and is re-raised as an agent-level card only if it passes. The stop-wording hazard (B9) belongs with H8.

arms (same 80 questions, same blind keyword lists, same frozen candidate pool P per question, same 12,000-token pack budget, same packing rule (windows in score order until the budget is full, a window that would overflow is skipped); only the scores that order and filter P differ):
- A (lexical floor): P ordered by genigrep's IDF recall score, no reranking.
- B (Jev): genigrep's Jev file score then passage score over the files and windows in P, thresholds as recorded from genigrep's config at da10c5e (expected: file 0.6, passage 0.5, top-5 keyword guard, minimum 8 files; the harness aborts if the config differs), Jev version pinned; windows below threshold are dropped, the rest ordered by passage score.
- B-noguard (guard ablation, no extra calls): B's Jev scores with the top-5 keyword guard switched off; the only arm that tests B11's claim that a lexical guard keeps gold evidence.
- C (keyword-only): the same genigrep scoring and packing functions with Jev scores replaced by lexical scores (the source's ablation), recorded as a harness patch with its sha256.
- D (local cross-encoder): bge-reranker-v2-m3 (pinned revision) scoring every window in P against the question, ordered by score: the open-weight comparison (priority 2).

metric: gold-span recall per question (primary): gold spans are the adjudicated line ranges, with overlapping ranges and ranges in one file separated by 3 lines or fewer merged before scoring; a span counts as covered when at least 80% of its lines are inside packed windows; question recall = covered spans / gold spans, every span weighted equally; mean over questions. Secondary: line-weighted recall (covered gold lines / gold lines); full-coverage rate; pack tokens; Jev tokens, cost and latency per question; B's evidence rating against full coverage (reported).

predeclared margin: Jev adds value if mean(B minus C) is at least 5 points with the two-sided 95% interval excluding zero; Jev beats the floor if the 95% interval of (B minus A) excludes zero; the local reranker is preferred if the one-sided 95% lower bound of (D minus B) is above minus 3 points (the 3-point rule now decided with its interval).

sample size and power note: 80 questions spread across at least 8 top-level modules, at most 15 per module. Assuming a per-question SD of the paired recall difference of about 0.25, SE of the mean difference is about 0.028 (about 0.032 with a module-cluster design effect of 1.3), so a true 7.7-point advantage of B over C passes (point at least 5 and interval excluding zero) with probability about 0.72, a true 5-point advantage about 0.5. For D against B, at a true difference of 0, the one-sided bound clears minus 3 points with probability Phi(3 / 3.2 minus 1.645), about 0.24: a local-preferred outcome is only returned when the data support it, and a failure to show it does not count against D. Jev run-to-run variation is measured by re-scoring P for 20 questions.

kill criterion: negative if the upper end of the two-sided 95% interval of (B minus C) gold-span recall is below 5 points. A point estimate below 5 whose interval still reaches 5 is inconclusive. Invalid (rerun under a new spec revision, not a verdict): span agreement between annotators (span-level F1) below 0.6; keywords edited after any arm ran or written by a gold annotator; the repository commit or the pool manifest differing from the pin; genigrep's config at da10c5e differing from the recorded thresholds; the secret scan flagging more than 1% of files.

what a pass unlocks: the first independent measurement of Jev at the reranking stage for code evidence (priority 1), with an open-weight comparison (priority 2); a direct test of the lexical guard for B11 (working); an agent-level cost card sized from real pack statistics; 80 annotated code questions for the PDLC memory benchmark (priority 4).

cost (runs, tokens, people-days): question writing and gold-span annotation by two engineers, about 4 engineer-days; blind keyword writing by a third engineer, 1 day; harness 2 engineer-days. Model tokens with P capped at 200 windows per question (about 300 tokens per scored window with the question): B 80 x about 60k = 4.8M Jev tokens, plus 20 repeats x 60k = 1.2M; D 80 x 60k = 4.8M local cross-encoder tokens; A, B-noguard and C no model calls.
