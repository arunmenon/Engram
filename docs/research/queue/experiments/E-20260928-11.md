claim: On engineering-memory questions, answering from write-time extracted fact records loses at least 3 points of answer accuracy against answering from the retained source evidence at the same retriever, reader and judge, even though retrieval recall on the source id is unchanged; and the loss is not only a token-budget effect, because source evidence cut to the fact records' token count still beats the fact records by more than 1 point. Source: N-20260928-10 (Lore, commit 4976fa1), on LongMemEval-S (500 questions) one extracted fact sheet per session dropped answer accuracy from 94.2% to 87.8% at about one tenth of the reader tokens (about 2.8k vs 28k), while session recall@10 barely moved (98.69% vs 98.98%); the loss was steepest on questions about what the assistant said (73.2% vs 100%). That was one run, one unnamed extractor, chat data, and the headline source run used type-aware reader prompts with no matched fact-sheet run (a static prompt gave 93.8%). Whether it holds on long structured engineering artifacts is the question.

arms (same questions, same retriever, same reader, same judge, same single static reader prompt in every arm, which removes the note's prompt confound):
- A: index the retained source artifacts (design sections, tickets, PR descriptions, decision records), chunked by the harness's standard chunker; retrieve top k = 10 chunks with the Track B hybrid retriever (BM25 plus vector, RRF k = 60).
- B: index one extracted fact sheet per source artifact, produced by one pinned extractor model and one frozen extraction prompt for every artifact; each fact sheet inherits its source artifact id; artifacts the extractor refuses or fails on pass through unchanged and are tagged `extractor_fallback` (counted and reported). Retrieve top k = 10.
- A': the A index, with the served chunk list truncated per question to the largest prefix whose reader tokens do not exceed arm B's reader tokens for that question (matched-token control).
- Reported, not decided on: A at k = 5 (the note's cheaper no-extraction point).

metric: answer accuracy by the frozen judge (primary); reader-level evidence sufficiency (fraction of questions whose served text contains the gold answer span, judged by exact or normalised span match, with a frozen judge only for paraphrase); recall@10 on source artifact id; reader input tokens per question; accuracy by question family (decision-behind-design, changed requirement, PR-implements).

predeclared margin: A minus B at least 3.0 points with the 95% repository-clustered paired bootstrap interval excluding 0 (the card's margin). Matched-token test: A' minus B greater than 1.0 point (point estimate), else the loss is attributed to budget, not extraction.

sample size and power note: 300 questions from at least 8 repositories (minimum 6; with fewer than 8 clusters the interval is also reported with a wild cluster bootstrap and the verdict is labelled low-precision). Paired binary outcomes: if the discordant-pair rate is about 0.10 (the Lore result implies at least 32 of 500 net, so about 0.06 to 0.12 is plausible), the unclustered SE of the difference is sqrt((0.10 - 0.064^2) / 300) = sqrt(0.0959 / 300) = 0.0179, about 1.8 points; with a design effect of 1.5 the SE is about 2.2 points. At a true gap of 6.4 points, the probability that the lower bound excludes 0 is about Phi(6.4 / 2.2 - 1.96) = Phi(0.95), about 83%. At a true gap of exactly 3.0 points it is about Phi(1.36 - 1.96) = Phi(-0.60), about 27%, so a small true loss will usually read as inconclusive, not as a pass. The A' versus B comparison has the same precision; a 1.0-point rule on a point estimate with SE about 2 points is a weak discriminator and is reported with its interval.

kill criterion: A' minus B at or below 1.0 point at matched tokens (extraction is not the loss; withdraw the claim); or A minus B below 3.0 points or its interval including 0 (claim not supported on our artifacts). Invalid (rerun, not a verdict): extractor fallback on more than 10% of artifacts, or gold span absent from the source artifacts for more than 5% of questions.

what a pass unlocks: the write-path decision for ingestion (source evidence canonical, extraction a derived view with its own sufficiency score); a reader-level sufficiency metric in the PDLC memory benchmark (priority 4); a revision event on B16 (lead) extending "raw beats distilled" from skills to facts on engineering artifacts, and a second negative measurement for summarising consolidation under B5 (working); input to H3 and H9's summarisation mechanism, which answer adjacent but different questions (curation at read time; scheduled summaries).

cost (runs, tokens, people-days): extraction over the corpus of the seed repositories (order of a few thousand artifacts, a few million tokens, estimate); 300 questions x 4 reader runs, dominated by A at about 10 chunks per question; judge calls on 1,200 answers. Question writing and gold spans: 2 engineers x 4 days. Harness: 3 engineer-days on Track B's frozen retriever. Cost S to M (the card said S; question construction is the main cost).

## Execution packet

- harness: harness not yet built: it must (1) load the frozen PDLC-EXTRACT-300 corpus and questions; (2) build index A from source artifacts with the Track B retriever at its frozen configuration; (3) run the pinned extractor once per artifact with the frozen prompt, write fact sheets with inherited source ids and the `extractor_fallback` tag, and build index B with the same retriever configuration; (4) for each question, retrieve for A, B, A' and A at k = 5, render with one static reader prompt, and call the pinned reader at temperature 0; (5) score answers with the frozen judge, compute span sufficiency, recall@10 on source id and reader tokens; (6) write the output manifest. The extractor, reader and judge are three distinct pinned models; the judge never sees arm labels.
- dataset: PDLC-EXTRACT-300: 300 questions over the artifact histories of H7's seed repositories (at least 8 repositories, minimum 6), about 100 per family (decision-behind-design, changed requirement, PR-implements), each with a gold answer and a gold span located in a source artifact, written by two engineers who do not see extractor output; the second engineer verifies each gold span. Frozen before any extraction run as Parquet plus a manifest of per-artifact sha256, repository commit SHAs and per-question sha256; the questions are a candidate seed for the PDLC memory benchmark v1 and are not used to tune the extractor or retriever.
- baseline arm: A, source artifacts at top k = 10 with the frozen Track B hybrid retriever and the static reader prompt.
- metric definition and statistic: accuracy = judge-yes / 300 per arm; difference A minus B and A' minus B with a 95% paired bootstrap (10,000 resamples), clustering unit: repository; sufficiency = served text contains the gold span; recall@10 on source artifact id; mean and p95 reader tokens.
- budget: policy unset (policy.md status: unset; sized S to M above).
- kill rule (machine-checkable): `valid = fallback_rate <= 0.10 and gold_span_missing_rate <= 0.05`; `supported = (acc["A"] - acc["B"] >= 0.03) and ci_low(acc["A"] - acc["B"]) > 0`; `extraction_is_loss = (acc["A_prime"] - acc["B"]) > 0.01`; if not valid: verdict = "invalid"; elif supported and extraction_is_loss: verdict = "positive"; elif not extraction_is_loss: verdict = "negative"; else: verdict = "inconclusive".
- expected output manifest: `run_manifest.json` (repositories, commits, model pins for extractor, reader and judge, prompt sha256s, retriever config); `questions.parquet` and `questions.sha256`; `fact_sheets.jsonl` (source id, fact sheet, fallback flag); `retrievals.jsonl` (question, arm, served ids, tokens); `answers.jsonl` (question, arm, answer, judge label); `metrics.csv` (per arm and family: accuracy, sufficiency, recall@10, tokens, intervals); `verdict.json`; `receipts.sha256`.
