claim: On H10's seeded history, with the decision record held constant (same decision text, date, cited files, snapshot and cited-file diffs, same formatting), adding only the pre-change reason raises the "still true given the snapshot?" audit's stale-flag precision by at least 0.10 at recall >= 0.7 on held-out repositories, and a "not updated in more than two weeks" age flag scores below the reasonless record. This is the exploration slot: a cheap, directional test of an opinion-grade rule that no current belief covers.

arms:
- Arm A (age flag): flag any item not updated in more than 14 days (rvaniaaaa's daily compilation recipe).
- Arm B (record without reason): decision text, decided_at, cited files, rendered from a fixed template; audited with jevmem's noul ("Is memory X still true for this repository, given the snapshot?"; true = consistent or no evidence against it; false = the file, dependency or approach it names is gone or replaced).
- Arm C (record with reason): Arm B's exact rendering plus one line "reason: <reason text>" at a fixed position; nothing else changes. Same audit model, prompt, batch composition and order as B.
- Arm B0 (bare fact, secondary, descriptive only): the one-line fact form from r1, kept so the r1 comparison can still be reported; it is not used in any verdict.
- Arm D (source-change invalidation, H10a's required first control): flag an item when a file or dependency it cites changes.
- Snapshot for B, B0 and C: jevmem's recipe (tree to depth 3, selected package.json fields, first 3,000 characters of README) plus the diff of files cited by the item.
- Model-visible allowlist: B and B0 see only {rendered item, snapshot, cited-file diffs}; C additionally sees reason_text. Stale labels, reason-source metadata, labeller ids, last_updated and repository split are never in model-visible state; they live in `labels.jsonl` and `meta.jsonl`, which the audit process does not open.

metric: stale score s = 1 - P(still true), mean of 3 repeats. For B, B0 and C, the flag threshold is fitted on the fitting half and applied to the test half (algorithm below). Primary: test-half precision at the fitted threshold, valid only if test recall >= 0.7. Also: recall at the fitted threshold; audit tokens per item. Deterministic arms A and D: precision and recall of their fixed flags on the test half.

threshold algorithm: on the fitting half, sort items by s descending; the threshold tau is the largest value such that flagging every item with s >= tau gives fit-half recall >= 0.7 (ties at tau are all flagged). If no tau achieves recall 0.7 on the fitting half, the arm is infeasible. On the test half, flag every item with s >= tau. An arm's operating point is feasible on test only if test recall >= 0.7 and at least one item is flagged; otherwise its precision is undefined and any verdict that uses it is inconclusive.

predeclared margin: directional_pass requires feasible B and C, (prec_C - prec_B) >= 0.10 on the test half, and A either infeasible or prec_A < prec_B. Because this is exploratory and underpowered, a pass is directional only and cannot by itself make P5's reason field mandatory.

sample size and power note: target 100 stale and 100 still-valid decisions across at least 6 repositories; fit and test halves are split by repository, with at least 3 repositories and at least 40 stale and 40 valid items in each half. With about 40 stale test items, precision at recall 0.7 rests on about 28 true flags, so the SE of a paired precision difference is roughly 0.07; a 0.10 difference is not reliably detectable, so every result is labelled directional and negative results are exploratory defaults. Leakage control: reasons are harvested from artifacts dated before the change that made the item stale (ADRs, PR descriptions, commit messages, design notes), never written by the audit designer or anyone who knows which items later go stale; items with no pre-change reason are excluded from all arms.

kill criterion: reason_not_worth_it_default: B and C feasible and (prec_C - prec_B) < 0.05 (an exploratory default, not proof). source_change_default: C and D feasible and prec_D >= prec_C (an exploratory default that matches H10a's planned order, not proof that the audit is unnecessary). Stop before running (not a result) if fewer than 100 stale items with pre-change reasons exist, any support minimum per half is not met, the allowlist check fails, or any pin is missing.

what a pass unlocks: a confirmatory run and a candidate register belief on record representation; informs whether P5 makes `reason` mandatory on Decisions and Beliefs; gives H10a a representation arm.
