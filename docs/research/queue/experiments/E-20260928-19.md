claim: Narrowed from the card to the stage the R9 question is about. On investigation questions about a real engineering codebase, genigrep's Jev file and passage filtering (at commit da10c5e, lexical guard on, thresholds as pinned) puts more of the gold evidence into the same 12,000-token pack than the same pipeline with keyword-only ranking, and than a self-hosted cross-encoder reranking the same candidates. Source: N-20260928-21 (genigrep at da10c5e and the OpenGeni evaluation doc): on 26 questions on one TypeScript monorepo, the agent with the tool was 6.6% cheaper [-11.5, -1.9] and 9.1% faster [-13.4, -4.6] in run 1 (gpt-6-astra), while run 2 (gpt-6-sol) intervals included zero; pass rate +1.9 points [-4.8, +8.7]; no effect on 24 bug-fix tasks; keyword-only ranking of the same pipeline "lost 7.7 points of answer quality"; question set, rubric and graders unpublished; thresholds tuned on an internal DEV split whose overlap with the 26 questions is not stated. override: the card's agent-level arms (grep-and-read loop against genigrep, 40 questions x 2 runs plus 20 bug-fix tasks) are not testable within POLICY-v1: an agent answer on a large repository uses an estimated 0.3M to 1M tokens, so the card's design needs roughly 60M to 200M tokens, 30 to 100 runs at the 2M-token cap, against 12 runs a week for all research. This spec tests whether Jev's filtering is better evidence selection, which is the precondition for any agent-level saving, and is re-raised as an agent-level card only if it passes. The card's stop-wording hazard (B9) is an agent-behaviour question and belongs with H8.

arms (same 80 questions, same frozen keyword lists written by the question author before any arm runs (6 to 15 keywords each, since the source's evaluation used agent-chosen keywords), same ripgrep recall stage, same 12,000-token pack budget):
- A: plain lexical pack: ripgrep matches ordered by genigrep's IDF recall score, windows packed in score order to the budget, no reranking (what a grep-and-read loop sees first).
- B: genigrep at da10c5e with Jev filtering as pinned (file threshold 0.6, passage 0.5, lead following up to 6 at 0.5, top-5 keyword guard, minimum 8 files), Jev version pinned.
- C: the same genigrep pipeline with keyword-only ranking (the source's ablation; genigrep fails closed without Jev, so the harness calls the ranking and packing functions with Jev scores replaced by lexical scores, recorded as a harness patch with its sha256).
- D: the same candidates and windows reranked by a self-hosted cross-encoder (bge-reranker-v2-m3, pinned), packed to the budget: the open-weight comparison (priority 2).

metric: gold-span recall per question (fraction of annotated gold line ranges covered by the pack; primary); full-coverage rate (questions whose pack covers every gold span); pack tokens; Jev tokens, cost and latency per question; B's evidence rating against full coverage (reported, to show whether the rating predicts coverage, the B9 hazard at the pack level).

predeclared margin: B's mean gold-span recall exceeds C's by at least 5 points with the paired 95% interval excluding zero (Jev filtering adds value over keyword ranking, the source's 7.7-point ablation direction); B versus A and B versus D reported with intervals; D preferred over B for later work if D is within 3 points of B.

sample size and power note: 80 questions, each with gold spans annotated by two engineers before any arm runs. Assuming a per-question SD of the paired recall difference of about 0.25, the SE of the mean difference is about 0.028 and the 95% half-width about 5.5 points, so a true 7.7-point advantage passes the rule (point at least 5 and interval excluding zero) with probability about 0.78; a true 5-point advantage about 0.5. Questions about the same subsystem are correlated, so the interval is cluster-bootstrapped by top-level module. Jev's run-to-run variation is measured by re-running B on 20 questions.

kill criterion: the upper end of the paired 95% interval of (B minus C) gold-span recall is below 5 points, so the data rule out the margin: Jev filtering adds nothing worth its call at the reranking stage on this repository; no agent-level test is raised. A point estimate below 5 points whose interval still reaches 5 is inconclusive, not a pass. Invalid (rerun under a new spec revision, not a verdict): gold-span agreement between annotators (span-level F1) below 0.6, keywords edited after any arm ran, or the repository commit differing from the pin.

what a pass unlocks: the first independent measurement of Jev at the reranking stage for code evidence (priority 1), with an open-weight comparison (priority 2); B11 (working) gets a direct check of whether the lexical guard keeps gold evidence; an agent-level cost card sized from real pack statistics; 80 annotated code questions for the PDLC memory benchmark (priority 4).

cost (runs, tokens, people-days): question writing and gold-span annotation by two engineers, about 4 engineer-days; executor: B on 80 questions plus 20 repeats, about 14M Jev tokens by the source's cost figure, 7 runs, under 15 USD (Jev at about 0.006 USD per question); A, C, D local; harness 2 engineer-days.
