claim: This is a pilot. On long-horizon terminal and coding tasks at a fixed 16K compaction threshold, deterministic verbatim truncation (CliffCompaction paper recipe, pinned by explicit flags) resolves no fewer tasks than LLM summarisation compaction within the card's 2-point tolerated loss, at no higher dollar cost per attempt; and a sliding window does not beat truncation by a clustered interval excluding zero. At 60 tasks the design can detect a large loss (about 10 points) and measure the paired variances needed to size a confirmatory study; it is not powered to show non-inferiority at 2 points, and the expected verdict when the arms are truly equal is inconclusive, which keeps the existing default.

arms (one frozen model, one frozen harness, threshold 16K tokens, same tasks, paired seeds):
- Arm A (baseline, existing default): harness-native LLM summarisation compaction at the 16K threshold, summariser model and summarisation prompt pinned (sha256); every summary text is retained as a receipt.
- Arm B: CliffCompaction proxy at commit b48d660ae3c1f6037094d6cfc6b5d9f5938a7957 configured to the paper recipe, not the repository defaults (the pinned README lists `--thought-max-chars` and `--thinking-max-chars` defaults as 0, unlimited, and keeps assistant text and thinking in full by default). Arm B sets `--thought-max-chars 300` and `--thinking-max-chars 300` explicitly and pins every other rule of the recipe by its flag and value in pins.json: tool results over 500 characters dropped, those up to 500 kept verbatim, tool calls reduced to signatures, system prompt and task kept, last K turn pairs kept (K declared), previous compactions discarded. Harness-native compaction is disabled in arm B so that only one compactor acts; this is a design choice made here to isolate the arm, not an adoption of the README's instruction.
- Arm C: sliding window (system prompt and task prefix plus the most recent turns that fit under the threshold), harness-native compaction disabled.
- In every arm the request body actually sent to the model is logged (sha256 plus bytes). For arm B a deterministic conformance check runs over every compacted request body and verifies each pinned rule (no retained tool result over 500 characters, no thought or thinking block over 300 characters, tool calls as signatures only, system prompt and task present, last K turn pairs intact, no prior compaction present). The same check runs on a 5-task smoke run before the pilot is scored; any violation stops the run.

metric: primary: task resolve rate (official Terminal-Bench 2.0 checker, mean over 3 attempts per task). Co-primary: dollar cost per attempt at a fixed, dated price list, cached and uncached input and output priced separately. Secondary: number of compactions per attempt; input and output tokens; wall-clock time; per-arm share of attempts that hit the turn cap; bytes that must be retained per attempt to replay what the model saw (arm A: summaries plus request bodies; arm B and C: rule pins plus ledger offsets, and request bodies as receipts). Pilot outputs used for sizing: per-task SD of the paired resolve difference (B minus A, C minus B) and per-task SD of log(cost_B / cost_A).

predeclared margin: the non-inferiority margin is 2 points, the loss the card's decision tolerates ("no more than 2 points below A"); it is not widened to fit the sample. truncation_default if ci95_low(resolve_B minus resolve_A) >= -0.02 and ci95_high(cost_B / cost_A) <= 1.0, and not (ci95_low(resolve_C minus resolve_B) > 0). summaries_kept if ci95_high(resolve_B minus resolve_A) < 0, or if (resolve_C minus resolve_B) > 0.03 with ci95_low(resolve_C minus resolve_B) > 0. Otherwise inconclusive, and the existing default (arm A) is kept. Replayability is not a tie-breaker: a retained summary is replayable as served evidence (B1); what truncation adds is deterministic regeneration from the ledger and the pinned rules without storing the compacted text, which is reported as the retained-bytes secondary and does not decide the verdict.

sample size and power note: 60 tasks x 3 attempts; the clustering unit is the task (attempts are averaged within task). The per-task SD of the paired resolve difference is not measured; E-20260928-03 assumed about 0.30 and this pilot measures it. Arithmetic at SD 0.30: SE = 0.30 / sqrt(60) = 0.30 / 7.746 = 0.0387; 95% half-width = 1.96 x 0.0387 = 0.0759.
- Power to show non-inferiority at the 2-point margin when the true difference is 0: P(Z >= (0.0759 - 0.02) / 0.0387) = P(Z >= 1.44) = about 7%. For reference, at a 10-point margin it would be P(Z >= -0.62) = about 73% (E-20260928-03 said about 70%), and at 5 points P(Z >= 0.67) = about 25%.
- Power to reach summaries_kept on harm (ci95_high(B minus A) < 0), by true loss: 10 points, P(Z < (0.10 - 0.0759) / 0.0387) = P(Z < 0.62) = about 73%; 5 points, P(Z < -0.67) = about 25%; 2 points, P(Z < -1.44) = about 7%.
- Tasks needed for a confirmatory 2-point test (one-sided alpha 0.025, power 80%, true difference 0): n = (1.960 + 0.842)^2 x SD^2 / 0.02^2 = 7.85 x SD^2 / 0.0004. At SD 0.30: 7.85 x 0.09 / 0.0004 = about 1,766 tasks; at SD 0.20: about 785; at SD 0.15: about 442. All exceed this 60-task subset, so the confirmatory study needs a larger task set (the P0 long-horizon set when it exists, or a second benchmark) and is out of scope this quarter; this pilot supplies its SD.
- Cost: no local paired cost data exists, so no cost power is claimed. With s the per-task SD of log(cost_B / cost_A) measured in the pilot and r the true ratio, tasks needed to show ci95_high(ratio) <= 1.0 are n = 7.85 x s^2 / (ln r)^2, and no n suffices if r >= 1.0. The only source figure points the other way: in N-20260928-01 Table 6 (Kimi K2.7, SWE-bench Verified, 16K), truncation cost $0.19 against $0.18 for summarisation (ratio about 1.06, aggregate, not paired, different benchmark). The cost condition is therefore expected to fail unless our harness differs from the source's.
- Source context: Table 6 differences between methods at 16K on SWE-bench Verified for Kimi K2.7 were within about 2.5 points (sliding window 72.80, CliffCompaction 71.33, summarisation 70.27), a size this pilot cannot resolve.

kill criterion: truncation-only compaction is killed as a default if resolve_B is below resolve_A with ci95_high < 0, or if the sliding window beats truncation by more than 3 points with ci95_low > 0. Abort mid-run (not a result) at any cap.

what a pass unlocks: the in-session compaction default for our engineering agents (truncation regenerable from the ledger, or summarisation retained as receipts); whether summaries are ever a read surface; the first in-house on/off number that bears on B5, in its in-session form.
