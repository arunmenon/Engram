claim: On our staleness checks ("which of these stored memories is still current as of the check time?"), when the answer depends on comparing dates or version numbers, Jev asked as one Choice with a "none of these is current" option rarely answers none when no memory is current, and either one Boolean question per memory with a fitted threshold, or the same Choice with a fitted threshold on the top option's probability, raises the correct-none rate by at least 30 points while losing no more than 3 points of correct picks when one memory is current. On text-only staleness checks the gap is expected to be small. This decides the question shape for every System One gate that must be able to return nothing.

Sources. N-SURVEY-20261001-05 (arXiv 2609.39496, hosted Jev, paired answer-present and answer-absent menus): on two-step arithmetic menus Jev picked the right answer when present 99% of the time but chose the explicit rejection option only 7% of the time when it was absent; wording did not matter ("None" 99/7, "Other" 99/9, "None of the above" 99/6); asked per candidate with Boolean verification, the same model rejected all wrong candidates on 99% of answer-absent cases; a threshold chosen on 20 development problems per task raised rejection to 79% at 97% answer-present accuracy; one operation 100/66 against two operations 98/4; time calculation and capacity rounding showed the gap (capacity rounding 18/20 against 2/20, pilot n = 20), while state tracking, set intersection, rule chains and scheduling were perfect both ways. Limits that make our test necessary: arithmetic and near-arithmetic menus, not memory decisions; non-numeric absence untested; hosted API only, exact version not stated; pilot families of 20 pairs. N-SURVEY-20261001-04 (arXiv 2609.37647, independent, 37 datasets): Jev Choice probabilities are well calibrated overall (pooled ECE 0.028 over 279,925 answers, per dataset 0.003 to 0.279) while binary probabilities need locally fitted thresholds (mean P(yes) 0.465 against observed 0.518; tuned thresholds lifted UNFAIR-ToS micro-F1 from 0.499 to 0.748), which is why arms B and C fit thresholds; general NLP tasks, not memory decisions. The card's claim matches both notes' numbers tables. E-20260926-06-r2 (merged from PC-20260927-03) compares per-candidate yes/no against one Choice for ranking when several candidates are relevant; it has no case where no candidate qualifies, so its arms cannot answer this. E-20261001-03-r2 changes the state (projection), not the question shape; arm D here borrows its projection so the two results can be read together.

arms (same 400 items, same memories, same check-time snapshot fields in the state, same question wording for "current", Jev version pinned; memory order randomised per item with seed 20261026 and identical across arms; neutral option names m1 to m5):
- A (control): one Choice over the item's memories plus the option "none of these is current", argmax decision.
- B (decision arm): one Noul per memory, "is this memory still current as of <check time>, given the snapshot?", the calls for an item issued concurrently; pick = the memory with the highest P(yes) if that P(yes) is at least t_B, otherwise none; t_B fitted on the development split.
- C (decision arm, no extra calls): A's option probabilities; none if A chose none or if the top non-none option's probability is below t_C, otherwise that option; t_C fitted on the development split.
- D (reported): A's question on the state projected by E-20261001-03-r2's frozen `stateproj` (relative ages, same-or-older version labels); run only if that module is frozen at a pinned commit before shard 1, otherwise not run and recorded.
- fitting: t_B and t_C on the grid 0 to 1 by 0.01, chosen on the development split to maximise the mean of correct-none rate and correct-pick rate subject to correct-pick at least the development-split correct-pick of A minus 0.03, ties to the lower threshold; one pooled threshold per arm over both strata decides, since a serving gate cannot see the construction stratum; thresholds fitted per predicate-routed stratum are reported beside it.
- strata: date/version (the item's currency is decided by comparing dates or version numbers in the memories against the snapshot) and text-only (decided by the content of the memories, for example a later decision that explicitly reverses an earlier one). The stratum is set by construction from the fixture's generation template, and an observable predicate (the question template is a date or version comparison and at least two memories carry differing non-null timestamp or version fields) is frozen and its agreement with the construction label reported; the decisive comparison uses the construction stratum, and the predicate-routed result is reported beside it.

metric: correct-none rate = none-current twins answered none / none-current twins; correct-pick rate = one-current twins answered with the current memory / one-current twins; both per stratum and arm on the test split with Wilson 95% intervals; paired differences per stratum (X minus A) with a cluster bootstrap over source artifacts (the project area or document a base item's memories come from); wrong-pick rate on none-current twins (a stale memory chosen as current, the error that makes an agent act on an outdated note); calls, input tokens and USD per item; p50 and p95 latency per item (B's concurrent calls counted as wall-clock); Jev reliability table for A and B in bins 0 to 0.5, 0.5 to 0.7, 0.7 to 0.9, 0.9 to 1.

predeclared margin: positive for arm X in {B, C} needs, on the date/version stratum of the test split, correct-none(X) minus correct-none(A) at least 0.30 with the 97.5% interval (Bonferroni over the two decision arms) lower bound above 0.15, and correct-pick(X) minus correct-pick(A) at least minus 0.03 (point estimate; a screen, with its one-sided 95% lower bound reported). If both pass, C is preferred unless correct-none(B) minus correct-none(C) is at least 0.10. Negative needs correct-none(B) minus correct-none(A) below 0.10 on the date/version stratum (the card's kill).

sample size and power note: 200 base items, 100 per stratum, each in two twins (400 items); development split 20% of base items (40, grouped by source artifact, seed 20261026, balanced on stratum), test split 160 base items (80 per stratum, so 80 none-current and 80 one-current test twins per stratum). Clustering unit: source artifact, about 50 to 70. If the true correct-none rates on the date/version stratum are about 0.10 for A and 0.70 for B or C, paired discordance is about 0.6 and the clustered SE of the difference is about 0.09, so the 97.5% lower bound clears 0.15 with probability above 0.95; at a true 30-point gain the probability is about 0.6. The correct-pick screen (discordance about 0.06, SE about 0.03) detects a large loss, not a 3-point one, and is labelled a screen. `nc power` (cluster-resampling simulation under these assumptions, 1,000 draws, seed 20261026) runs before any model call and is recorded in `power.json`; the rule does not change with it.

kill criterion: negative if correct-none(B) minus correct-none(A) on the date/version stratum of the test split is below 0.10 (point estimate): keep the single Choice call. Invalid (rerun under a new spec revision, not a verdict): a twin pair whose memories differ in anything other than the removed current memory; a none-current twin in which any remaining memory is current according to the snapshot (checked by the labellers); labeller kappa below 0.6 on the gold answer; question text, memory order or snapshot fields differing between arms; a threshold fitted on a test-split cluster; labels edited after any arm ran; fewer than 70 test base items in either stratum; the Jev version differing from the pin; any item missing from A or B without an explicit failed record.

what a pass unlocks: the priority 1 question shape for System One gates at the staleness and recall stages that must be able to return nothing; for B11 (working: admission is a separate decision that must allow empty) a local measurement that a none option alone does or does not deliver empty admission on our data; for B14 (working: calibration claimed, not shown) whether a threshold fitted on 20% of our items transfers within the stratum, and a reliability table for Choice and Noul on our state; a frozen paired none-current set for the PDLC memory benchmark's stale-memory family (priority 4); with E-20261001-03-r2, a joint answer on whether to fix the input (projection) or the question (shape), or both.

cost (runs, tokens, people-days): building 200 base items from the PDLC-SEED-ASF history (H10's seeded Decisions and E-20261001-03-r2's staleness items reused where they fit, recorded) with paired twins, 2 engineer-days; gold answers and the none-current check by two labellers blind to arm outputs, adjudicated, about 14 labeller-hours; harness 1.5 engineer-days (reuses E-20261001-03-r2's state renderer where frozen).
