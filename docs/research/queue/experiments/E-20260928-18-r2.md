claim: This is a pilot at the card's 2-point margin. On a seeded PDLC history, with the node set, the candidate neighbours, the rendering and the retrieval held identical across arms so that only the link decisions differ, Jev deciding typed links at write time (as arXiv 2609.23986 describes: deterministic candidate neighbours, at most 10; timestamps and exact entity ids create edges directly; Jev confirms semantic, causal, same-episode and entity-alias edges and, on PDLC records, the trace links implements, verifies, refines, satisfies and blocks), with per-type thresholds refit on a labelled dev slice, is non-inferior to our current LLM linker deciding over the same candidates (one-sided 95% bound of the macro-F1 difference above minus 2 points), beats deterministic-only links, and costs no more than one fifth as much per 1,000 writes, without lowering PDLC answer accuracy by more than 3 points. All link metrics are conditional on the frozen candidate pool; the out-of-pool gold link rate is estimated and reported beside them. Source: N-CAT-18 (Jev-Mem, arXiv 2609.23986): LoCoMo overall 0.777 against 0.700 for MAGMA (same authors, same four relation views), build time 158 s against 1,044 s for Nemori, query latency 0.93 s against 1.47 s for MAGMA. Design warnings kept from the card and the note: one benchmark (LoCoMo), one answering model, an unstated judge, no ablations, single runs, different baselines for build speed and latency, text and table disagreeing in 4 places, fixed thresholds on scores the authors say are not calibrated (B14). Nothing in the source measures link accuracy.

arms (one frozen harness. Every arm reads the same frozen node set NODES-v1, produced once by the production extractor and hashed; the same frozen candidate manifest, at most 10 candidates per new node; the same node rendering; the same retrieval (Engram hybrid, RRF k = 60, then one-hop expansion along typed edges within the served-token budget of 4,000 tokens); the same answering model and prompt. Only the edge set differs):
- A-refit (decision arm): Jev scores every candidate pair for every applicable link type; per-type thresholds refit on the dev slice to maximise F1; raw scores logged; Jev version pinned; 3 scoring passes on PDLC (hosted Jev is not bit-reproducible, N-20260929-06), 1 on LoCoMo.
- A-paper (reported, replication only): the same Jev scores with the paper's fixed 0.60 threshold for every type; no extra calls.
- B (baseline): the production LLM linker (pinned model and prompt) run on NODES-v1 over the same candidate manifest, so it sees exactly the pairs A and C see; its extraction step is not re-run; 3 linking passes on PDLC, 1 on LoCoMo.
- C (deterministic floor): timestamps (temporal), exact entity ids (entity) and, on PDLC records, explicit references (a ticket key in a PR title, branch or body creates implements; a test file touching a PR's changed module creates verifies), no model; built twice to confirm byte-identical edge sets.
- N (edge-sensitivity control, answers only): the same retrieval with edge expansion switched off. If N answers within 1 point of B, answer differences cannot measure linking on this harness.
- override: the card's read-side ablation (controller on reads only, and on both) is not run: read-side routing and the stop rule are H8's question, and running both in one round bundles two changes. The neighbour-perturbation set is E-20260928-07-r2's and is not re-run; the implements rubric is shared with E-20260928-08-r2.

metric: per link type, precision, recall and F1 against adjudicated labels within the candidate pool, weighted by inverse inclusion probability of the stratified sample; macro-F1 over types per corpus (primary: PDLC macro-F1 including trace links, averaged over passes); trace-link precision (kill quantity); out-of-pool gold link rate from a separate random sample of non-candidate pairs (reported; every recall figure is labelled conditional on the pool); build cost in USD and seconds per 1,000 writes from billed usage; PDLC answer accuracy on the 120 frozen PDLC questions (judge from a model family different from Jev, the linker and the answering model, 20% human-checked subsample), 3 answering repetitions per arm; LoCoMo answers on a fixed random 100-question sample, 1 repetition, reported only.

predeclared margin: link non-inferiority margin 2.0 points of PDLC macro-F1 (the card's), tested as the one-sided 95% lower bound of (arm minus B); answer non-inferiority margin 3.0 points of PDLC answer accuracy, fixed now (replaces the post-hoc range of B's repetitions); A over C: the two-sided 95% interval of (A-refit minus C) PDLC macro-F1 excludes zero; cost: A's cost per 1,000 writes at most one fifth of B's (deterministic quantity, billed).

sample size and power note: labelled PDLC sample: 600 test pairs stratified by link type and by who proposed the pair (A only, B only, both, deterministic candidate no arm linked), with inclusion probabilities recorded; a 100-pair dev slice drawn from different source records and a different calendar month of the fixture than any test pair (so thresholds never see near-duplicates of test pairs); 100 random out-of-pool pairs for the out-of-pool rate. LoCoMo: 200 test and 100 dev pairs, reported only. Two labellers per pair, blind to arm; kappa per corpus. Power: at a paired discordance of about 0.15 over 600 pairs, SE = sqrt(0.15 / 600) = 1.58 points; with a design effect of about 1.3 for pairs sharing a write, SE is about 1.80. P(lower bound above minus 2 | true difference 0) = Phi(2 / 1.80 minus 1.645) = Phi(-0.53), about 0.30; at a true A advantage of 2 points, Phi(4 / 1.80 minus 1.645) = Phi(0.58), about 0.72. A 2-point bound powered at 80% under equality would need about 2,300 labelled pairs per corpus (about 130 labeller-hours); this run is therefore declared a pilot that can return a clear negative, a positive only when the bound clears, and a sized confirmatory run otherwise. Answers: 120 questions, 3 repetitions; repetitions estimate model variance, not generalisation; the interval is question-clustered. Trace-link precision rests on about 150 labelled trace pairs; zero false links in 150 bounds the rate near 2% (B21).

kill criterion: negative if the two-sided 95% interval of (A-refit minus C) trace-link precision lies wholly below zero, or that of (A-refit minus C) PDLC answer accuracy lies wholly below zero; a point estimate below C with an interval including zero is inconclusive, not negative. Invalid (rerun under a new spec revision, not a verdict): labeller kappa below 0.6 on either corpus; any threshold fitted on test pairs; dev and test pairs sharing a source record; NODES-v1 or the candidate manifest hash differing between arms; the served-token budget differing between arms.

what a pass unlocks: the first measurement of a System One model at the linking stage (priority 1), on PDLC trace links (priority 3), with locally fitted per-type thresholds for B14 (working); 900 labelled link pairs that seed the linking family of the PDLC memory benchmark (priority 4) and that E-20260929-03 reuses for the open-weight comparison.

cost (runs, tokens, people-days): labelling 1,100 pairs by two labellers, about 60 labeller-hours; 120 PDLC questions written and frozen, 2 engineer-days (shared with E-20260928-20-r2); harness 5 engineer-days. Model tokens, priced at the planning ceiling for the pinned hosted models (3 USD per million input tokens, 15 USD per million output tokens; Jev at 0.042 USD per million input tokens): node extraction once, 1.3M tokens, about 4 USD; A scoring, PDLC 3 passes x 0.8M plus LoCoMo 1.2M = 3.6M tokens, under 1 USD; B linking, PDLC 3 passes x 1.3M plus LoCoMo 2.0M input and about 0.5M output = 6.4M tokens, about 25 USD; answering, PDLC 120 x 4 arms x 3 repetitions plus LoCoMo 100 x 4 arms, about 1,840 answers x 4.5k = 8.3M tokens, about 28 USD; judging 1,840 x 1k = 1.8M tokens, about 6 USD. Total about 21.4M tokens and about 64 USD; 14 runs at no more than 1.5M tokens each; cap 80 USD. Cost L.
