claim: On a seeded PDLC history and on chat memory, Jev deciding typed links at write time, as arXiv 2609.23986 describes (deterministic candidate neighbours, at most 10; timestamps and exact entity ids create edges directly; Jev confirms semantic, causal, same-episode and entity-alias edges and, on PDLC records, the trace links implements, verifies, refines, satisfies and blocks), with per-type thresholds refit on a labelled dev slice, matches our current LLM extraction and linking on link F1 against human labels within 2 points, at no more than one fifth of its build cost, without lowering PDLC answer accuracy beyond the noise floor, and beats deterministic-only links. Source: N-CAT-18 (Jev-Mem, arXiv 2609.23986): LoCoMo overall 0.777 against 0.700 for MAGMA (same authors, same four relation views), build time 158 s against 1,044 s for Nemori, query latency 0.93 s against 1.47 s for MAGMA. Design warnings kept from the card and the note: one benchmark only (LoCoMo, despite "two benchmarks"), one answering model, an unstated judge, no ablations (so the linking controller's contribution is not isolated from the graph, the no-admission policy or the stop rule), single runs, different baselines for build speed and latency, text and table disagreeing in 4 places, and fixed thresholds on scores the authors say are not calibrated (B14). This spec isolates the write-time linking controller; nothing in the source measures link accuracy.

arms (one frozen harness; same corpus, same answering model, same retrieval (Engram hybrid, RRF k = 60) and the same served-token budget; only the linking step differs):
- A-refit (decision arm): the Jev write-time controller as above, per-type thresholds refit on a 100-pair labelled dev slice per corpus to maximise F1, raw scores logged, Jev version pinned.
- A-paper (reported, replication only): the same Jev scores with the paper's fixed 0.60 threshold for every type. A-refit and A-paper share one set of Jev calls; only the threshold differs.
- B: our current LLM extraction and linking (Engram production extractor, pinned model and prompt).
- C: deterministic links only: timestamps (temporal), exact entity ids (entity) and, on PDLC records, explicit references (a ticket key in a PR title, branch or body creates an implements candidate; a test file touching a PR's changed module creates a verifies candidate), no model.
- override: the card's read-side ablation (controller on reads only, and on both) is not run here: read-side routing and the stop rule are H8's question, and running both in one spec would bundle two changes into one round. The neighbour-perturbation set is E-20260928-07-r2's and is not re-run; the implements label rubric is shared with E-20260928-08-r2 rather than written twice.

metric: link precision, recall and F1 per link type against adjudicated labels, and macro-F1 over types per corpus (primary: PDLC macro-F1 including trace links); trace-link precision (kill quantity); build cost (USD and seconds) per 1,000 writes; answer accuracy on 120 PDLC questions (graded by a judge from a model family different from Jev, the extractor and the answering model, with a 20% human-checked subsample) and, for comparability with the source, on the 2 LoCoMo conversations' questions (reported, not decided on); 3 answering repetitions per arm on PDLC; B's run-to-run spread as the noise floor.

predeclared margin (the card's): A-refit is preferred for linking if its PDLC link macro-F1 is within 2 points of B's, its build cost per 1,000 writes is at most one fifth of B's, and its PDLC answer accuracy is not below B's by more than B's noise floor (max minus min of B's 3 repetitions, at least 1 point). Deterministic suffices if C meets the same F1 and answer conditions against B.

sample size and power note: labelled link sample: 300 candidate pairs per corpus (PDLC and LoCoMo), stratified by link type, drawn from the union of pairs any arm proposes plus deterministic candidate pairs no arm linked (so recall is measurable), each labelled per link type by two labellers blind to arm, with a separate 100-pair dev slice per corpus for A-refit's thresholds. Paired differences in per-pair correctness between arms at a discordance rate of about 0.15 give an SE of about sqrt(0.15 / 300) = 2.2 points, a 95% half-width of about 4.4 points, so a 2-point F1 margin is decided on the point estimate and screened by the interval: if the point estimate passes but the lower 95% bound of (A-refit minus B) is below minus 6 points, the result is inconclusive. Trace-link precision rests on about 100 labelled trace pairs; B21 sets the bound on false links (0 false links in 100 bounds the rate at about 3%). PDLC answers: 120 questions, 3 repetitions; repetitions estimate model variance, not generalisation; question-clustered intervals are reported.

kill criterion (the card's): A-refit's trace-link precision below C's, or A-refit's PDLC answer accuracy below C's (point estimates), gives a negative verdict. Invalid (rerun under a new spec revision, not a verdict): labeller kappa below 0.6 on either corpus, any threshold fitted on test pairs, or the served-token budget differing between arms.

what a pass unlocks: the first measurement anywhere of a System One model at the linking stage (priority 1, the stage the CTO's request WR-20260928-03 names), on PDLC trace links (priority 3, the ontology's links decided by a System One model as the priorities ask); locally fitted per-type thresholds for B14 (working); 600 labelled link pairs that seed the linking family of the PDLC memory benchmark (priority 4).

cost (runs, tokens, people-days): labelling 800 pairs (600 test, 200 dev) per type by two labellers, about 45 labeller-hours; writing and freezing 120 PDLC questions, 2 engineer-days. Executor: A builds (one Jev scoring pass on LoCoMo, about 1,200 writes, about 2.4M tokens, 2 runs; three passes on PDLC, about 400 writes each, about 0.8M tokens each, 2 runs), B builds (1 run), C no tokens; answering and judging: PDLC 120 questions x 4 arms x 3 repetitions and LoCoMo about 300 questions x 4 arms x 1, about 9M tokens, 6 runs. About 11 runs, under 120 USD. Harness 5 engineer-days. Cost L (as the card graded it), held under POLICY-v1 by the run split.
