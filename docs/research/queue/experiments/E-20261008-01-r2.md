claim: With the same pre-selected, content-audited memory items, the same question prompt and the same token cap, the reader-facing rendering of memory changes memory QA accuracy on our stack: our current typed briefing versus a natural-language rendering of the same items differ in a predeclared direction-agnostic screen for at least one of two readers from different model families. Source, narrowed: arXiv 2608.23568 (N-SURVEY-20261007-02) reports a 24.6 to 48.8 point spread across deployed-style templates, but its Section 4.3 states that comparison is "rather than a pure same-content ablation" (templates differ in content and prompt as well as format), and Section 4.2 attributes refusals to an artifact-and-prompt interaction. The source therefore motivates, but does not measure, an isolated rendering effect; this spec is the same-content test. The decision it serves is harness design: if rendering alone moves scores, H2, H3 and H8 must run on a frozen renderer.

arms:
- Common input: for each question, oracle evidence sessions are converted by a deterministic, gold-free extractor (`to_items.py`, pinned) into an ordered item list with fields subject, statement, date, provenance (session id, turn), qualifiers (negation, uncertainty, conflict marker). The answer field and any gold annotation are never passed to the converter or renderers. Items are then selected BEFORE rendering: the longest prefix of items whose rendering fits the cap in BOTH arms is kept, so both arms serve the same complete item set; no truncation happens after rendering.
- A (baseline): current Engram typed briefing renderer at the pinned harness commit, applied to the common item set.
- B: natural-language renderer: each item as one plain sentence carrying subject, statement, date, provenance and every qualifier in words, same order, no field labels or ledger syntax.
- Two readers, one Anthropic and one non-Anthropic, pinned by version string, temperature 0, max output 256 tokens. Identical question prompt.

semantic-preservation audit: before any reader call, `audit_packets.py` checks per item that every field value in the common item (statement tokens, date, provenance id, each qualifier) appears in both rendered packets; any item failing in either arm is dropped from both arms and counted. If more than 5% of items fail, the run stops as `invalid_render`.

metric: answer accuracy per item by a frozen judge from a third family, prompt frozen, judge blinded to arm (sees only question, gold answer and reader response; arm labels stripped, order shuffled with seed 7). Refusal ("not enough information" or equivalent, matched by a frozen rule list then judged) counts as incorrect for accuracy and is reported separately as refusal rate. Statistic: paired difference B minus A per reader, paired cluster bootstrap with question as cluster, 10,000 resamples, seed 7; Holm correction across the two readers (family-wise alpha 0.05). Judge noise is measured in-run, not borrowed: 100 randomly chosen (seed 7) responses are re-judged with the same judge and the disagreement rate is reported as this run's noise floor.

predeclared margin: this is a directional screen. Renderer effect is DETECTED if, for at least one reader, the Holm-adjusted 95% CI of B minus A excludes 0 and the point estimate is at least 5 points in absolute value. The spec does not claim the true effect is at least 5 points; the CI lower bound is reported as the supported magnitude. The decision rule (freeze renderer) needs only detection, since a detected effect of either sign means an unfrozen renderer confounds H2/H3.

sample size and power note: 250 paired items per reader. With about 20% discordant pairs, the 95% CI half-width on the difference is about 5.5 points (wider after Holm, about 6.3 at alpha 0.025); a true 10-point effect is detected with power about 0.75 to 0.8 per reader, a 5-point effect is not reliably detected. The run is a screen for a large effect. If the re-judge disagreement exceeds 3%, the result is reported as inconclusive.

kill criterion: effect absent: for both readers the Holm-adjusted CI of B minus A lies within [-5, +5] points. Then freeze A in P3 without a renderer arm.

what a pass unlocks: renderer frozen and versioned in P3's frozen evaluate(); served packets stored with every score (needed for P4 receipts and for the PDLC benchmark); a later spec on which format ships.

cost (runs, tokens, people-days): 1 run. Measured, not averaged: before launch, `estimate_cost.py` renders all 250 items in both arms and counts input tokens with each reader's tokenizer; the run launches only if measured input plus max output (256 per reader call, 64 per judge call) for 1,000 reader calls, 1,000 judge calls and 100 re-judge calls is under 1.8M tokens and 9 USD at pinned prices; otherwise the run stops at estimation with status `over_budget_estimate` and no model calls. Expected about 1.4M tokens. 1.5 people-days for converter, renderer and audit, 0.5 for analysis.

## Revision notes

Answers REV-20261008-01 (challenger, revise).

1. Attribution overstated "with evidence fixed": claim narrowed; the source's 24.6 to 48.8 spread is described as a template, content and prompt comparison (Section 4.3), refusals as an artifact-and-prompt interaction (Section 4.2); this spec is the genuine same-content test it motivates.
2. Arm B could drop provenance, qualifiers, or facts under truncation: common item schema now carries provenance and qualifiers into both arms; items are selected before rendering so both arms serve the same complete set; a per-item semantic-preservation audit drops failing items from both arms and invalidates the run above 5%.
3. Leakage and blinding: gold-free deterministic converter (answer and annotations never passed to converter or renderers), renderer-tuning questions excluded from the frame, judge blinded to arm with shuffled order.
4. Multiplicity, 5-point claim, borrowed noise floor: Holm across two readers; margin restated as a directional screen with the CI lower bound reported as supported magnitude; judge noise measured in-run on 100 re-judged responses and the borrowed N-SURVEY-20261007-01 figure removed from the rule.
5. Executable bundle: commands, lockfile, sampling frame, scorer, refusal rule, output caps, partial-run handling specified. override: the harness is not yet built and cannot be staged before acceptance; the packet states `harness not yet built:` with the exact interface.
6. Budget: output caps fixed (256 reader, 64 judge); PDLC removed from this run; a measured pre-launch cost estimate including judging and re-judging gates the launch, so a run that cannot finish under caps never starts. Cap raised to 1.8M tokens and 9 USD, still under the 10 USD review trigger.
7. Injection: the paper's Appendix C.1 judge prompt is not adopted; our judge prompt is our own frozen file.
