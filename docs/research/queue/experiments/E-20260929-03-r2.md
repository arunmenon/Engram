Cygnet and Jeff-Qwen3.5-2B are reported, not decided on. Secondary, merged from PC-20260929-08: local Laya served through Unsloth's Jev-compatible API on a CPU host, with thresholds refit on its `probabilities` output, keeps accepted-set accuracy at the automation threshold within 3 points of hosted Jev at matched coverage, at no more than 2x Jev's p50 latency, on items that fit its context window. Sources: N-20260929-09 (JevBench v1.5.0, third-party, vendor-benchmark grade): on 1,624 generic decisions run in evaluator-owned offline containers, Cygnet 73.7 and Winnow-12B Q8 73.2 lead hosted Jev 1.13 at 72.1 on the composite; Winnow-12B is above Jev outside the 95% interval (difference CI [0.28, 2.08]); Intelligence 74.4 (Winnow) and 71.1 (Cygnet) against 72.0 (Jev), Calibration 84.1 and 87.0 against 88.0. Limits that make our test necessary: generic decisions, no memory-stage task; the composite mixes accuracy with the evaluator's latency and cost; the Calibration metric is undefined in what the note read; hosted APIs saw sealed text; Cygnet versus Jev not separately reported. Winnow-12B is the primary arm because it is the only open model with a resolved gap above Jev on that board; naming one primary arm avoids a multiplicity correction. N-20260929-28 (Unsloth Decision API, docs plus code pinned at 6c20f0f, repo-pinned): Laya is served on `/v1/systemone` with Jev's request shape, so the swap is a base-URL change; the docs themselves say `confidence` uses a different formula (normalised entropy) and Jev thresholds do not transfer, choice labels past about 20 described options get trimmed, and states over the window are refused with HTTP 422; no accuracy, calibration or latency figures are published. N-SURVEY-20260929-02 (independent reproduction of laya-typed-decisions): Laya is under-confident (mean confidence 0.553 against accuracy 0.767), one fitted temperature (T = 0.469) generalised and isotonic did not, and a threshold fitted on a calibration split missed its error budget on test (9.2% to 14.0%).

L (per family, in-window items): laya_positive needs the one-sided 95% lower bound of (L minus J) accepted-set accuracy above minus 3 points, L's test coverage no more than 2 points below J's, L's p50 at most 2x J's p50, and a 422 rate at most 5%. sample size and power note: linking: 800 test pairs, discordance between two competent models about 0.12, design effect about 1.3 for pairs sharing a write: SE about 1.4 points; at a true difference of 0, non-inferiority at minus 3 is shown with probability about 0.69; at a true 3-point loss, a false pass has probability 0.05. Write gate: 300 turns, SE about 2.3 points; at a true difference of 0, about 0.37: a pilot that can reject a large gap. Accuracy here is a mean of per-item binary outcomes, so the paired-discordance approximation is appropriate; because items cluster by write and session with unequal sizes, the harness also runs `sys1 power` before any test call, a pre-registered simulation that resamples whole clusters from the frozen label sets with discordance drawn from a grid (0.08, 0.12, 0.16) and records pass probabilities (1,000 draws, seed 20261123) in `power.json`; the decision rule does not change with it. L: accepted-set accuracy is computed on an accepted subset of unknown size (about 50% to 80% of in-window items), so its SE is about 1.5 to 2 times W's; L's result is labelled a pilot, able to reject a large gap, and sizes a follow-up. ECE: with 800 predictions and 10 bins, the noise floor for a well-calibrated model is about 0.02 to 0.03.

kill criterion: W is dropped for linking if (W minus J) is below minus 5 points with the interval wholly below zero, or its ECE after refit exceeds 0.08; if W is dropped for linking, linking stays hosted this quarter. A point estimate below minus 5 whose interval reaches zero is inconclusive. L: laya_window_fail if its 422 rate exceeds 5% in a family; laya_negative if (L minus J) accepted-set accuracy is below minus 5 points with the interval wholly below zero. Invalid (rerun under a new spec revision, not a verdict): any model seeing a different rendered state than J for the same item (checked by per-item state sha256); thresholds or temperature fit on test items; WG-TURNS v1 or LINK-ASF-LOCOMO v2 labels not frozen by their own specs; a model file sha256, server commit or licence record missing; L called through an alias instead of the explicit checkpoint name.
