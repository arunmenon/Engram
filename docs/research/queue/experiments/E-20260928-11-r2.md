claim: On engineering-memory questions, when the reader is given the same parent artifacts and the same number of tokens, answering from write-time extracted fact sheets loses at least 3 points of answer accuracy against answering from the retained source text of those artifacts, with the same reader, reader prompt and judge. End to end (each representation retrieved by its own index at the same k), the loss is also reported, together with a test of whether retrieval recall on the gold parent artifact is equivalent between the two indexes. Source: N-20260928-10 (Lore, commit 4976fa1), on LongMemEval-S (500 questions) one extracted fact sheet per session dropped answer accuracy from 94.2% to 87.8% at about one tenth of the reader tokens (about 2.8k vs 28k), while session recall@10 barely moved (98.69% vs 98.98%); the loss was steepest on questions about what the assistant said (73.2% vs 100%). The source states that retrieval algorithm, reader and judging protocol were kept fixed across that comparison, and both headline arms used question-type-aware reader instructions; a static-prompt source run gave 93.8%, and no static-prompt fact-sheet run was published. That is one run, one unnamed extractor, chat data, and no matched-token control. Whether the loss holds on long structured engineering artifacts, and whether it is the extraction rather than the budget or the retrieval unit, is the question.

arms (same 300 questions, same reader model at temperature 0, one static reader prompt in every arm, same judge; the static prompt is a robustness choice for our run, not a correction of the source):
- Candidate set. For each question, P_q = the top 10 parent artifacts returned by the frozen Track B hybrid retriever (BM25 plus vector, RRF k = 60) over a parent-level source index, where a parent's score is its best chunk score. P_q is computed once and shared by the fixed-candidate arms, so parent coverage is identical by construction.
- FC-S (fixed candidates, source, matched tokens): for each parent in P_q, the source text of that parent cut to the token count of that parent's fact sheet: its chunks in retriever-score order, the last one cut at a sentence boundary. Token matching is per parent, so no arm is empty and the total matches FC-F per question.
- FC-F (fixed candidates, fact sheets): the fact sheet of each parent in P_q. Fact sheets come from one pinned extractor model with one frozen extraction prompt; artifacts the extractor refuses or fails on pass through as source text and are tagged `extractor_fallback` (counted, reported).
- FC-S-full (reported, not decided on): the full source text of P_q up to the reader's context cap; shows what the budget alone buys.
- E-S (end to end, source): top 10 parents from the parent-level source index, each served as its highest-scoring chunk up to 10 chunks in total (the card's arm A at parent level).
- E-F (end to end, fact sheets): top 10 fact sheets from a fact-sheet index built with the same retriever configuration (the card's arm B).

metric: answer accuracy by the frozen judge (primary); reader-level evidence sufficiency (served text contains the gold answer span, exact or normalised match, frozen judge only for paraphrase); recall@10 on the gold parent artifact id for E-S and E-F; reader input tokens per question and the per-question token ratio FC-S / FC-F; accuracy by question family (decision-behind-design, changed requirement, PR-implements).

predeclared margin: primary contrast D_fc = acc(FC-S) - acc(FC-F). Positive if D_fc >= 3.0 points and the 95% repository-clustered paired bootstrap interval excludes 0. Bounded negative if the one-sided 95% upper bound of D_fc (upper end of the 90% two-sided interval) is below 3.0 points. Otherwise inconclusive. Secondary: D_e2e = acc(E-S) - acc(E-F), reported with its 95% interval. Recall equivalence: recall@10(E-S) - recall@10(E-F) with its 90% clustered interval inside [-3.0, +3.0] points (two one-sided tests); if not equivalent, D_e2e is labelled confounded by retrieval and no end-to-end conclusion is drawn from it.

sample size and power note: 300 questions from at least 8 repositories (minimum 6; with fewer than 8 clusters the interval is also reported with a wild cluster bootstrap and the verdict labelled low-precision). Fixing the candidate set removes retrieval variance from D_fc; assume a discordant-pair rate of about 0.08 and a design effect of 1.5, giving SE(D_fc) = sqrt((0.08 - 0.04^2) / 300) x sqrt(1.5), about 2.0 points. Positive: at a true loss of 6.4 points (the source's), P(lower bound > 0) = Phi(6.4 / 2.0 - 1.96) = Phi(1.24), about 89%; at a true loss of 3.0 points, Phi(1.50 - 1.96) = Phi(-0.46), about 32%. Bounded negative: at a true loss of 0, P(D_fc_hat + 1.645 x 2.0 < 3.0) = P(D_fc_hat < -0.29) = Phi(-0.15), about 44%; the rest reads inconclusive. So this design will usually confirm a source-sized loss, and will establish the absence of a 3-point loss less than half the time; a null result is therefore most often inconclusive, which is declared, not a failure. Recall equivalence with a 3-point margin at recall near 0.95 is well powered (SE about 1 point).

kill criterion: the claim is withdrawn on a bounded negative (upper one-sided 95% bound of D_fc below 3.0 points). The run is invalid (rerun, not a verdict) if: extractor fallback on more than 10% of artifacts; gold span absent from the source artifacts for more than 5% of questions; median per-question token ratio FC-S / FC-F outside [0.9, 1.1] or more than 5% of questions outside [0.8, 1.25]; gold parent absent from P_q for more than 20% of questions (the fixed-candidate contrast would then be about the wrong evidence; both D_fc on all questions and on the gold-in-P_q subset are reported); or the token cap is hit.

what a pass unlocks: the write-path decision for ingestion (source evidence canonical, extraction a derived view with its own sufficiency score); a reader-level sufficiency metric in the PDLC memory benchmark (priority 4); a revision event on B16 (lead) extending "raw beats distilled" from skills to facts on engineering artifacts. B5 (scheduled summarising consolidation) is not moved by this run: write-time extraction is a different mechanism, so the result is filed as a related measurement only, and H9's summarisation arm remains the on/off test for B5. Input to H3 (read-time curation), which answers an adjacent question.

cost (runs, tokens, people-days): estimate, pending model pins. Corpus of the seed repositories about 3,000 artifacts at about 1,500 tokens: extraction about 6.0M input and 0.9M output tokens; embeddings for the two indexes about 5.4M tokens. Reader: about 31.5k input tokens per question over the five arms (FC-S 3.5k, FC-F 3.5k, FC-S-full 15.5k, E-S 5.5k, E-F 3.5k), about 9.5M in total, 0.15M output. Judge: 1,500 answers at about 0.8k, about 1.2M, plus paraphrase sufficiency calls about 0.2M. Total model tokens about 18M (excluding embeddings). Question writing and gold spans: 2 engineers x 4 days. Harness: 4 engineer-days on Track B's frozen retriever. Cost M.
