claim: For implements links from a requirement or design section to the pull requests that deliver it, ranking each requirement's candidate pool (merged PRs within 180 days) with a LambdaMART model over text similarity plus repository metadata (time proximity, file overlap with paths named in the requirement or design, diff size) and asking Jev only about the top 5 is non-inferior within 3 F1 points to asking Jev about every candidate, at no more than one fifth of the model calls; and the ranker alone is reported against both. Sources: N-SURVEY-20260929-06 (paper-ablated): LinkRank (arXiv 2607.23610), a LightGBM LambdaMART over 17 features on 3,103 issues and 7,688 commits in six large projects, reached average F1 73.17 against 48.39 for a GPT-OSS-120B agent (LinkAnchor) and 35.88 for SBERT plus GPT-4o rerank, in 19.6 against 421 minutes of test time; removing metadata caused the largest drop (PyTorch: all features 76.38, SBERT only 44.69, metadata only 38.73); a small supervised RoBERTa plus GraphCodeBERT model beat plain Gemini 2.5 Pro on requirement-to-code links (0.7155 against 0.5874, arXiv 2509.05585, with table inconsistencies). N-SURVEY-20260929-04: Jev had the highest contradiction recall of ten models on ContractNLI at a fraction of the cost, which is why Jev is the decider held constant here. Limits that make our test necessary: gold links in LinkRank are developer references the authors call inconsistent; issue-to-commit in large Apache and PyTorch projects, not requirement-to-PR in spec-driven repositories; the abstract and tables disagree (74.54 against 73.17); no paper puts a System One model behind a ranker. The register holds no belief on trace-link deciders, so this decides the linking stage's design rather than a grade.

arms (same test requirements, same candidate pools, same rendered (requirement, PR) pair for every model; per-arm decision threshold fit on the dev repositories, never on test):
- B (baseline): Jev noul "Does this pull request implement this requirement?" (true and false criteria fixed in `prompts/implements.json`) on every candidate in the pool; link if P(true) >= t_B.
- A (reported, no model): LambdaMART over BM25, TF-IDF cosine, embedding cosine (pinned local embedder), time proximity, file overlap with paths named in the requirement or design, diff size, and the other LinkRank metadata features that SpecMine records; link if normalised score >= t_A (LinkRank's absolute stop).
- C (decision arm): A's top 5, then the same Jev noul; link if P(true) >= t_C.
- D (reported): A's top 5, then a single-call LLM checker (the checker pinned in E-20260928-08-r2, same prompt); link on its verdict.
- E (reported, co-primary for the kill only): A's top 5, then Winnow-12B Q8 through the same request contract as E-20260929-03-r2's W arm; link if P(true) >= t_E.
- override: the card's pool of plus or minus 180 days is kept, capped at the 40 PRs nearest in time when larger, so that arm B stays inside the budget; the cap is applied identically to every arm and its effect is reported as the share of gold PRs outside the cap. The card's internal repository is dropped: POLICY-v1.1 names no dogfood tenant, so only public SpecMine repositories are used.

metric: link F1 on test requirements at each arm's dev-fit threshold (primary), micro-averaged over (requirement, PR) pairs; precision at recall 0.8 (threshold-free, reported); ranker top-5 recall = share of test requirements whose gold PRs are all within A's top 5 (the card's "top 5 missing the gold PR" is computed on requirements with at least one gold PR); model calls, USD and p95 latency per 1,000 requirements; share of gold PRs outside the 40-PR cap.

predeclared margin: positive needs the one-sided 95% lower bound of F1(C) minus F1(B) above minus 3 points, ranker top-5 recall at least 0.90, and C's model calls at most one fifth of B's (true by construction when the mean pool size exceeds 25; recorded, not assumed).

sample size and power note: 120 test requirements or design sections from at least 4 held-out repositories, about 1 to 3 gold PRs each, pools of up to 40 PRs. C's decisions are B's decisions restricted to A's top 5, so C and B differ only on gold PRs outside the top 5 and on B's false positives outside it; the paired F1 difference is therefore tightly correlated. At an expected discordance of about 0.06 over the roughly 250 pairs that either arm links, with clustering by requirement (design effect about 1.5), SE of the F1 difference is about 2 points; at a true difference of 0, non-inferiority at minus 3 is shown with probability about 0.6; at a true 6-point loss, the negative rule fires with probability about 0.75. F1 is a ratio, so the harness runs `lr power`, a cluster-resampling simulation over the dev labels (1,000 draws, seed 20261102), before any test call and records it in `power.json`; the decision rule does not change with it. Top-5 recall: 120 requirements give a Wilson interval of about plus or minus 5 points around 0.90.

kill criterion: negative if both C and E are more than 3 F1 points below B with each interval wholly below zero, or ranker top-5 recall is below 0.90 (point estimate; the card's "gold missing for more than 10% of requirements"). Invalid (rerun under a new spec revision, not a verdict): labeller kappa on implements below 0.6; any test repository used in ranker training or threshold fitting; the rendered pair differing between model arms; pools differing between arms; the Jev version or noul text differing from the pin; fewer than 100 test requirements with at least one gold PR.

what a pass unlocks: the linking design for the PDLC ontology's core trace link (priority 3): whether candidate implements links are ranked by cheap features we already hold in the event ledger before any model call, which decides whether keeping the graph current on every change is affordable; a candidate set of at most 5 per requirement on which E-20260928-08-r2's choice of decider (Jev, open model or LLM checker) is then applied; a labelled pool design reused by E-20260930-05 for link revalidation.

cost (runs, tokens, people-days): labelling: pooled candidates for 120 test and 30 dev requirements (union of every arm's top 10 plus every developer-referenced PR, about 12 per requirement, about 1,800 pairs), two labellers, about 25 labeller-hours; ranker training labels are developer-referenced links in the training repositories (silver, no labelling); harness and feature extraction 4 engineer-days. Model tokens: embeddings for requirements and PRs in all repositories, about 1.5M local; B: 150 requirements x 40 x about 900 = 5.4M is over plan, so B runs on the 120 test requirements and the 30 dev requirements at 30 candidates nearest in time for fitting only: test 120 x 40 x 900 = 4.3M plus dev 30 x 30 x 900 = 0.8M, 5.1M; C: reuses B's answers on the top 5 (no new calls; C is B restricted to A's top 5, which also guarantees identical answers); D: 150 x 5 x about 1.2k = 0.9M; E: 150 x 5 x 900 = 0.7M local; total about 8.2M in 7 shards, aggregate hard cap 8.5M. USD: Jev about 0.25 USD, LLM checker about 5 USD, one rented GPU for E about 1.5 hours at 4 USD; aggregate cap 20 USD.
