claim: On our Spec-to-PR-review decisions, re-running the pinned hosted model at temperature 0 on the retained served briefing, with every tool call answered from a frozen deterministic tool environment, does not reproduce the recorded decision and trajectory on every case, while returning the recorded output from the receipt reproduces every case byte-identical. Retaining served artifacts is therefore sufficient to show what was served and what was decided, not to re-derive the decision. The fixture can only support offering re-derivation when it has enough independent Specs to bound the non-reproduction rate at or below 5%.

arms:
- Arm A (hosted re-run): for each case, re-run the pinned hosted model on the pinned served briefing and the same tool surface at temperature 0, seed set where the provider supports one, 5 replays per case. Tool calls are answered by the frozen tool environment (see packet): responses are keyed by (tool name, canonical arguments, occurrence index of that key within the trajectory) and state-changing calls must occur in the recorded order. The first call that the environment cannot answer ends the replay with outcome `trajectory_divergence`; no empty or invented result is ever returned, so no decision is attributed to a missing tool answer.
- Arm B (self-hosted, batch-invariant, optional): the same 5 replays on a pinned open-weights model served self-hosted with batch-invariant kernels. Runs only if such an endpoint exists in the quarter; its pins are mandatory only if it runs. If not run it is recorded as not run with the reason. Arm B answers whether re-derivation can be offered at all on controlled serving; it never substitutes for A and never changes the verdict.
- Arm C (recorded output, baseline): return the recorded output from the receipt; check byte identity of briefing and output against stored sha256 values, check that the receipt carries output, model id and version, provider, sampling parameters and the serving-stack record, and check zero silent substitutions (any missing item is an explicit error).
- Held equal across A and B: case set, served briefing bytes, prompt template sha256, tool environment, decision schema. The arm A pin is the model that recorded the original decision (same id, version and provider).

metric: primary (per case, arm A): the case reproduces iff all 5 replays complete without `trajectory_divergence` and every replay's final decision equals the recorded decision. Non-reproduction is split into `decision_flip` (a completed replay with a different final decision, including a malformed decision) and `trajectory_divergence` (the model issued a call the recorded trajectory does not contain; since all inputs up to that call were byte-identical, the divergence is attributable to inference). Secondary: argument-aware tool-signature unanimity among completed replays (a new extension: DFAH's historical signature statistic ignores arguments, so the two are not compared numerically); majority agreement with the recorded decision; replay-level flip rate across all replays (the merged card PC-SURVEY-20260927-05's "decision flip rate"); arm B reproduction; arm C fidelity. Final decision = the PR review verdict enum {approve, request_changes, comment_only} extracted by the pinned schema parser, not by a model; a parse failure is the value `malformed`.

predeclared margin: primary unit = the predeclared primary case of each Spec (one per Spec, so units are independent at the Spec level); k = non-reproducing primary cases, n = primary cases. `nondeterminism_shown` if k >= 1. `rederive_supported` if k == 0 and n >= 60 (one-sided 95% Clopper-Pearson upper bound on the non-reproduction rate 1 - 0.05^(1/60) = 4.87%, at most 5%) and fidelity_C == 1.0. `no_flip_underpowered` if k == 0 and n < 60. The rate k/n and its Clopper-Pearson interval are reported in every case. Secondary cases are descriptive only (cluster bootstrap by Spec) and never change the verdict. Arm C must reach fidelity 1.0 for any verdict; a C failure is a receipt defect reported to P0, not a result on B1. No threshold depends on a hard-coded case count.

sample size and power note: the independent unit is the Spec. 60 primary cases are needed for a zero-failure bound at or below 5% (59 gives 4.95%, 50 gives 5.82%, so the previous 50-case design could not support its own 95% promise). If P0 has fewer than 60 Specs this quarter, the run is still worth doing: any k >= 1 settles the contract question (artifact_only) and needs no power; only the rederive branch needs 60. Prior: frontier decision unanimity 64.0 to 94.0% on DFAH's two valid benchmarks (realized coverage can be below 50 cases per benchmark; Table 6 lists 50 authored exceptions with Opus coverage 25 in the saved table); Qwen3-235B produced 80 distinct completions in 1,000 samples at temperature 0 (N-SURVEY-20260927-13). If our true per-case non-reproduction rate is 6%, P(k >= 1 in 60) is about 98%; at 2% it is about 70%.

kill criterion: the hypothesis (re-derivation is unreliable) is killed by `rederive_supported`. Stop before running (not a result) if the policy gate fails, any primary case lacks a recorded output or tool environment, any mandatory pin is missing, any sha256 mismatches, or the harness cannot answer tool calls by (name, canonical arguments, occurrence).

## Execution packet

- **Harness:** harness not yet built: it must extend the P0 harness with `engram-p0 replay-decisions --manifest <path>/manifest.json --arms A,C[,B] --replays 5 --budget <path>/budget.json --out <run_dir>` that (1) runs the policy gate first (policy.md status set, dataset in permitted_datasets, hosted-provider egress cleared, budget.json present) and refuses otherwise; (2) loads each case's served briefing, receipt and tool environment and verifies sha256 values; (3) for A and B, re-runs the pinned model with the pinned prompt template at temperature 0 (seed where supported), answering tool calls only from the frozen tool environment keyed by (tool name, canonical arguments, occurrence index) with state-changing calls enforced in recorded order, and ends the replay with `trajectory_divergence` at the first unanswerable call; (4) extracts the final decision with the pinned schema parser (`malformed` on failure); (5) for C, returns the recorded output and checks required receipt fields and zero silent substitutions; (6) logs per replay: outcome, decision, tool signature hash, divergence point, tokens, latency, provider response id, retries; (7) enforces token, dollar (tokens x pinned price list) and wall-clock caps and stops cleanly at the first cap.
- **Invalid-call, timeout and retry policy:** a provider error or timeout is retried with the identical request up to 3 times (retries logged, not counted as replays); after 3 failures the replay is `invalid`. A primary case with any invalid replay is replaced by that Spec's predeclared next case if one exists, else the Spec is dropped from n and listed. Invalid replays never count as reproductions or flips. A malformed decision counts as `decision_flip` and is also reported separately.
- **Pins (`pins.json`):** mandatory: hosted model id, version and provider; sampling parameters; seed-support flag; prompt template sha256; decision schema and parser sha256; tool-environment builder commit; harness git commit and container image digest; price list with date. Mandatory only if arm B runs: self-hosted model id and weights sha256, serving engine and version, batch-invariant flag, dtype, tensor parallelism, GPU type.
- **Dataset:** `datasets/replay-decisions-v2/`: `cases.jsonl` (case id, Spec id, primary flag, replacement order, repository, recorded decision, recorded output sha256), `briefings/`, `receipts/` (model id, provider, sampling parameters, serving-stack record where exposed), `toolenv/<case>.jsonl` (recorded tool calls and responses with occurrence index and state-change flag). Frozen by `manifest.json` (sha256 per file, Spec and case counts, primary-case list) before any replay.
- **Baseline arm:** Arm C, the recorded output returned from the receipt (the guarantee P0 already aims for). Arm A is judged against the reproduction rule, not against C.
- **Metric definition:** reproduces(case) = all 5 replays completed without divergence and all decisions equal the recorded decision; k = count of non-reproducing primary cases; rate = k/n with Clopper-Pearson two-sided 95% interval and one-sided 95% upper bound; secondary cases by cluster bootstrap over Specs (2,000 resamples, clustering unit: Spec); fidelity_C = share of cases byte-identical with all required receipt fields and no substitution.
- **Budget:** policy unset. Proposed caps for the desk (`budget.json`): arm A 11M tokens; arm B 11M tokens and 16 GPU-hours; 10 wall-clock hours; a dollar cap set by the desk from the pinned price list; hosted egress requires explicit clearance.
- **Kill rule (machine-checkable), first match wins:** `not_runnable = policy_gate_fails or any_primary_missing_output_or_toolenv or any_mandatory_pin_missing or (arm_B_run and any_B_pin_missing) or sha_mismatch`; `receipt_defect = fidelity_C < 1.0`; `nondeterminism_shown = k >= 1`; `rederive_supported = k == 0 and n >= 60`; `no_flip_underpowered = k == 0 and n < 60`. Arm B is reported beside the verdict and never changes it.
- **Expected output manifest:** `manifest.json`, `pins.json`, `budget.json`, `policy_gate.json`, `replays_A.jsonl`, `replays_B.jsonl` (or `arm_B_not_run.json` with the reason), `arm_C_fidelity.jsonl`, `invalid_and_retries.jsonl`, `usage.jsonl`, `metrics.json` (k, n, rate, bounds, split by decision_flip and trajectory_divergence, secondary descriptive rates, signature unanimity, fidelity, verdict), `ledger_entry.json`.
