claim: On TWIST Track B (161 human-validated items: 38 contradicting, 61 aligned, 62 hard-negative drafts), with the same retrieved top-k memories and the same per-memory question and true and false criteria for both model arms ("does this draft contradict memory item X?", criteria naming the acknowledged-pause and change-question cases as not contradictions), Jev answering that question per memory and flagging at a threshold fitted on other conversations reaches hard-negative specificity at least 0.10 higher than our default LLM checker answering the identical question per memory, while its contradiction-recall loss is bounded at 0.10 and grounded contradiction recall stays within 0.05; the claim is about the model under a matched rubric, and the whole configured flagger from the source is reported, not decided on. Source: N-20260930-03 (TWIST, arXiv 2609.28575, per-item outputs and frozen key public; paper-single-benchmark): flat RAG with GPT-4o reached CR 0.97 [.87, 1.0] but HNS 0.57 [.44, .68]; flat RAG with Claude 0.92 / 0.74 and Gemini 0.76 / 0.84; even gold evidence with GPT-4o flagged too much (HNS 0.42), so the judgement step, not retrieval, drives false flags for that backend; the author's deployed coherence system had HNS 0.98 but CR 0.42. Scoring is structural (verdict and evidence turn ids against a key), no LLM judge. Limits that make our test necessary: one track of four instantiated; 161 items, 38 contradicting; raw inter-annotator kappa 0.565 before adjudication dropped 39 items; single author who founded the deployed system tested; GPT-4o generated the items; LoCoMo chat memory, not engineering records; no System One model measured on it. N-SURVEY-20260929-04 adds that Jev had the highest contradiction recall of ten models on ContractNLI (77.27%) at a fraction of the others' cost.

arms (identical items, identical retrieved top-k from our retriever for every retrieved-evidence arm; flag = the item is declared a contradiction; evidence = the arm's top-3 memory turn ids):
- M (baseline, matched rubric, decision-relevant): our default LLM checker (model id pinned in `freeze.json`, the model we would otherwise deploy), one call per (draft, retrieved memory) with exactly the question and criteria in `prompts/contradicts.json`, answering true or false; flag if any memory is answered true; evidence = memories answered true, then retrieval order.
- B (decision arm): hosted Jev (pinned version), one noul per (draft, retrieved memory) with the same question and criteria; flag if max P(true) >= t; evidence = top-3 memories by P(true); t fitted per fold (below). B at the fixed threshold 0.5 is reported beside it, which matches M's decision rule exactly.
- S (strong source control, reported and used as a guard): TWIST's flat-RAG flagger prompt at the pinned commit with the strongest balanced backend in the source's Table 3 that we can pin (Claude, the 0.92 / 0.74 row; snapshot id pinned), over our top-k.
- A (reported anchor): TWIST's flat-RAG flagger with GPT-4o (pinned snapshot), over our top-k, as in E-20260930-02.
- C (reported): the same noul on laya-typed-decisions served locally through Unsloth's Jev-compatible API (same server commit and model revision as E-20260929-03-r2's L arm, pinned here independently), thresholded on `probabilities`, never `confidence`; items over its window counted as 422, not re-rendered.
- O-M, O-B (reported): M and B given the gold evidence turns instead of the retrieved top-k, to separate retrieval failure from judgement failure.
- override: the card fits t on 40 items and tests on 121. This spec uses 2-fold cross-fitting grouped by conversation (5 conversations per fold, assignment frozen with seed 20261019 and balanced on class counts), so every item is tested once with a threshold fitted on other conversations; the card's fixed split is reported beside it.
- override: the card's control is the source's flat-RAG GPT-4o flagger. It is kept as a reported anchor (A) but no longer decides, because the challenger showed it is the weakest reasonable backend and differs from B in rubric as well as model.

metric: on held-out predictions pooled over both folds: contradiction recall (CR); aligned specificity (AS); hard-negative specificity (HNS); grounded contradiction recall (GCR, a correct flag with at least one gold evidence turn in the arm's top-3); attribution accuracy (reported); cost and p50 latency per item; Jev repeat disagreement (every Jev call sent twice with canonical option order; share of items whose flag differs). Threshold rule for B and C, predeclared: on the fit fold, t is the grid value (0.05 to 0.95 by 0.05) maximising Youden's J = CR + specificity on aligned and hard-negative items pooled minus 1; ties go to the higher t.

predeclared margin: positive needs HNS(B) minus HNS(M) at least 0.10 with the conversation-level two-sided 95% interval excluding zero and the difference at least 0.05 in every leave-one-conversation-out replicate; the one-sided 95% upper bound of CR(M) minus CR(B) at most 0.10; GCR(B) at least GCR(M) minus 0.05 (point estimate); and HNS(B) at least HNS(S) (point estimate). A specificity pass whose recall bound exceeds 0.10 is `inconclusive_recall_unshown`, not positive.

sample size and power note: 62 hard negatives and 38 contradicting items across 10 conversations, all tested once. Items share conversations, so the conversation is the unit of uncertainty: the primary interval is a conversation-cluster bootstrap that, in each resample, redraws conversations, reassigns the two folds by the frozen balancing rule, refits t on cached probabilities and recomputes every rate, so the uncertainty covers the fitted decision rule, not only the test predictions; with 10 clusters a percentile bootstrap under-covers, so its half-width is inflated by sqrt(10 / 9) and the leave-one-conversation-out stability check is added. Before any model call, `twist power` simulates the full rule (conversation random effect with an intraclass correlation of 0.1, item discordance 0.3 on hard negatives and 0.1 on contradictions, fold assignment, threshold fitting on simulated probabilities, the decision rule above; 2,000 draws, seed 20261019) and records P(positive), P(negative) and P(inconclusive_recall_unshown) at true HNS gains of 0, 0.10, 0.20 and 0.30 in `power.json`. The unclustered approximation in E-20260930-02 (P(positive) about 0.8 at a true 0.20 gain) is withdrawn; the simulation replaces it and is expected to be lower, mainly because the recall bound on 38 items is hard to meet (SE of the CR difference about 0.06 to 0.07 when clustered, so the upper bound is at most 0.10 only when the observed loss is about zero or negative). This is a pilot; the recall bound is the part most likely to return `inconclusive_recall_unshown`, and that outcome sizes the PDLC confirmatory run.
