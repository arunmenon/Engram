claim: On multi-session software tasks where prior-session history fits the executor's context window, raw prior-session history in context is at least as good as every derived read surface H3 considers (session summary, Workflow node text, curated briefing from the top-3 raw episodes): no derived arm beats raw history on oracle pass rate with a sequence-clustered 95% interval excluding zero.

arms (same frozen executor, same tools, same task prompts; only the memory block differs):
- Arm 0 (stateless): no prior-session material.
- Arm 1 (session summary): Consumer 4 session summaries of the prior sessions.
- Arm 2 (Workflow text): Consumer 4 Workflow node text extracted from the prior sessions; if Consumer 4 produces no Workflow node for a sequence the block is empty and that is recorded.
- Arm 3 (curated briefing): H3's task-conditioned briefing synthesised from the top-3 raw episodes, with the same curator pin H3 uses.
- Arm 4 (raw history): verbatim prior-session transcripts (task, agent turns, tool results, final diff) in chronological order, up to the executor's window minus a fixed reserve for the current task; if they exceed it, truncated to the most recent material and flagged.
- Sessions 1 of each sequence have no prior history and are run once, shared by all arms; sessions 2 and 3 are run per arm.

metric: primary: oracle pass rate on sessions 2 and 3 (120 session instances), per arm. Reported for each arm: gain over arm 0 (the CL-Bench stateful-minus-own-stateless measure, normalised as (pass_arm - pass_0) / (1 - pass_0)); input tokens per session (median and p95); executor steps. Secondary: the truncated-history subgroup; CL-Bench Codebase Adaptation normalised gain with reward 1 - (steps - 1)/max_steps when solved, if the dataset is available (directional only, 19 issues in 2 repositories).

predeclared margin: for each derived arm d in {1, 2, 3}: `derived_superior(d)` if ci95_low(pass_d - pass_4) > 0; `derived_noninferior_cheaper(d)` if ci95_low(pass_d - pass_4) >= -0.10 and median_tokens_d <= 0.5 x median_tokens_4; `raw_superior(d)` if ci95_high(pass_d - pass_4) < 0. Verdict: derived_wins if any derived_superior; raw_wins if no derived_superior and raw_superior holds for every derived arm; otherwise inconclusive, with each derived_noninferior_cheaper arm listed. The card's rule (a derived arm ships only if it beats raw history at equal or lower tokens) is kept as the ship rule; the non-inferior-and-cheaper finding is reported so the token trade-off is visible, and does not by itself ship a surface.

sample size and power note: 60 sequences, 2 scored sessions each, 3 rollouts per session per arm (rollouts estimate model variance and are averaged per session; they do not add independent units). Clustering unit: sequence. With about 20% discordant session outcomes between two arms, the paired SE is about 0.041 before clustering and about 0.050 with a design effect of 1.5 across the two sessions of a sequence. A 0.10 non-inferiority margin then has about 64% (design effect 1.5) to 79% (no clustering) power at a true difference of 0; a 0.05 margin would have about 26% to 34%, which is why 0.10 is used. Superiority by 0.10 or more is detected with similar power; smaller true differences will read inconclusive, and the spec says so rather than claiming equivalence. Noise floor: the unchanged stack's spread from H1's noise-floor runs is reported beside every difference.

kill criterion: the claim is killed (derived_wins) if any derived arm's pass rate exceeds raw history's with ci95_low > 0. Stop before running (not a result) if H1's DreamBench-SWE harness or H3's arm builders are not frozen, more than 20% of arm 4 sessions need truncation (then the run is not in the fitting regime the claim is about), any pin is missing, or the executor or curator model is also the oracle.
