claim: On our labelled staleness and supersession decisions, giving Jev a state projected in code (relative-age labels, same or older version labels, counts as bands, fields the question does not use dropped) instead of the raw stored state (ISO timestamps, version strings, counts, all fields) raises decision accuracy by at least 5 points on decisions whose gold answer depends on a date, version or count, cuts input tokens by at least 25%, and loses no more than 2 points on decisions that depend on text only; and a deterministic rule over the projected fields alone is reported to show whether projection makes the model call unnecessary. Source: N-20261001-03 (jev-state at 3c30e89, repo-pinned, priority 1): on 70 seeded synthetic NPC scenarios x 3 reruns on jev-1.13.0, accuracy 74.3% raw against 100.0% projected, unstable scenarios across reruns 6/70 against 0/70, mean input tokens 1,236 against 699 (minus 43%), p95 latency 422 against 390 ms, total cost 0.0171 USD for 420 calls; raw-state errors concentrated on rules needing arithmetic (retreat 50.0%, patrol 43.3%, heal 60.0%); raw-state confidence was overconfident below 0.5 (41.2% claimed, 28.9% observed, n = 38) and close in 0.7 to 0.9 (81.7% against 81.4%, n = 70). Limits that make our test necessary: one synthetic game domain, policy and grader written by the library author, and the projected label can encode the answer ("critical" is close to the rule "retreat below 20% of max"), so 100% partly measures that the code did the arithmetic (the author says so); no rule-only or LLM comparison on projected state; nothing on text-heavy decisions. Our staleness and supersession state carries recorded_at timestamps, dependency versions and citation counts, which is the failure shape the source isolates.

arms (same 300 decisions, same question text, same options and the same decision threshold for A and B; Jev version pinned; every A and B call made 3 times):
- A (control): Jev on the raw state as stored (P5 fields: recorded_at, last_verified_at, cited artifact versions and blob ids, citation counts, source_class, all other stored fields), serialised by the production serialiser.
- B (decision arm): Jev on the state projected by `stateproj` (frozen code, pinned commit): ages relative to the check time into "under a day / under a week / under a month / under a year / older"; each cited version against the current version into "same / older patch / older minor / older major / newer / not comparable"; counts into "none / one / few (2 to 4) / many (5 or more)"; text fields kept verbatim; fields not on the question's keep list dropped. The keep list per question type is written from the labelling guide before any model call.
- C (reported, no model): a decision table over B's projected fields only, written by an engineer from the labelling guide and the fit fold's labels before any model call, frozen as `rules.yaml`; decisions it cannot reach return "abstain" and are scored as errors.
- override: the card's "thresholds" are kept identical for A and B by deciding on the option with the highest probability (argmax), with no fitted threshold, so that only the state differs; a per-arm fitted threshold on the fit fold is reported beside it.

metric: accuracy per stratum (numeric or temporal; text-only) with Wilson 95% intervals, each decision scored as the majority answer over its 3 calls; rerun instability = decisions whose answer differs across the 3 identical calls / decisions; mean input tokens per call; reliability table (n, mean confidence, accuracy) per confidence bin 0 to 0.5, 0.5 to 0.7, 0.7 to 0.9, 0.9 to 1, per arm; C's abstention rate.

predeclared margin: positive needs, on the numeric and temporal stratum, accuracy(B) minus accuracy(A) at least 0.05 with the two-sided 95% interval excluding zero; on the text-only stratum, accuracy(B) minus accuracy(A) at least minus 0.02 (point estimate, with its one-sided 95% lower bound reported); mean input tokens of B at most 0.75 of A's; and accuracy(B) minus accuracy(C) on the numeric and temporal stratum above 0.02. The rule-route check is separate: if accuracy(B) minus accuracy(C) on that stratum is at most 0.02 (point estimate), those decisions route to the rule.

sample size and power note: 300 decisions, at least 150 per stratum, labelled by two engineers who mark, before any model call, whether the gold answer depends on comparing a date, version or count (stratum label, kappa recorded). Clustering unit: the memory item's source artifact (about 80 to 120). On the numeric and temporal stratum the source's effect was 26 points; at a true 10-point gain with paired discordance about 0.2 on 150 decisions and a design effect of about 1.3, SE about 4.2 points, P(interval excludes zero and mean at least 5) about 0.75; at a true 5-point gain about 0.3. The text-only screen has SE about 2.5 to 3 points (discordance about 0.08), so it detects a large loss, not a 2-point one, and is labelled a screen. `sp power` (cluster-resampling simulation under these assumptions, 1,000 draws, seed 20261026) runs before any model call and is recorded in `power.json`; the decision rule does not change with it.

kill criterion: negative if accuracy(B) minus accuracy(A) on the numeric and temporal stratum is below 0.02 (point estimate): projection is dropped as a requirement. Rule route if accuracy(B) minus accuracy(C) on that stratum is at most 0.02. Invalid (rerun under a new spec revision, not a verdict): the question, options or decision rule differing between A and B; the projection code, keep lists or `rules.yaml` changed after any model call; stratum or gold labels edited after any arm ran; stratum-label kappa below 0.6; fewer than 120 decisions in either stratum; the Jev version differing from the pin; any decision missing from A or B without an explicit failed record.

what a pass unlocks: the priority 1 design rule for every System One call at the staleness and supersession stages: whether code resolves dates, versions and counts before the model is asked, and which of these decisions need a model at all (the rule route); a local reliability table for Jev on our own state for B14 (working: calibration claimed, not shown; the note records a narrow contradiction row), with the raw-against-projected bins side by side; for B3 (lead: write-time supersede edges are part of what wins knowledge updates), a measured accuracy for the supersession decision that writes those edges, which bounds how much the edge can contribute; a frozen projection module and keep lists that E-20260928-07-r2, E-20260926-09-r2 and E-20261001-04's audit arm can adopt.
