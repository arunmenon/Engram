claim: On multi-session software tasks where a common, frozen prior-session history fits the executor's context window, presenting that history raw is at least as good as every derived representation of the same history that H3 considers (session summary, Workflow node text, curated briefing from the top-3 raw episodes): no derived representation beats raw history on oracle pass rate by a practical margin at no higher total token cost. This tests representation of a fixed history, not an adaptive memory policy.

arms (same frozen executor, same tools, same task prompts, same frozen repository state and workspace image, paired seeds; only the memory block differs):
- Arm 0 (stateless): no prior-session material.
- Arm 1 (session summary): Consumer 4 session summaries of the frozen prior sessions.
- Arm 2 (Workflow text): Consumer 4 Workflow node text extracted from the frozen prior sessions; if none is produced the block is empty and that is recorded.
- Arm 3 (curated briefing): H3's task-conditioned briefing synthesised from the top-3 raw episodes of the frozen prior sessions, with H3's curator pin.
- Arm 4 (raw history): verbatim frozen prior-session transcripts (task, agent turns, tool results, final diff) in chronological order.
- History protocol (representation estimand): sessions 1 and 2 of every sequence are run once with a reference configuration (arm 0 executor, reference seed); their transcripts and end-of-session repository states are frozen. Scored session 2 in every arm starts from the frozen end state of reference session 1 with a block built from reference session 1; scored session 3 starts from the frozen end state of reference session 2 with a block built from reference sessions 1 and 2. No arm's scored output ever feeds another session. Arm-specific adaptive histories (the policy estimand) are out of scope and left to a follow-up.
- Isolation: each run is a fresh container from the pinned image, with caches cleared, no shared home directory, no network, and oracle tests stored outside the container. Git history of the frozen repository state is identical across arms, including arm 0, and is declared as part of the world state.

metric: primary: oracle pass rate on eligible scored session instances (sessions 2 and 3), per arm, rollout-averaged. Reported per arm: gain over arm 0, (pass_arm - pass_0) / (1 - pass_0); total tokens per session instance = block-build tokens (summariser, Workflow extractor, curator calls, amortised per instance) + executor input + executor output; median and p95. Secondary: the over-window (truncated) subgroup, reported separately and never pooled with the primary; CL-Bench Codebase Adaptation normalised gain for arms 0, 3 and 4 if the release is runnable (directional only, 19 issues, 2 repositories).

predeclared margin: confidence level: two-sided 95% intervals throughout. Multiplicity: fixed-sequence testing of derived superiority in the order arm 3, arm 1, arm 2, each at alpha 0.05, stopping at the first arm not declared superior (arm 3 first because it is H3's candidate and B7's claim; arm 1 is Consumer 4's current surface; arm 2 is often empty). derived_superior(d) = reached in the sequence and ci95_low(pass_d - pass_4) > 0 and (pass_d - pass_4) >= 0.05 (practical superiority margin 5 points). Ship rule, separate from descriptive flags: ship(d) = derived_superior(d) and mean_total_tokens_d <= mean_total_tokens_4. raw_superior(d) = ci95_high(pass_d - pass_4) < 0. raw_wins = no derived_superior and raw_superior for every d (an intersection-union test, no adjustment needed). Descriptive only, never ships: noninferior_cheaper(d) = ci95_low(pass_d - pass_4) >= -0.10 and mean_total_tokens_d <= 0.5 x mean_total_tokens_4.

sample size and power note: eligibility is predeclared and computed before any scored run, which the common frozen histories make possible: a session instance is eligible iff the rendered raw prior history fits the window minus the fixed reserve. Required support: at least 90 eligible instances from at least 45 sequences, else not runnable. Unit: sequence (clustering unit); rollouts are averaged per instance and their variance is carried by a two-stage bootstrap (resample sequences, then rollouts within each resampled instance). With 120 eligible instances, 20% discordance and a design effect of 1 to 1.5, the SE of a paired difference is about 0.041 to 0.050. Using two-sided 95% intervals: power to show superiority when the true difference is 0.10 is about 52% to 69% (first arm in the sequence); at 0.15 about 85% to 96%; power to show non-inferiority at a 0.10 margin when the true difference is 0 is about 52% to 69%, and at 0.05 about 17% to 23%. With only 90 eligible instances the SE grows by about 15% and these powers fall. Differences below about 0.10 will usually read inconclusive, and the spec says so rather than claiming equivalence. Noise floor: H1's unchanged-stack spread is reported beside each difference.

kill criterion: the claim is killed (derived_ships) if any derived arm passes the ship rule. Stop before running (not a result) if H1's harness, H3's arm builders or H1's noise-floor artifact are not frozen; fewer than 90 eligible instances or 45 sequences remain after exclusions; any sequence used to develop or tune Consumer 4 or H3 prompts is not in tuning_exclusions.json; the executor, curator or any block builder is also the oracle or can read oracle files; the memory-block provenance check fails; or any pin is missing.
