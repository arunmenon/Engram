claim: On H10's seeded history, invalidating a Decision when the exact unit it depends on changes (the cited file's line range or symbol, or the specific ticket field) flags stale Decisions with precision at least 0.20 higher than invalidating every Decision whose cited file changed, at recall no more than 0.10 lower, and leaves fewer valid Decisions withheld; source-level invalidation, no invalidation, H10a's model audit, and span-level followed by the audit are reported. Source: N-SURVEY-20260930-07 (Invalidation Contracts for Cross-Episode Agent Memory, arXiv 2609.00243, paper-ablated): across seven models and three seeds per cell (about 9,400 episodes), row-level invalidation with diffs had eviction precision 1.00 on every model, while table-level invalidation had 0.25 on five of seven (0.31 and 1.00 on the others) and cut post-drift first-try success on still-valid entries in the untargeted class to 0% on five of seven (66.7% with row-level); stamp checks with dependency vectors changed tokens by minus 0.11 to plus 0.20% against lazy checking, stamp-only checks by plus 14.0 to 14.3%; the contract added 15.1% to response payloads. Limits that make our test necessary: two synthetic API domains authored for the study; cached items are API error fixes, not engineering knowledge; the mapping to files, tickets and requirements is structural (the note's inference); many ticket and document tools expose only a last-modified time, which is the coarse arm. H10 says to test source-change invalidation before a model audit and does not say at what granularity; P5 does not yet say what unit a derived item's dependency is recorded at.

arms (same 160 Decisions, same pre-change dependency annotations, same post-change snapshot; arms 1 to 4b are deterministic code with no model call):
- 1 (reported): no invalidation; every Decision served.
- 2 (reported): source-level: flag if the cited repository or ticket changed at all after recorded_at.
- 3 (baseline): file-level: flag if any cited file's blob hash changed (for ticket-sourced Decisions, if the ticket's last-modified time changed).
- 4 (decision arm): span-level: flag if a changed hunk overlaps a cited line range or a cited symbol's body, tracked through renames and moves with the pinned diff algorithm (for ticket-sourced Decisions, if a cited field changed); spans are the human annotations made from the pre-change snapshot.
- 4b (reported): span-level with spans derived automatically at recorded_at (symbols named in the Decision text resolved by the pinned ctags at the pre-change commit; files only when nothing resolves), to show whether P5 can capture spans without a person.
- 5 (reported): H10a's model audit alone: Jev noul "is this decision still true given the current snapshot?" on every Decision, snapshot = cited files' current content and diffs since recorded_at (E-20260926-09-r2's recipe), flag if P(still true) < 0.5.
- 6 (reported): arm 4, then arm 5's audit on the Decisions arm 4 did not flag (union of flags), reusing arm 5's cached answers, no new calls.
- override: the card's "about 50 stale and 50 valid" is extended to 160 (60 stale, 100 valid) because the file-versus-span contrast exists only for valid Decisions whose cited file changed elsewhere; the set requires at least 60 such Decisions, otherwise file-level and span-level coincide by construction.

metric: stale-flag precision and recall per arm with Wilson 95% intervals; valid Decisions wrongly withheld (count and share of valid Decisions); serve-time cost per 1,000 checks (model tokens and wall-clock for arms 5 and 6; compute time for 1 to 4b); for 4b, agreement of automatic spans with annotated spans.

predeclared margin: positive needs precision(4) minus precision(3) at least 0.20 with the two-sided 95% interval excluding zero, and recall(3) minus recall(4) at most 0.10 (point estimate, with its one-sided 95% upper bound reported).

sample size and power note: 160 Decisions in about 50 to 70 clusters (the cited file, or the ticket, a Decision's first dependency sits in; clustering unit, since Decisions citing one file change together). File-level flags every stale Decision whose file changed plus the 60 or more valid Decisions with a changed file elsewhere, so its precision is near 60 / (60 + 60) = 0.5 by construction of the set; span-level, if spans are good, flags few of those valid Decisions. A true precision gap of 0.3 on about 120 file-level flags and 70 span-level flags, with a design effect of about 1.5, gives a cluster-bootstrap SE of about 0.08, so P(pass) is about 0.85; a true gap of 0.2 about 0.5. Because the file-level precision depends on how many valid Decisions share a changed file, the set's composition is frozen and reported, and the finding is stated as conditional on that share; the PDLC-SEED-ASF history's own share of Decisions whose file changed elsewhere is measured and reported beside it as the deployment-relevant base rate.

kill criterion: negative if precision(4) minus precision(3) is below 0.20 (point estimate): file plus blob hash is enough for P5. Invalid (rerun under a new spec revision, not a verdict): a dependency annotation made with access to the post-change snapshot (annotation tool logs the commit shown); labeller kappa on stale or valid below 0.6; fewer than 40 stale Decisions or fewer than 60 valid Decisions with a changed file elsewhere; annotations or labels edited after any arm ran; the diff algorithm, ctags version or Jev version differing from the pin.

what a pass unlocks: the unit at which P5 records what a derived memory depends on, which every staleness rule and H10a's audit build on; a clause for the scoped-interface contract (B22, firm local: the enterprise contract demands one scoped interface, a swap test and point-in-time reads): a store adapter declares whether it can report versions and diffs at file or span level and therefore what invalidation it supports; the right baseline for H10a, since a model audit that only beats coarse invalidation has not shown it is needed; a measured share of model-audit flags that span-level invalidation already catches.

cost (runs, tokens, people-days): extending H10's seeded Decisions to 160 and annotating dependencies at four granularities from the pre-change snapshot, two engineers, about 2 days; stale or valid labels after the change, two labellers, adjudicated, about 8 labeller-hours; harness 2 engineer-days (diff tracking through renames, ctags at a commit). Model tokens: arm 5, 160 x about 3.5k = 0.56M plus repeat calls on 40 Decisions for a flip rate, 0.14M, about 0.7M; arm 6 reuses arm 5's answers; aggregate hard cap 1.5M. USD: Jev under 0.1 USD; aggregate cap 5 USD. Cost S.
