claim: When Engram's stores and views are exposed as explicit named tools, a decision model choosing the tool plus a small fast LLM writing the arguments reaches end-task success within 2 points of a frontier model's native tool calling on our memory requests, at under a quarter of the median cost per request.

arms:
- A (baseline): pinned frontier model, native tool calling over the frozen memory tool set.
- B: hosted Jev picks the tool at each step (task, tool list, previous results as state); a pinned small fast LLM writes the arguments and the final answer.
- C: open-weight decision model (Laya, pinned, zero-shot) in place of Jev, same small LLM.
Same frozen tool set, same tool descriptions, same turn budget (8 tool calls) for every arm; WindTunnel's unequal per-interface budgets are the confound this removes.

metric: primary: request success, by majority of 3 attempts, where success is a deterministic check (expected store or view hit and the expected item ids returned, set equality). Secondary: median cost and latency per request, per-tier success (single-store lookup, multi-store, multi-hop).

predeclared margin: B passes if success(A) minus success(B) has a request-clustered one-sided 95% upper bound below 2 points and median cost(B) is below 0.25 x median cost(A).

sample size and power note: 150 requests, cluster = request (3 attempts nested). The 2-point bound is only reachable if the arms are nearly concordant; with 10% discordant pairs the standard error is about 2.6 points, so a clean pass needs B at or above A in point estimate. The run is honest about this: inconclusive is a likely outcome unless discordance is low. At least 50 requests must be multi-hop so A does not saturate.

kill criterion: B more than 5 points below A in point estimate; or both A and B at or above 98% success (benchmark too easy, rebuild before deciding).

what a pass unlocks: a cheap router for the memory routing stage; moves B12 (lead) by testing "decision model under a structure works" on our own requests rather than games or browser tasks; makes explicit tool contracts a hard design rule.

cost (runs, tokens, people-days): 3 arms x 150 requests x 3 attempts in one run of about 1.9M tokens; estimated $8 to $10 (frontier arm dominates); 4 people-days for the fixture and the tool wrappers.
