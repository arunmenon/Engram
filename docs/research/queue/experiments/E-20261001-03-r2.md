claim: On our labelled staleness and supersession decisions, giving Jev a state projected in code (relative-age labels, same or older version labels, counts as bands, fields the question does not use dropped) instead of the raw stored state (ISO timestamps, version strings, counts, all fields) raises decision accuracy by at least 5 points on decisions whose gold answer depends on a date, version or count, cuts input tokens by at least 25%, and loses no more than 2 points on decisions that depend on text only; and a deterministic rule over the projected fields alone is reported to show whether projection makes the model call unnecessary. Source: N-20261001-03 (jev-state at 3c30e89, repo-pinned, priority 1), figures checked against the README benchmark table by REV-20261001-06: on 70 seeded synthetic NPC scenarios x 3 reruns on jev-1.13.0, accuracy 74.3% raw against 100.0% projected, unstable scenarios across reruns 6/70 against 0/70, mean input tokens 1,236 against 699 (minus 43%), p95 latency 422 against 390 ms. The note's per-rule error rates, exact cost and calibration-bin figures come from bench/results.md, which was not staged for checking; they are dropped from this spec until a person places the pinned results file in the fixture store. Limits that make our test necessary: one synthetic game domain, policy and grader written by the library author, and the projected label can encode the answer ("critical" is close to the rule "retreat below 20% of max"), so 100% partly measures that the code did the arithmetic (the author says so); no rule-only or LLM comparison on projected state; nothing on text-heavy decisions. Our staleness and supersession state carries recorded_at timestamps, dependency versions and citation counts, which is the failure shape the source isolates.

arms (same 300 decisions, same question text, same options and the same decision threshold for A and B; Jev version pinned; every A and B call made 3 times):
- A (control): Jev on the raw state as stored (P5 fields: recorded_at, last_verified_at, cited artifact versions and blob ids, citation counts, source_class, all other stored fields), serialised by the production serialiser.
- B (decision arm): Jev on the state projected by `stateproj` (frozen code, pinned commit): ages relative to the check time into "under a day / under a week / under a month / under a year / older"; each cited version against the current version into "same / older patch / older minor / older major / newer / not comparable"; counts into "none / one / few (2 to 4) / many (5 or more)"; text fields kept verbatim; fields not on the question's keep list dropped. The keep list per question type is written from the labelling guide before any model call.
- C (reported, no model, cross-fitted): two decision tables over B's projected fields only. `rules_fold1.yaml` is written by engineer E1 from the labelling guide and fold-1 labels only and is scored on fold 2; `rules_fold2.yaml` is written by a different engineer E2 from the guide and fold-2 labels only and is scored on fold 1. Each author receives a label export containing only their fold (the export's sha256 and the author are recorded in `rules_provenance.json`), neither sees the other fold's labels or any model output, and both tables are hashed before any model call. Decisions a table cannot reach return "abstain" and are scored as errors.
- routing predicate R (deployable, observable, frozen before labels are seen by its author): `route.py`, written from the labelling guide's question templates and the P5 field schema only, returns `numeric` when the decision's question type has a date, version or count comparison in its template (staleness "still current as of", supersession "newer than") AND the item or item pair carries at least one non-null field of type timestamp, version or count that differs between the compared values, and `text` otherwise. It reads only the question type and the stored state, never a label. Its agreement with the gold stratum label is a reported metric; every primary comparison is reported both on the gold strata and on the predicate-routed strata, and the decisive comparison uses the predicate-routed strata, because production can only route by R.
- override: the card's "thresholds" are kept identical for A and B by deciding on the option with the highest probability (argmax), with no fitted threshold, so that only the state differs; a per-arm fitted threshold on the fit fold is reported beside it.

metric: accuracy per stratum (numeric or temporal; text-only) with Wilson 95% intervals, each decision scored as the majority answer over its 3 calls; rerun instability = decisions whose answer differs across the 3 identical calls / decisions; mean input tokens per call; reliability table (n, mean confidence, accuracy) per confidence bin 0 to 0.5, 0.5 to 0.7, 0.7 to 0.9, 0.9 to 1, per arm; C's abstention rate; routing confusion (R against the gold stratum: precision and recall of `numeric`, with Wilson intervals) and the end-to-end accuracy of the routed system (R's `numeric` decisions answered by B, R's `text` decisions by A) against A everywhere, so routing mistakes are priced.

predeclared margin (this is a pilot; no margin here changes a production default): pilot_positive needs, on the predicate-routed numeric stratum, accuracy(B) minus accuracy(A) at least 0.05 with the two-sided 95% interval excluding zero; on the predicate-routed text stratum, accuracy(B) minus accuracy(A) at least minus 0.02 (point estimate; a screen, with its one-sided 95% lower bound reported); mean input tokens of B at most 0.75 of A's. The rule-route candidate is separate and needs, on the predicate-routed numeric stratum, the one-sided 95% lower bound of accuracy(C) minus accuracy(B) above minus 0.03 and accuracy(C) at least 0.90 (absolute floor); equal poor performance therefore cannot qualify. The same quantities on the gold strata are reported beside them.

sample size and power note: 300 decisions, at least 150 per stratum, labelled by two engineers who mark, before any model call, whether the gold answer depends on comparing a date, version or count (stratum label, kappa recorded). Clustering unit: the memory item's source artifact (about 80 to 120). On the numeric and temporal stratum the source's effect was 26 points; at a true 10-point gain with paired discordance about 0.2 on 150 decisions and a design effect of about 1.3, SE about 4.2 points, P(interval excludes zero and mean at least 5) about 0.75; at a true 5-point gain about 0.3. The text-only screen has SE about 2.5 to 3 points (discordance about 0.08), so it detects a large loss, not a 2-point one, and is labelled a screen. `sp power` (cluster-resampling simulation under these assumptions, 1,000 draws, seed 20261026) runs before any model call and is recorded in `power.json`; the decision rule does not change with it.

kill criterion: negative if accuracy(B) minus accuracy(A) on the predicate-routed numeric stratum is below 0.02 (point estimate): projection is not pursued. Invalid (rerun under a new spec revision, not a verdict): the question, options or decision rule differing between A and B; the projection code, keep lists, `route.py`, `rules_fold1.yaml` or `rules_fold2.yaml` changed after any model call; a rule table whose provenance shows its author received the other fold's labels, or both tables written by the same engineer; stratum or gold labels edited after any arm ran; stratum-label kappa below 0.6; fewer than 120 decisions in either gold stratum or fewer than 100 in either predicate-routed stratum; the Jev version differing from the pin; any decision missing from A or B without an explicit failed record.
