claim: On a frozen set of build-time engineering tasks whose artifact pool contains superseded, conflicting and falsely-final documents, serving the same top-k artifacts (byte-identical payloads) each with an authority label and a one-paragraph evidence report raises the task rubric pass rate by at least 5 points over serving the same top-k unlabelled, without misclassifying more than 5% of authoritative artifacts as superseded or false final.

arms (same frozen executor, same retrieval, same top-k artifact ids and order, same frozen payload bytes in A, E, B and C; only the served decoration differs):
- Payload freeze (all main arms): the harness runs retrieval once per task (k = 10, the value implied by the original spec's 600 artifacts over 60 tasks), truncates the top-k payload once to the pinned payload ceiling `T_payload`, and stores the result as `payload/<task>.bin` with its sha256. Arms A, E, B and C serve exactly these bytes; decoration is added in a separate per-artifact decoration slot of exactly `dec_tokens` tokens (pinned before freeze) and never truncates the payload.
- Arm A (baseline): frozen payload, no decoration.
- Arm E (evidence-only, matched length): each artifact's decoration slot holds its observable ledger edge records (edge type, counterpart artifact id, date) and neutral metadata (path, commit date) rendered by a fixed template, with no authority label and no report; padded with a fixed neutral filler line or cut to exactly `dec_tokens`. Separates the effect of extra ledger evidence and decoration length from the effect of a label.
- Arm B (deterministic labels, matched length): label from observable ledger edges only: `superseded` if the artifact has an observable outgoing superseded-by edge, otherwise `unknown (no ledger evidence of supersession)`. Absence of an edge is never labelled authoritative, because pools contain fabricated, conflicting and out-of-scope material that has no edges. Templated one-line report naming the superseding artifact id and date where one exists; slot filled to exactly `dec_tokens` as in E. No model call.
- Arm C (model labels, the card's arm, matched length): one typed choice per artifact over the six Env-Rethink authority classes (authoritative record, false final version, fabricated authority, misleading redirection, superseded version, out of scope) plus an explicit `unknown` abstention, conditioned on the artifact, its observable ledger edges and its top-k neighbours, plus a one-paragraph evidence report; slot filled or cut to exactly `dec_tokens` as in E.
- Arm D (hide, secondary, exploratory): the Arm B `superseded` labels are used to drop those artifacts from the frozen payload; the remaining artifacts are byte-identical to the frozen payload and the freed budget is not refilled. D changes the payload by design and is outside the common-payload comparison; it is dropped first if the approved cap is below this spec's total.
- Held equal: task prompt, executor pin, retrieval config and pool, top-k ids and order, frozen payload bytes (A, E, B, C), decoration token count per artifact (E, B, C), total served-token ceiling `T_payload + k x dec_tokens`.
- Isolation: labeller and executor read only `pools/<task>/artifacts/` and `pools/<task>/ledger_observable.jsonl`. Seeding logs, ground-truth classes and rubrics live under `eval_only/`, which the labeller and executor processes cannot read.

metric: primary: rubric pass rate per task (share of predeclared rubric items passed, averaged over 3 rollouts), Arm C minus Arm A. Secondary (Holm-corrected as one family): E minus A (evidence plus length), B minus E (deterministic label beyond matched evidence), C minus E (model label and report beyond matched evidence), C minus B, D minus the better of B and C. Label outcomes against `eval_only/ground_truth_labels.jsonl`: authoritative mislabelled as superseded or false final (safety), superseded mislabelled as authoritative, abstention (`unknown`) rate, and the full confusion matrix for C; served tokens per task; labeller tokens and latency. The judge scores rubric items blind to arm and does not share a model family with the executor or the labeller.

predeclared margin: three disjoint primary outcomes, evaluated after the safety check. labels_help if mean(C minus A) >= 0.05 and ci95_low(C minus A) > 0. labels_do_not_help (bounded negative) if ci95_high(C minus A) < 0.05, i.e. a 5-point gain is excluded. inconclusive otherwise. Ship-B rule: if labels_help and ci95_low(B minus C) >= -0.03, the deterministic arm ships instead of the model arm (deterministic first).

sample size and power note: 96 tasks, 3 rollouts each; the unit is the task (rollouts are averaged and estimate model variance only). Clustering unit: source repository (at least 12 repositories, no repository contributing more than 8 tasks). Assumptions carried from the original spec: per-task SD of the paired difference 0.15, design effect 1.3 from repository clustering. Arithmetic: SE = 0.15 x sqrt(1.3) / sqrt(n) = 0.1710 / sqrt(n).
- At the original n = 60: SE = 0.1710 / 7.746 = 0.0221; 1.96 x SE = 0.0433. The original's "about 60% power at a true 5-point gain" was wrong: with a 0.05 point-estimate threshold, P(pass | true 0.05) = Phi(0) = 0.50 at most. Its "95% at 8 points" held only for "CI excludes 0" alone; with the 0.05 point threshold it is Phi(0.03 / 0.0221) = Phi(1.36) = 0.91. The bounded-negative rule at n = 60 needs mean < 0.05 - 0.0433 = 0.0067, so P(labels_do_not_help | true 0) = Phi(0.0067 / 0.0221) = Phi(0.30) = 0.62, too weak.
- Sizing: require P(labels_do_not_help | true 0) >= 0.80, i.e. 0.05 / SE - 1.96 >= 0.8416, SE <= 0.05 / 2.8016 = 0.01785, n >= (0.1710 / 0.01785)^2 = 91.8. Chosen n = 96 (12 repositories x 8).

True gain 0.08: P(labels_help) = Phi(1.72) = 0.96.
