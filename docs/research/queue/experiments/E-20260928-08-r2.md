claim: A System One model can decide whether a pull request implements a requirement or design section close enough to an LLM checker to be used at the PDLC linking stage. Specifically, on 200 held-out human-labelled (requirement or design section, PR) pairs from SpecMine Kiro repositories, frozen at decision time, at least one of hosted Jev or a self-hosted open-weight decision model reaches macro-F1 on the 3-way label (implements / partial / no) within 10 points of a single-call LLM checker, or a fine-tuned ModernBERT-large reaches binary macro-F1 (any link vs no) within 10 points of the checker's binary collapse, or a Jev-then-LLM confidence cascade comes within 2 points of the checker at under 50% of its cost; and, separately, whether any arm's calibration-fit auto-write threshold meets absolute accepted-link precision and coverage targets at deployment prevalence. This revision runs as a PILOT: at n = 200 it cannot reliably confirm the margins (power arithmetic below); it can return a clear negative for large gaps, a positive only when the selection-aware interval clears the margin, and it sizes a confirmatory run. Sources: N-SURVEY-20260928-14 (explicit PR-issue links misaligned in 13.6% of SWE-bench Verified; frontier multi-agent checker 88.11% to 92.12% binary accuracy at USD 0.08 to 0.23 per link on average, with large patches pushing per-instance cost above USD 1; human kappa 0.575 on a fine-grained label; fine-tuned 3B to 7B models 62.75% accuracy but 34.44% macro-F1; no System One arm in any source), N-SURVEY-20260928-11 (Jev 11.6 macro-F1 points behind the best LLM at about 44x lower cost on social-science tasks; cascade at 27% to 56% of LLM cost), N-SURVEY-20260928-13 (SpecMine data; its Appendix B states co-change is an assumption, not ground truth, and a PR may implement a requirement only partially), N-SURVEY-20260928-12 (fine-tuned encoder close to a bespoke read-out). The card lists no belief; the register has none on trace-link deciders. The spec tags B14 because the auto-write threshold rests on calibration measured here, on our data, rather than vendor calibration.

arms (same frozen pair renderings, same rubric; neutral option names A/B/C, following N-SURVEY-20260928-10, so the result does not depend on E-20260928-06's outcome):
- A: hosted Jev, one Choice decision over three neutral-named options with rubrics for implements / partial / no. Confidence: the probability the Choice response assigns to the selected option; if the API returns no per-option probability at freeze, A is scored on labels only and is excluded from E and from auto-write (stated in run_manifest.json).
- B: a self-hosted open-weight decision model, Laya-0.4B (Apache 2.0), weights revision hash pinned at freeze; decider-0.8b replaces it only if its licence is confirmed before freeze. Same Choice. Confidence: normalised option probability from the model's output distribution.
- C: ModernBERT-large fine-tuned as a BINARY classifier (any link vs no) on SPECMINE-LINK-TRAIN silver labels from repository families disjoint from calibration and test. C is not scored on the 3-way label because silver labels cannot separate implements from partial (see Revision notes). Confidence: softmax probability of "any link".
- D: LLM checker: one call to a pinned Claude model (claude-sonnet-5, version string pinned at freeze), temperature 0, the PAIChecker misalignment taxonomy in the prompt, the same three labels, and a JSON field with a stated probability for each label (used as D's confidence). This is the quality reference, not PAIChecker itself (which is multi-agent). D must meet absolute floors (below) or the relative comparison is invalid.
- E: cascade: A, then D for every pair whose A confidence is below a threshold fit on the calibration split to maximise macro-F1 subject to D-call share <= 50% (calibration split only). E reuses D's logged decision for routed pairs, so E's cost is A's cost on all pairs plus D's cost on routed pairs.
- Controls: a rule arm (explicit reference or co-change only, no model) and the label base rate, both reported.
- Three-option instability (N-SURVEY-20260928-10 reports it on Laya even with neutral names) is checked by also reporting A and B as two binary decisions (any link? then full or partial?) on the test split; the verdict uses the Choice form and states the gap.

metric: primary: macro-F1 on the 3-way label (A, B, E vs D) and binary macro-F1 on the any-link collapse (C vs D's collapse); secondary: accepted-link precision and coverage of the auto-write rule at deployment prevalence (reweighted, see packet); precision at recall 0.8 on the binary collapse; ECE after one temperature refit per arm on the calibration split; cost per 1,000 links at list prices on the run date (B and C: amortised GPU time); p95 decision latency; whether pair text left our infrastructure (A, D, E: yes; B, C: no). Every arm is also reported against each labeller and against the adjudicated label, next to inter-labeller kappa; kappa is context for label noise, not a ceiling on F1.

predeclared margin: relative: 10 macro-F1 points for A, B (3-way) and C (binary) against D; 2 points and < 50% of D's cost for E. These are the card's margins; they are practical margins. Absolute floors (our predeclared design targets, not source numbers): D validity floor: D 3-way macro-F1 >= 0.50 and D binary precision at recall 0.8 >= 0.70 at deployment prevalence; auto-write targets for any arm: accepted-link precision point estimate >= 0.90 with one-sided 95% lower bound >= 0.80, and coverage (share of true links auto-written) >= 0.50, all on the test split at deployment prevalence using the threshold fit on calibration only. An arm can be adopted for review-routed proposals on the relative margin, but can auto-write only if it also meets the auto-write targets; otherwise its auto-write threshold is set to "never" and every link goes to review, which is consistent with the positive outcome.

sample size and power note: Evaluation data: 300 human-labelled pairs split by repository family into 100 calibration and 200 test, plus a 100-pair uniform prevalence sample from the test families' deployment candidate stream (see packet). Target 12 to 20 repository families (minimum 6), at least two thirds of them in test; the actual number of test clusters is reported, not assumed. Planning assumptions (not measured; the pilot estimates them): arm-vs-D discordance on the 3-way label d = 0.30; E-vs-D discordance d_E = 0.10 (only on pairs not routed to D); macro-F1 standard error about 1.3x the accuracy-difference standard error; clustering design effect 1.5. Selection-aware critical value: the pass family is {A, B, C, E}, so each one-sided test uses alpha = 0.05 / 4 = 0.0125, z = 2.241.
- Single arm vs D at margin 0.10, n = 200: SE_acc = sqrt(0.30 / 200) = 0.0387; SE_F1 = 1.3 x 0.0387 = 0.0503; with design effect, 0.0503 x sqrt(1.5) = 0.0617. Power to show the lower bound above -0.10 when the true gap is 0: Phi(0.10 / 0.0617 - 2.241) = Phi(-0.62) = 0.27 (pair-level only: Phi(1.99 - 2.24) = 0.40). True gap -0.05: Phi(0.81 - 2.24) = 0.08. Power to show a negative (upper bound below -0.10): true gap -0.20: Phi((-0.2382 + 0.20) / 0.0617) = Phi(-0.62) = 0.27; true gap -0.30: Phi(1.00) = 0.84.
- Test pairs needed for 80% power at true gap 0: n = (2.241 + 0.842)^2 x 0.30 x 1.3^2 x 1.5 / 0.10^2 = 9.505 x 0.30 x 1.69 x 1.5 / 0.01 = about 723; at true gap -0.05, / 0.05^2 gives about 2,891.
- E vs D at margin 0.02: SE = sqrt(0.10 / 200) x 1.3 x sqrt(1.5) = 0.0224 x 1.3 x 1.225 = 0.0356; power at true gap 0: Phi(0.02 / 0.0356 - 2.241) = Phi(-1.68) = 0.05. Needed n = 9.505 x 0.10 x 1.69 x 1.5 / 0.02^2 = about 6,024 pairs, beyond any human-labelled set this quarter.
Consequence: this is a pilot. It is powered only to detect large deficits (gap of 30 points or more) and to estimate discordance, intraclass correlation and prevalence for sizing a confirmatory run of about 720 test pairs for the single-arm margin; the E margin is reported descriptively. Interval rule: each gap gets a pair-level paired bootstrap interval and a cluster bootstrap by repository family (10,000 resamples, seed 20261005); the verdict uses the wider of the two at the selection-aware level (97.5% two-sided, i.e. one-sided 0.0125 per bound). If test families < 8, the cluster interval is flagged as unstable but still used when wider. Two labellers label every pair; disagreements are adjudicated by a third; kappa is reported. Label noise from the source (kappa 0.575 on a 4-class variant) is expected to depress all arms' agreement with gold; it is not a mathematical bound on F1.

kill criterion: System One is killed for the IMPLEMENTS decision this quarter only if the run is valid and every arm in {A, B, C, E} fails: for A, B, C the upper bound of (arm minus D) is below -0.10; for E the upper bound of (E minus D) is below -0.02 or E's cost is >= 50% of D's. Invalid (rerun, not a verdict) if labeller kappa on the 3-way label < 0.4, or D misses its validity floor. C alone is invalid (dropped from the family, not killed) if its class-wise silver audit fails. Anything that is neither a pass nor a kill is inconclusive.

what a pass unlocks: The CTO's priority 3 slice: IMPLEMENTS edges proposed on every pull request by a model we can afford and, for B or C, host ourselves so the text stays in-house (priority 2); an auto-write confidence threshold fit on our data rather than vendor calibration, written only if it meets the absolute precision and coverage targets (B14); up to 500 human-labelled pairs (evaluation, prevalence sample, silver audit) that seed family F3 of the PDLC memory benchmark (PC-SCOPE-20260928-01, deferred) and H7's typed records; measured discordance, intraclass correlation and prevalence that size the confirmatory run.

cost (runs, tokens, people-days): decisions: 400 labelled evaluation pairs (300 split plus 100 prevalence) x 4 model arms (A, B, C, D) = 1,600, plus A and B binary variants on test, 200 x 2 decisions x 2 arms = 800; E reuses A and D outputs; about 2,400 decisions in total, 400 of them D calls. Tokens: pair rendering capped at 4,096 tokens (ModernBERT tokenizer count, fixed at freeze), so D uses about 400 x 4,096 = 1.64M input tokens plus about 400 x 300 = 0.12M output tokens (estimate); A similar in count on 600 calls. USD: not estimated here; PAIChecker's USD 0.08 to 0.23 per link are source averages for a multi-agent pipeline and are neither an upper bound nor a price for a single call (the source reports large patches above USD 1 per instance); D's cost is computed from billed tokens at list price on the run date. Training: ModernBERT-large fine-tune on one GPU, 3 seeds, a few hours. Labelling: 500 pairs (300 split, 100 prevalence, 100 silver audit) x 2 labellers x about 5 minutes = about 83 labeller hours, plus adjudication (third labeller, about 12 hours if about 30% disagree). Engineering: about 7 engineer-days (extraction with revision freezing, family deduplication, stratified weighting, harness, fine-tune). Cost M.

def arm_pass(x):

    if x == "E": ok = ok and cost["E"] < 0.5 * cost["D"]

def arm_fail(x):
    bad = gap_hi[x] < -MARGIN[x]
    if x == "E": bad = bad or cost["E"] >= 0.5 * cost["D"]
    return bad
# precedence: invalid > positive > negative > inconclusive
if not valid: verdict = "invalid"
elif any(arm_pass(x) for x in FAMILY): verdict = "positive"

# t_write[x] fit on calibration only: smallest threshold with weighted precision >= 0.90
