claim: Two separate, scoped claims for PDLC trace links (IMPLEMENTS, REFINES, VERIFIES). (1) Representation, same model: with the same pinned LLM judge, the same criteria and comparable output budget, writing a link when the judge's yes/no probability clears a threshold fitted on our labels leaves at least 10 points fewer gold-linked requirement trails orphaned than writing it from the same judge's verbalised five-band confidence with a refit threshold, at adequate per-type precision. (2) System, end-to-end: a decision model (hosted Jev, or a self-hosted open-weight decision model) with a locally fitted threshold does the same against the band design; this is a comparison of whole systems (model, interface and token cost differ) and is reported with its cost per 1,000 links, not attributed to representation.

Sources: unchanged from E-20261002-01 and still correct (N-SURVEY-20261001-01 Tables VI and VII with the card's Table VI correction; N-SURVEY-20261001-06 on scale compression at the final decision, our inference for links; N-SURVEY-20261001-02 on the cost of missing trails, read from a figure). E-20260928-08-r2 tests which model decides IMPLEMENTS on precision and F1; this spec tests the confidence representation and threshold policy, scored on orphaned trails, across three link types.

arms (same 720 candidate pairs, same retrieval, same artifact text, the paper's four criteria verbatim in every arm):
- A (reported): the pinned judge returns label, five-band confidence and justification; link at confidence at least 0.7.
- B (baseline): A's outputs with the threshold refit per link type on the calibration split.
- B2 (representation control, new): the same pinned judge, same criteria, asked "does <source> <implement | refine | verify> <requirement>? answer yes or no", no justification; P(yes) read from the endpoint's token log-probabilities restricted to the yes and no tokens and renormalised; threshold fitted per type as for C. The judge pin is chosen at stage 0 as a model whose endpoint returns top-k log-probabilities (recorded); A and B2 use that same model. Output budget: A's justification is capped at 150 tokens, and a variant B2j (B2 preceded by the same 150-token justification, then the yes/no token) is run on the calibration split only to show whether the justification itself moves the result; B2j is reported, never decides.
- C (system arm): hosted Jev (pinned), one Noul per pair, same question, threshold fitted per type.
- D (system arm, self-hosted): first of Bongard, decider-2b, KEV-9B whose licence permits self-hosted internal use; P(yes) from native decision output or the restricted next-token distribution; threshold fitted as C. Not run if no licence permits (recorded).
- threshold fitting: per arm and link type, the lowest grid value (0.01 steps) whose calibration-split precision is at least P* = 0.85; ties to the higher threshold. If no threshold reaches P* for a type, that arm is marked `no_threshold` for that type and cannot pass or support equivalence on any rule that involves that type; its fallback threshold (maximum calibration precision) is used for reporting only.

metric: primary, orphan rate on the test split = share of gold-linked (requirement, link type) units with no gold-positive written link, pooled and per type; per-type test precision and link recall; review queue; phantom-trail rate; ECE (10 equal-mass bins) for B2, C, D and A's band midpoints; band utilisation; cost per 1,000 links (USD at the frozen price table, GPU-seconds for D); p50 and p95 latency. Failure and empty-set handling: an output that fails or cannot be parsed is a failed record, never re-asked; the per-arm failure rate must be at most 3% (else invalid); primary analysis uses the common paired set (pairs valid in every arm run), and a sensitivity analysis treats each failed pair as not written; a type for which an arm writes no links on the test split has precision undefined and fails the per-type precision requirement.

predeclared margin: positive for arm X in {B2, C, D} needs (i) orphan(B) minus orphan(X) at least 0.10 pooled, with the 97.5% interval (Bonferroni over the up to three arms compared to B; representation and system claims reported separately) excluding zero; (ii) for every link type, X has a fitted threshold (not `no_threshold`), test precision(X) at least 0.80, and test precision(X) at least test precision(B) minus 0.03. Negative (equivalence) for X needs the 90% two-sided interval of orphan(B) minus orphan(X) entirely inside (minus 0.05, plus 0.05) (two one-sided tests at 5%) and condition (ii). Otherwise inconclusive for X. The question is closed only when every arm run is negative; with this sample, equivalence is unlikely to be shown, and that is stated as the expected outcome rather than read as a negative.

sample size and power note: 60 requirements from 15 repositories (4 per repository, seed 20261102), split by repository into 6 calibration repositories (24 requirements) and 9 test repositories (36 requirements), balanced on requirement count; test units 108, about 80 to 95 gold-linked. Dependence: requirements share repositories, so uncertainty uses a two-stage cluster bootstrap (resample test repositories, then requirements within each), and the design effect is estimated from the calibration split's repository intraclass correlation before any test-split call and recorded in `power.json`. Under an assumed repository ICC of 0.10 and paired discordance 0.25, SE of the pooled orphan difference is about 8 points: a true 20-point reduction passes with probability about 0.7, a true 10-point reduction about 0.2, and equivalence within 5 points is shown with probability under 0.2 even if the arms are identical. This is a pilot that can detect a large effect and sizes a confirmatory run. `tl power` simulates exactly this two-stage design (1,000 draws, seed 20261102) using the calibration-split ICC, before any test-split call; the rule does not change with it.

kill criterion: negative only by the equivalence rule above. Invalid (new spec revision, not a verdict): labeller kappa below 0.6 on any type; candidate lists, artifact text or criteria differing between arms (sha256); a threshold fitted on any test repository; labels edited after any arm ran; any pin differing; any arm's failure rate above 3%; common paired set below 680 pairs; fewer than 60 gold-linked test units; B2's judge endpoint not returning log-probabilities for more than 3% of pairs.

what a pass unlocks: the priority 3 confidence-scored trace-link design (pdlc-memory-layer.md section 2): whether link confidence is a yes/no probability with a local threshold (and, from B2, whether that holds within one model) or an LLM's verbalised band, with the orphan cost and serving cost of each; B14 (working) gains local ECE for a judge's probability, Jev and an open-weight model on link decisions; B8 (working) gains a measured orphan rate that bounds how complete H7's typed edges can be; the frozen three-type pairs as the linking family of the PDLC memory benchmark (priority 4); a corrected citation of arXiv 2606.17203.

cost (runs, tokens, people-days): retrieval and audit 1 engineer-day; labelling 720 pairs by two blind labellers, adjudicated, about 40 labeller-hours (IMPLEMENTS pairs labelled under E-20260928-08-r2 reused only where their repository is among the 15, re-checked, recorded); harness 3 engineer-days.
