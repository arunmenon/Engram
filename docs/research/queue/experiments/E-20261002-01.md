claim: For PDLC trace links (IMPLEMENTS: pull request to requirement; REFINES: design section to requirement; VERIFIES: test to requirement), writing a link when a decision model's yes/no probability clears a threshold fitted on our labels (Jev Noul, or a self-hosted open-weight decision model) leaves at least 10 points fewer gold-linked requirement trails orphaned than writing it from an LLM's verbalised five-band confidence with a refit threshold, at no lower precision. This decides how our linking stage scores confidence and which threshold it ships, given that the threshold's cost is requirements left without a path to code, design or tests.

Sources and what they do and do not show. N-SURVEY-20261001-01 (arXiv 2606.17203, the paper our PDLC design cites for calibrated per-link confidence): confidence is the LLM's own verbalised score in five bands; no ECE or Brier value appears in any table and no recalibration is applied; the threshold sweep (Table VII) gives the best link F1 at 0.7 (P 0.782, R 0.818, review queue 23.0 per subsystem) and P 0.983 at R 0.340 at 0.9, so recall, and with it trail completeness, is very sensitive to where the threshold sits on an uncalibrated scale; 535 artifacts, one automotive domain, LLM unnamed, thresholds tuned on the evaluation data. Correction to the card: the card says confidence filtering cut conflict-aware path completeness from 100.00% to 33.64% and gives 36.12% "without the conflict detector". In Table VI, 36.12% is the row without confidence filtering and the row without conflict detection is 100.00%, so the completeness drop is driven by the conflict detector; removing confidence filtering moved completeness by only about 2.5 points. This spec therefore does not rest on Table VI; it measures orphan rate directly as a function of the threshold policy. N-SURVEY-20261001-06 (arXiv 2609.38827): decision models compress graded scales at the final decision (Jev 1.13 used 95.9% of the gold level spread at 2 levels and 54.5% at 14; 72.97% over 36 ordinal datasets), which is the design reason to ask a yes/no question and threshold its probability rather than ask for one of five bands; not a memory task, so the transfer to link confidence is our inference. N-SURVEY-20261001-02 (arXiv 2607.18886, TraceDev): a completeness walk over trace links raised end-task success from 28.37% to 47.19% on one dataset and model (read from a figure), so missing trails cost real work; link accuracy itself was not measured there and tests were not modelled. E-20260928-08-r2 already tests which model decides IMPLEMENTS on precision and F1; this spec asks a different question (the confidence representation and threshold policy, scored on orphaned trails, across three link types), so the arms that answer it differ.

arms (same 720 candidate pairs, same top-4 retrieval per requirement and link type with the pinned embedding model, same artifact text; the four judging criteria of the paper (coverage, specificity, terminology alignment, absence of contradiction) appear verbatim in every arm's instructions):
- A (reported, paper's design): the pinned LLM judge returns a label, a confidence on the paper's five bands ("0.90 to 1.00 clear/direct, 0.70 to 0.89 strong, 0.50 to 0.69 partial, 0.30 to 0.49 indirect, 0.00 to 0.29 no relationship") and a justification; link written at confidence at least 0.7, the paper's threshold.
- B (baseline): A's outputs, with the threshold refit per link type on the calibration split to the target precision below. No new calls.
- C (decision arm): hosted Jev (pinned version), one Noul per pair, "does <source> <implement | refine | verify> <requirement>?", neutral option names; link written at P(yes) at least t_C, fitted per link type on the calibration split to the target precision.
- D (decision arm, self-hosted): an open-weight decision model, chosen at stage 0 as the first of Bongard, decider-2b, KEV-9B whose model card licence permits self-hosted internal use (the licence text and model hash recorded), same question, P(yes) read from the model's native decision output or, if it has none, from the next-token distribution restricted to the option codes and renormalised (N-SURVEY-20261001-04's method); threshold fitted as in C. If no candidate's licence permits it, D is not run and this is recorded; the rule then uses C alone.
- target precision: P* = 0.85 per link type; each arm's threshold is the lowest grid value (0.01 steps; A's continuous confidence for B) whose calibration-split precision is at least P*, ties to the higher threshold; if no threshold reaches P* on the calibration split, the threshold maximising calibration precision is used and the shortfall is reported.
- override: the card asks for at least 150 labelled pairs per link type with top-10 retrieval. This spec uses 240 pairs per link type from top-4 retrieval over 60 requirements, because orphan rate is a per-requirement measure and 150 pairs at top-10 would cover only 15 requirements per type; retrieval recall at 4 against a 10-candidate audit on 12 requirements is reported, and candidates retrieval missed are equally missing in every arm.

metric: primary, orphan rate on the test split = share of gold-linked (requirement, link type) units (at least one gold-positive candidate among the four) for which the arm wrote no gold-positive link, pooled over the three link types and reported per type; precision and link recall at the fitted threshold per arm and type; review-queue size per requirement (pairs not written whose score is at or above the arm's threshold fitted for precision 0.5); phantom-trail rate (units where the arm wrote links but none is gold-positive); ECE (10 equal-mass bins) for C and D probabilities and for A's band midpoints; level utilisation of A's five bands (predicted against labelled strength levels, per N-SURVEY-20261001-06); serving cost per 1,000 links (USD at the frozen price table, plus GPU-seconds for D); p50 and p95 latency per pair.

predeclared margin: positive for arm X in {C, D} needs orphan(B) minus orphan(X) at least 0.10 pooled over link types, with the 97.5% interval (Bonferroni over the two decision arms) excluding zero, and test precision(X) at least test precision(B) minus 0.02 (point estimate) pooled over types. If both C and D pass, the cheaper per 1,000 links is preferred unless the other's orphan rate is at least 0.05 lower. Negative needs |orphan(B) minus orphan(X)| below 0.05 for every decision arm that ran. A against B is reported and never decides.

sample size and power note: 60 requirements from 10 repositories (clustering unit: the requirement, whose three link types are correlated; repositories split 4 calibration (24 requirements, 40%) and 6 test (36 requirements, 60%), assignment frozen with seed 20261102 and balanced on requirement count). Test units: 36 x 3 = 108, of which about 80 to 95 are expected to be gold-linked. At a paired discordance of about 0.25 and a design effect of about 1.2, the SE of the pooled orphan difference is about 6 to 7 points, so a true 10-point reduction passes with probability about 0.3 and a true 20-point reduction about 0.85. This is a pilot that can detect a large effect and return a clear negative, and it sizes a confirmatory run; `tl power` (requirement-cluster resampling simulation under these assumptions, 1,000 draws, seed 20261102) runs before any model call and is recorded in `power.json`; the rule does not change with it.

kill criterion: negative (band-versus-probability question closed) if |orphan(B) minus orphan(X)| is below 0.05 for every decision arm that ran. Invalid (rerun under a new spec revision, not a verdict): labeller kappa below 0.6 on any link type; candidate lists or artifact text differing between arms; criteria text differing between arms (sha256); a threshold fitted on any test-split repository; labels edited after any arm ran; Jev version, judge model or D's model hash differing from the pin; any pair missing from A or C (or D if run) without an explicit failed record; fewer than 60 gold-linked test units.

what a pass unlocks: the priority 3 confidence-scored trace-link design (pdlc-memory-layer.md section 2) on our data: whether link confidence is a yes/no decision-model probability with a local threshold or an LLM's verbalised band, and the orphan cost of the threshold we ship; for B14 (working: calibration claimed, not shown) a local ECE for Jev and an open-weight model on link decisions; for B8 (working: typed questions such as completeness favour typed structure) a measured orphan rate that bounds how complete the typed edges H7's traversal assumes can be; the frozen three-type labelled pairs as the linking family of the PDLC memory benchmark (priority 4); a corrected citation of arXiv 2606.17203 in the design document.

cost (runs, tokens, people-days): candidate retrieval and 10-candidate audit, 1 engineer-day; labelling 720 pairs by two labellers blind to arm outputs, adjudicated, about 40 labeller-hours (IMPLEMENTS pairs already labelled under E-20260928-08-r2 for the same requirements are reused and only re-checked, recorded); harness 3 engineer-days. Model tokens: A, 720 x about 1.9k = 1.37M; C, 720 x about 0.75k = 0.54M; D, 720 x about 0.75k = 0.54M (self-hosted, counted against the token cap); total about 2.45M in 2 shards, aggregate hard cap 3M. USD: judge about 5 USD at the frozen price table, Jev under 0.1 USD, D GPU time on the harness host; aggregate cap 12 USD. Cost M.
