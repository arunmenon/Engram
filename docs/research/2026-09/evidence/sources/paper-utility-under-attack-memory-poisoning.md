# Utility Under Attack: Agent Memory Poisoning and the Limits of Content Screening and Provenance Ranking

- **URL:** https://arxiv.org/abs/2608.21230 (HTML: https://arxiv.org/html/2608.21230)
- **Type:** paper
- **Author / org:** Arulnidhi Karunanidhi, Quantify Labs Ltd
- **Date:** August 24, 2026
- **Retrieved:** 2026-10-02 (local copy: /Users/arunmenon/MemoryRSI-Signals/work/survey/survey-20261002T054505Z-3d1e/out/log/src/arxiv-2608.21230.html)
- **Cited by evidence:** survey R8
- **Relevance to a memory stack:** high, it directly tests a write-time injection screen plus a provenance-weighted read ranker against poisoned memory and reports benign false-positive cost alongside recall.

## TL;DR
- Plain false-fact poison (no instruction, no trigger, not optimized), 360 memories at about 1.2% of corpus, drops LongMemEval accuracy "0.850 to 0.300" on n=120.
- The four-stage write-time content screen, which reaches "0.832 recall on indirect prompt injection", "refuses 0 of 360 poisoned memories". Authors argue content-only screening cannot detect falsity without external grounding.
- Additive provenance weight at the shipped value (w_t=0.15) was "statistically indistinguishable from no defense (p=0.80)"; corrected w_t=0.35 recovers accuracy to 0.475 but works by categorical exclusion of untrusted content.
- When answer-bearing evidence itself arrives untrusted (Corpus N), w_t=0.35 drops accuracy from 0.8583 to 0.0417 with 0.00% evidence recall: provenance weighting becomes a denial-of-service primitive.
- No adaptive attack was run ("we make no robustness claim about screening beyond the non-adaptive setting"); proposed remedy (provenance as bounded occupancy quota plus write-time origin binding) is unbuilt and unevaluated.

## What it claims / describes
- System ("Aegis", the author's released memory system): write path runs Stage 1 structural validation, Stage 2 PII/secrets detection, Stage 3 rule-based injection detection, Stage 4 optional LLM classifier invoked conditionally (untrusted/unknown trust, shared/global scope, or Stage 3 flagged-but-allowed); confidence >= 0.8 rejects.
- Read path: score(m) = w_s*sim + w_t*tau + w_e*e + w_d*d + w_p*p, with tau map untrusted 0.0, unknown 0.5, internal 0.7, privileged 0.85, system 1.0. Trust "can only outbid" similarity, never veto.
- Margin argument: at shipped weights provenance can outbid similarity "only within a margin of 0.175", while poison "gained 0.32 in similarity by being phrased like the query". At corrected weights the untrusted penalty is 0.245 against max semantic contribution 0.45, "more than half the available range".
- Claim: "Any weight large enough to resist an attacker who can shape content is large enough to exclude untrusted content categorically." Scoped by the authors to additive scoring "under the measured similarity regime".
- Methodological claim: attack success rate is the wrong metric; report utility retained and FPR beside recall.

Other:
- Ablation (Table 5): all 155 InjecAgent detections before Stage 4 come from Stage 2 (secrets detector); Stage 3 injection rules contribute 0 on indirect injection and take direct recall from 0 to 0.144. Adding Stage 4 "doubling the NotInject false positive rate".
- Latency: deterministic core "tens of microseconds against roughly 200 ms for the transformer-based detectors". API-backed latency not reported (cached, rate-limit backoff).
- Benign over-defense on ingest: "refused 109 of 124,462 ingested rounds as suspected credential leaks"; none answer-bearing.
- Cost: "The mixed-provenance arms cost $11.22". Other costs not stated.

Text/table disagreement flag: the abstract and conclusion pair "0.832 recall on indirect prompt injection" with "flagging only 1.5% of trigger-word-laden benign text". In Table 4 these belong to different configurations: 0.832 is stages 1-4 (Haiku 4.5) whose NotInject FPR is 0.035; 1.5% is the deterministic stages 1-3 whose InjecAgent recall is 0.620. Also, the deterministic core's 0.620 InjecAgent recall is entirely the secrets detector (Table 5), not injection detection, which the authors acknowledge in section 6.4.

Shared-model flag: claude-haiku-4-5-20251001 is both the poison generator and one Stage-4 classifier / LLM-judge backend. The memory QA judge (gpt-4o) differs from the reader (claude-sonnet-5).

## Mechanism details you could implement
- Report FPR on a trigger-word benign set (NotInject style) next to recall for any memory gate; DeBERTa-class detectors flagged 42.8% there.
- Stage a cheap deterministic core on every write, reserve an LLM classifier for untrusted/unknown or shared-scope writes; keep a secrets detector as a distinct stage and do not count it as injection detection.
- Compute the provenance margin before choosing weights: the maximum score a trust tier can buy (w_t times tier gap) versus the similarity advantage an attacker can obtain by echoing query wording (0.32 observed here).
- Evaluate any provenance defense on a mixed corpus where benign and answer-bearing content also arrives untrusted, not only where untrusted equals malicious.
- Proposed (unbuilt): provenance as a bounded occupancy constraint (floor and ceiling on untrusted share of retrieved context) plus write-time origin binding so labels cannot be laundered through summarization or tool echo.
- Snapshot/restore of the memory store between arms so each arm starts from the exact clean state.

## Limitations, caveats, counter-evidence
- Non-adaptive attacker only; adaptive screening sweep was pre-registered but not completed. Attack results are lower bounds, defense results upper bounds (authors' framing).
- One memory system, one embedder, one reader; the 35% surviving utility partly reflects the reader's abstention behaviour.
- Trust labels assumed correct and unforgeable; label laundering not studied.
- Corpus M overstates benefit, Corpus N overstates cost; no real deployment operating point located.
- Domain is conversational personal memory; authors explicitly do not know transfer to code memory.
- Self-evaluation by the system's author; no independent replication.
- Compared with the already-known Price of Safety (2609.22818) and hermes-firewall notes: this paper adds the payload-free false-fact class, which an injection gate cannot see by construction (inference: an orthogonal failure mode to the paraphrase/adaptive question rather than a measurement of it).

## Takeaways for tuning a memory stack
- An injection gate on served memory (B24 design) addresses only payload-bearing poison. For false-fact poison it should be expected to block roughly nothing; 20/22 on author-written injection lines says nothing about this class (inference from 0/360).
- Benign false-block rate of a well-built deterministic gate can be low (0.0 to 0.1% on ordinary benign text, 1.5% on trigger-word text), so the gate is cheap to keep; adding an LLM stage roughly doubles trigger-word FPR.
- Do not ship an additive trust weight without computing its margin; small weights do nothing, large weights silently become hard exclusion and can zero out legitimate untrusted evidence (for build agents, e.g. vendor docs or issue text) (inference for coding domain).
- Provenance must be fixed at write time and must not be raisable by the content itself, consistent with B25.
