## TL;DR
- **Magneto.** An MPNet (about 110M) retriever proposes candidate matches and GPT-4o-mini reranks them.
  - On the GDC benchmark (Table 6), MPNet zero-shot reaches "0.731±0.086" MRR, and "0.860±0.088" when fine-tuned on LLaMA-3.3-70B-generated data.
  - Figure 6 (not a table): COMA++ about 0.35 against Magneto-ft-llm above 0.80.
  - Runtime (Figure 8, 153 columns): 11 to 33 s for the small model with bipartite matching, 545 to 589 s with LLM reranking.
- **Schema to ontology with LLMs only** (RODI, Table 2). Self-demonstrations score "0.79 / 0.79 / 0.51" on Conference (23 classes), Mondial (49) and NPD (300 classes, 1000 columns), against curated few-shot "0.72 / 0.82 / 0.48". Accuracy drops sharply as the ontology grows.
- **Column type annotation** with FLAN-T5 XXL LoRA on SOTAB (91 types, Table 2): 0.730 weighted F1 on its own template but 0.676 on an unseen one. Augmented training brings the spread across templates under 3.3 points.

## Mechanism details you could implement
- For G7 and the binding registry: embed the source field (name, description, sample values) and retrieve the top-k shared properties with a small encoder. A decision model or LLM then picks one from that closed menu of k, which suits a typed Choice.
- Train the small retriever on matches generated by a large model and confirmed by a person. Magneto's gain came from LLM-generated training data.
- Test against unseen serialisations. A Jira export and a Jira API record differ.

## Limitations, caveats, counter-evidence
- None of this is on engineering tools.
- No typed decision model is in any comparison.

## Takeaways for tuning a memory stack
- G7 as written ("Choice per dimension over fixed tag sets") matches the rerank stage of Magneto. The evidence says to put a small retriever in front of it once the type set passes a few dozen types.

## Open questions
- At what ontology size does a single Choice over all types fail? RODI suggests somewhere between 49 and 300 classes for an LLM.
